## What v0.1 confirmed

All five daemons fire cleanly under round-robin rotation. Single-instance lock works (mirrored from `harmonia_loop.py` `ba0893ec`). Graceful degradation on DeepSeek 402 works at the tick level — no daemon crashes; every tick emits ≥1 artifact; rotation index advances on schedule.

The substrate signal Hecate measures is real: post-v0.2 sampling fix, `MI(kill_pattern, generator_id) = 2.50 bits` on Theseus's local corpus, `mi_z = 952` against permutation null. First Hecate-measured confirmation that the kill-geometry thesis transfers to Theseus-emitted records (separate from the historical 314K-kill ledger).

## What dried up or needs work

Five distinct issues surfaced during observation, ranked by impact.

### P1 — Moros corpus-goes-quiet handling (downgraded from P0 on cycle 2 data)

**Initial (wrong) diagnosis:** "Moros stuck on the same artifact" — observed after cycle 1 where Moros picked `pivot/model_sweep_results_2026-05-19.md`.

**Empirical correction (cycle 2):** Moros picked a **different** artifact (`aporia/doctrine/dr_prompt_discipline.md`). Backlog jumped 103 → 104. Cause: Moros sorts by `(recency_bucket, -mtime)`, so whenever any load-bearing file's mtime advances (parallel agent activity, substrate-tester refresh, git pull), the newest floats to the top and Moros picks it. With other agents continually modifying load-bearing files, Moros has a stream of fresh work even with DeepSeek 402.

**Real bug, downgraded:** The corpus-goes-quiet edge case. If no load-bearing artifacts get modified for an extended period AND DeepSeek stays down, Moros will rotate through the same N artifacts repeatedly emitting SELF_AUDIT_NULL each time. Not high-impact (the substrate isn't going quiet anytime soon — too much agent churn), but worth fixing for resilience.

**Fix:** Track `failed_attempts[artifact_path] = [{at, reason}]` in state. When `failed_attempts >= 3` within a 24h window for an artifact AND the artifact's mtime hasn't advanced, skip it and try the next one in the backlog. Reset on success. ~40 LOC.

**Discipline lesson noted inline:** Don't promote a swarm bug to P0 based on a single observation. Same sampling-window failure mode that caught Hecate v0.1 just caught me one floor up, on a single-cycle sample of Moros behavior. Memory updated.

**Update 2026-05-19T11:20 — second cycle data after recent-coverage fix:** Under stable load-bearing-artifact mtime, Moros now correctly skips duplicate enqueues (`dr_skipped_reason='recent_coverage'`) but also doesn't advance past the same artifact. Two natural unblocks: (a) any new commit modifies a load-bearing file → mtime advances → Moros picks the newer one; (b) Pythia completes an in-flight row → Moros's `_process_dr_inbox` writes a feedback artifact → `_has_feedback` returns True → next-by-mtime is picked. Both happen frequently in the active mesh. The remaining corpus-goes-quiet edge case (no commits AND Pythia stalled) is bounded by Pythia's worst-case turnaround. **Patch (4) — tried-but-failed tracking — would still harden the edge case** by advancing after N consecutive recent-coverage skips on the same artifact, but P1 is the right priority, not P0.

### P0 — DeepSeek 402-cooldown (covers Lethe + Moros)

Both LLM-dependent agents currently burn API calls every tick when balance is exhausted. Lethe fires 4 calls × 4-min cadence = 1 wasted call/min. Moros fires 1 call × 4-min = 0.25 wasted/min. Log noise is high (the warning lines flood the output).

**Fix:** Shared cooldown helper on the `CharonAgent` base class. On any DeepSeek `402 Insufficient Balance` response, write `_deepseek_cooldown_until: <ts+3600>` to state. Subsequent `deepseek_complete()` calls short-circuit during the cooldown window and return None immediately (no API call). When the cooldown expires, the next call attempts the API; if it succeeds, cooldown clears; if it 402s again, cooldown re-extends.

Lower bound on cooldown: 60 minutes. Upper bound: 4 hours. Configurable per-agent.

This is the single highest-leverage v0.2 patch — fixes Lethe noise AND lets Moros's tried-but-failed tracking work properly (no more spurious "tried" entries from rate-limited calls).

### P2 — Hecate runner-up pattern DR fallback (post-DR-wire observation)

Observed 2026-05-19T11:43: Hecate's MI shifted from 2.4996 → 2.2678 bits
(real corpus motion as Theseus produced new batches), but `top_pattern`
remained `a2_detrended_correlation_below_threshold`. Recent-coverage
correctly skipped a duplicate DR enqueue, but Hecate has 2/3 daily
budget remaining and a wealth of runner-up patterns that haven't been
surveyed yet (`a2_detrended_correlation_not_significant`,
`a1_relation_equal_violated`, `c1_mut_*`, etc.).

**Fix:** when the top kill_pattern is recent-coverage-blocked AND quota
remains, walk the top-N list to the first unblocked pattern. Captures
the gradient-shift signal across multiple patterns per day instead of
locking onto whichever happens to be #1.

~10 LOC. Captures real substrate value at zero new cost.

### P1 — Hecate idempotency (efficiency)

When `theseus/corpus/` doesn't grow between ticks, Hecate recomputes the same 2.5-bit MI analysis using the same 50K sampled records and emits an identical artifact. The MI estimation takes ~10s/tick. At 4-min cadence, that's 10s wasted every 4 min when the underlying data hasn't changed.

**Fix:** Cache a tick fingerprint = `sha256(sorted([(f.name, f.mtime, f.size) for f in corpus_files]))`. If fingerprint matches last tick's, emit a lightweight `gradient_archaeology_unchanged_<utc>.md` artifact (just the fingerprint + "no change since last analysis" + pointer to prior artifact). Re-run the full MI computation only when fingerprint differs.

Side benefit: makes the artifact stream meaningful again. A reader scrolling through `hecate/artifacts/` will see a clear timeline of substrate state changes rather than a wall of identical analyses.

### P1 — Acheron backlog-enumeration cost growth

Acheron's `_enumerate_candidate_files` re-globs all `*.md` files under SCAN_ROOTS each tick. Observed elapsed_sec across three ticks: 1.5s → 7.3s → 12.6s. The corpus is growing (daemons keep writing artifacts that get scanned), so the trend continues. Linear in corpus size; not fatal, but compounds.

**Fix:** Cache `scanned_files` keyed by directory + mtime threshold. Maintain a "files-seen-since" timestamp per SCAN_ROOT; only enumerate files modified since that timestamp. On Windows + WSL filesystem this should drop the enumeration from O(N) to O(changed-since-last-tick), typically 0-10 files instead of hundreds.

### P2 — Stygian execution gap (deferred to v0.3+)

Stygian writes attack_plan artifacts cleanly and round-robins through BL-C-001..010 as designed, but the v10 battery has **never actually executed** during observation. The plan-vs-execute split was deliberate per CHARTER ("propose-only; v10 battery execution downstream"), so this isn't a v0.1 bug. But the substrate-block emission pipeline (`agora.kill_ledger_entries` Postgres table from the DESIGN doc, KillVector population, attack_plan → executor handoff) is the next-but-one big piece.

**v0.2 scope:** keep plan-only. Document the executor-handoff requirement explicitly. File a v0.3 roadmap item: build the Postgres queue and a battery-runner subprocess that consumes attack_plan artifacts and emits kill_ledger entries.

### P2 — Lethe always-zero-emit deterministic signal

Even when DeepSeek works, Lethe's emit_rate has not crossed the 0.30 threshold in any observation tick. Sample evidence:
- `schinzel_zassenhaus` — DeepSeek correctly says "settled by Dimitrov 2019" (catalog v0 hit; emit_rate=0.0)
- `catalan_mihailescu`, `vinogradov_mean_value`, `mertens_conjecture` — all 402'd (can't tell yet)
- `fermat_last_theorem_calibration` — calibration probe; should be 0.0; haven't reached it yet in rotation

The catalog v0 may be too conservative — Lethe's anti-anchor candidates won't fire until either the catalog grows (post-2024 conjectures less well-trained) OR the false-form-patterns regex relax. Worth investigating empirically once 402 clears.

**v0.2 scope:** add 5-10 catalog entries from harder territory (post-2024 conjectures, niche subjects where LLMs are more likely to hallucinate). Candidates from Pythia's `AA-VERIFY-*` DR reports already in flight.

### P3 — Telemetry gap

No per-agent lifetime_stats.json being written despite the base class having `heartbeat()`. Penelope and Theseus both write `lifetime_stats.json` to track cumulative production. Useful for "Lethe has fired N times; M produced candidates; X false-form-rate over rolling 90 days." Not on the v0.2 critical path but cheap to add.

## v0.2 patch list (in build order, updated post-cycle-2)

P0 (real bugs that affect production):

1. **DeepSeek-cooldown helper** on `CharonAgent` base class. Wraps `deepseek_complete()` to short-circuit during cooldown. ~30 LOC. Drop-in. Fixes Lethe's 4-calls-per-tick wasted-call problem + log noise; sets up (2).

P1 (efficiency / resilience):

2. **Hecate idempotency check** — skip recompute when corpus fingerprint hasn't changed. ~30 LOC. Standalone.
3. **Acheron cached-enumeration** — replace per-tick O(N) glob with incremental mtime-since-last-tick. ~40 LOC. Standalone.
4. **Moros tried-but-failed tracking** — corpus-goes-quiet resilience. Builds on (1). ~40 LOC. Downgraded from P0 after cycle-2 data showed Moros DOES advance through fresh artifacts as the corpus churns.

P2 (catalog / signal):

5. **Lethe catalog growth** (5-10 new entries, harder territory). Inline data only. ~120 LOC.

P3 (polish):

6. **Per-agent lifetime_stats**. ~30 LOC. Defer to v0.3 if time-boxed.

Total: ~270 LOC across 5 daemons + base class. Single-day build. P0+P1+P2 cover the empirically-observed dry-up modes; P3 is optional.

## What v0.2 will NOT do

- Stygian battery execution (deferred to v0.3).
- Postgres queue tables (the design doc sketches them; build deferred until at least 3 agents need them concurrently).
- Multi-model cross-pollination cascade in Moros (gated on DeepSeek budget greenlight + multi-key plumbing).
- Acheron multi-paragraph context isolation (current per-file check is good enough; multi-paragraph is a refinement).
- Hecate HDBSCAN clustering on KillVector embedding (current top-N kill_pattern listing covers the same use case for now).

## Smoke pattern for v0.2 verification

Mirror the v0.1 smoke: `python scripts/charon_loop.py` 5 times in sequence with all five agents firing cleanly. Add a 6th verification step: `python scripts/charon_loop.py --agent moros` twice in a row after a fake 402 condition (env var or local stub) — confirm the second tick picks a DIFFERENT artifact (proving tried-but-failed tracking works).

For Hecate's idempotency: `python scripts/charon_loop.py --agent hecate` twice — confirm the second tick emits the lightweight unchanged artifact and runs in <1s.

## Open questions for James

1. **Cooldown window default.** 60min, 2hr, or 4hr? Conservative argument: 60min (resume promptly when balance returns). Aggressive: 4hr (don't burn calls on chronic-empty-balance state).

2. **Moros multi-model upgrade timing.** Even with cooldown, single-model cross-pollination is limited. When is the budget greenlight likely? Doesn't block v0.2 but informs whether to plumb the multi-key abstraction now or later.

3. **Lethe catalog growth source.** Pull from Pythia DR reports tagged `AA-VERIFY-*`, manually curate from arXiv recent-resolutions, or both? Both is more robust; manually-curated catalog v0 seeded the existing 10 entries.

4. **Telemetry priority.** Add per-agent lifetime_stats now (v0.2) or defer to v0.3? Costs ~30 LOC; benefit is visibility into long-running rates.

5. **Postgres queue tables.** Hold off until v0.3, or fold into v0.2 to harden the pub/sub pattern early? My recommendation: hold off — the file-based artifacts work fine for MVP, and Postgres adds operational surface area that's only worth it once consumption patterns are clearer.
