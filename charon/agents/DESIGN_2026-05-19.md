**Date:** 2026-05-19
**Author:** Charon
**Status:** Design draft. Build gated on (a) Harmonia's reusable-components push to `origin/main`, (b) James greenlight on the table-schema sketch below, (c) confirmation that Postgres `prometheus_fire` is reachable for new schema additions.

## Context

James named me the bottleneck for recurring asks. The remediation is to spin five looping agents that automate Charon's standing mandate (attack execution, anti-anchor mining, coordinate-collapse detection, cross-pollination, kill-geometry analysis) so the asks become "is the loop healthy" rather than "run today's attack."

The orchestration model follows the existing exemplars: Theseus (parallel-generator + bandit + lifetime stats), Penelope (daemon with --once / --batches / --forever + processed-files ledger + agora telemetry), Pythia (Postgres-backed queue with parallel in-flight slots + status state machine), Calliope (nightly synthesis from commit deltas). Each Charon sub-agent gets its own directory under `charon/<name>/` with the Penelope-shaped layout (`daemon.py`, `config.py`, `state/`, `journals/`, `orchestration/`, `tests/`).

Pub/sub runs through Postgres tables in the `agora.*` schema on `prometheus_fire` (M1's local Postgres at 192.168.1.176:5432, the same DB Pythia's `agora.research_queue` lives in). Producers `INSERT`; consumers `SELECT ... WHERE status='pending'` with row-level locking via `SELECT ... FOR UPDATE SKIP LOCKED`. Optional NOTIFY/LISTEN for near-real-time wakeups; default is poll-every-N-minutes.

## Postgres pub/sub schema (proposed)

All tables live in `agora.*` and follow Pythia's `research_queue` convention: composite priority + status state machine + indexes for pending/in-flight/recently-completed queries.

**`agora.attack_queue`** — Stygian's input queue.
- Columns: `id` (BIGSERIAL PK), `priority` (INT), `tier` (TEXT), `problem_id` (TEXT), `problem_name` (TEXT), `hardness_signature` (TEXT), `seed_attack_vector` (JSONB), `target_substrate_block_shape` (TEXT), `source` (TEXT — `aporia` / `self_plumb` / `james`), `status` (TEXT — `pending` / `claimed` / `running` / `complete` / `failed` / `deferred`), `claimed_by` (TEXT), `claimed_at` (TIMESTAMPTZ), `result_summary` (JSONB), `created_at`, `completed_at`.
- Indexes: `(status, priority DESC, created_at)`, `(problem_id)`.
- Producers: Aporia (canonical), Stygian's self-plumb submodule (fallback).
- Consumers: Stygian.

**`agora.kill_ledger_entries`** — Stygian (and others) emit KillVectors here.
- Columns: `id` (BIGSERIAL PK), `kill_id` (TEXT UNIQUE — content-addressed), `claim_id` (TEXT), `falsifier_id` (TEXT), `kill_pattern` (TEXT), `competing_hypothesis_id` (TEXT), `calibration_tier` (TEXT), `precision_floor` (NUMERIC), `repair_attempt_id` (TEXT), `kill_vector` (JSONB — full v2 12-or-20-component record), `emitted_by` (TEXT), `emitted_at` (TIMESTAMPTZ).
- Indexes: `(kill_pattern)`, `(emitted_at DESC)`, `(falsifier_id)`.
- Producers: Stygian (primary), any agent running the battery.
- Consumers: Hecate (nightly gradient archaeology), Aporia (audit), Ergon (eventual training corpus).

**`agora.anti_anchor_candidates`** — Lethe and Stygian emit; Aporia/Techne adjudicate.
- Columns: `id` (BIGSERIAL PK), `candidate_id` (TEXT UNIQUE — `AA-CAND-NNN`), `false_form` (TEXT), `true_form` (TEXT), `citation` (TEXT — arXiv/DOI), `verification_source` (TEXT — which DR prompt or LLM-probe pass surfaced it), `sample_emissions` (JSONB — the cold LLM completions that flagged it), `emit_frequency` (NUMERIC — fraction of samples that produced false-form), `emitted_by` (TEXT), `status` (TEXT — `candidate` / `staged` / `promoted` / `rejected`), `adjudication_notes` (TEXT), `emitted_at`, `adjudicated_at`.
- Producers: Lethe (primary), Stygian (per attack).
- Consumers: Phylax (gates promotion), Aporia (adjudicates), Ergon (eventual training).

**`agora.collision_candidates`** — Acheron emits HARD-5 violations.
- Columns: `id` (BIGSERIAL PK), `term` (TEXT), `context_a` (JSONB — file path + line range + claimed-coordinate), `context_b` (JSONB — same shape), `coordinate_distance` (TEXT — which two primitives are being collapsed), `severity` (TEXT), `proposed_edit` (TEXT), `status`, `emitted_at`.
- Producers: Acheron.
- Consumers: Iris (sister daemon), Techne (catalog edit), Aporia.

**`agora.cross_pollination_jobs`** — Moros's input + output.
- Columns: `id` (BIGSERIAL PK), `artifact_path` (TEXT), `artifact_sha` (TEXT — commit or content hash), `trigger_source` (TEXT — `git_watch` / `phylax_promotion_pending` / `manual`), `status` (TEXT — `pending` / `dispatched` / `responses_collected` / `meta_analyzed` / `failed`), `models_targeted` (TEXT[]), `feedback_doc_path` (TEXT), `meta_analysis_doc_path` (TEXT), `convergence_score` (NUMERIC), `pattern_candidates_filed` (TEXT[]), `created_at`, `completed_at`.
- Producers: Moros's git-watch (primary), Phylax's pre-gate trigger (downstream), James (manual).
- Consumers: Moros executes; Phylax reads `meta_analyzed` rows for the gate-feed.

**`agora.gradient_archaeology_runs`** — Hecate's nightly snapshots.
- Columns: `id` (BIGSERIAL PK), `run_date` (DATE), `ledger_size` (INT), `mi_observed` (NUMERIC), `mi_null` (NUMERIC), `mi_z` (NUMERIC), `top_kill_patterns` (JSONB), `cluster_separations` (JSONB), `emerging_operator_classes` (JSONB), `primitive_proposals_filed` (TEXT[]), `alarm_flags` (TEXT[]), `created_at`.
- Indexes: `(run_date)`, `(mi_z)`.
- Producers: Hecate.
- Consumers: Aporia (substrate health monitoring), James (dashboard).

**`agora.primitive_proposals`** — emitted by Hecate / Stygian / Lethe when novel attack vectors survive ablation.
- Columns: `id`, `proposal_id` (TEXT UNIQUE), `proposed_by` (TEXT), `primitive_spec` (JSONB — schema-conforming to SUBSTRATE_SHAPED_PROMPTS §2.6), `evidence_kills` (BIGINT[] — kill_ledger_entries.id refs), `status`, `adjudicated_by`, `emitted_at`.
- Consumers: Techne (registers in `techne/registry/`), Aporia (adjudicates).

NOTIFY channels per table (for daemons that want push instead of poll): `attack_queue_new`, `kill_ledger_new`, `anti_anchor_candidate_new`, etc.

## The five agents

### 1. Stygian — daily v10-battery attack worker

**Purpose.** Automate BL-C-001 through BL-C-010 (and Phase 1+ continuation): pull the top-priority unattempted Atlas problem from `agora.attack_queue`, run the frozen v10 battery (25 tests × 4 tiers), emit a `kill_ledger_entries` row with full KillVector provenance, emit zero-or-more `anti_anchor_candidates` if the attack reveals a clipped-qualifier or boundary-condition failure, emit zero-or-more `primitive_proposals` if a novel attack vector survives ablation. File a daily attack-summary ticket to `aporia/meta/queue/aporia_inbox.jsonl`.

**Orchestration.**
- Layout: `charon/stygian/{daemon.py, config.py, battery_runner.py, kill_emit.py, journals/, state/, tests/}`.
- Cron slot: :07 (the reserved Charon slot from the roadmap).
- CLI: `python -m charon.stygian.daemon --once` (fire one attack); `--batches N` (fire N attacks then stop); `--forever --interval 3600` (daemon mode, default hourly).
- Tick loop: claim next pending row from `agora.attack_queue` via `SELECT ... FOR UPDATE SKIP LOCKED`; mark `claimed`; run battery (Tier A → D); accumulate KillVector components; on completion, write `kill_ledger_entries` row + conditional `anti_anchor_candidates` rows + conditional `primitive_proposals` rows; mark queue row `complete`; emit heartbeat; release lock.
- Hard stops preserved from RESPONSIBILITIES.md: battery FROZEN at v10; no `--writeable` upgrade; no multiprocessing scaling; no LoRA. Tickets file out if the daemon hits any hard-stop need.

**Self-plumbing submodule.** Yes — `charon/stygian/self_plumb.py`. When `agora.attack_queue` has zero `pending` rows for Charon-tier problems for ≥6 hours, the self-plumb pass: (a) reads `aporia/mathematics/tensor_open_problems_v1.md` + `charon/BACKLOG.md` (BL-C-001..010); (b) computes `attempted_recently` from `kill_ledger_entries` last 30 days; (c) inserts the highest-priority unattempted-recently entry with `source='self_plumb'` and `priority=99` (lower than any Aporia-curated row). Closed loop achieved; Aporia's curation overrides self-plumb whenever she's active.

**Anti-capture safeguard.** Every Stygian tick MUST emit ≥1 substrate block (kill_ledger entry minimum), even on "nothing to kill" outcomes — the null-result is itself a kill_ledger row with `kill_pattern='NULL_ATTEMPT'` and full provenance. Silent ticks are forbidden (the HARD-2 gravitational-well failure mode the BACKLOG flags). Lifetime stats track `attempts_with_zero_emission`; if it climbs above 5%, daemon raises a SELF_AUDIT_NULL alarm.

**Harmonia dependency.** Heartbeat helper, Postgres queue helper, processed-files ledger primitive. If she ships these, Stygian is ~400 LOC. If not, ~700 LOC.

### 2. Lethe — anti-anchor miner

**Purpose.** Mine the inexhaustible "recently-settled-but-LLMs-still-think-open" pattern. The Saxl capture (README §6) was one anti-anchor that reverted four documents; Lethe industrializes that pattern at $0.01/sample.

**Orchestration.**
- Layout: `charon/lethe/{daemon.py, config.py, conjecture_catalog.py, llm_probe.py, scoring.py, journals/, state/, tests/}`.
- Cron slot: floating (no contention; runs whenever cheap LLM API capacity is available — coordinate with Aletheia/Pythia's quota model).
- CLI: same shape (`--once`, `--batches`, `--forever`).
- Tick loop: pick next conjecture from `conjecture_catalog` (round-robin with priority weighting); fire N=10 cold completions across 2-3 frontier models (no system prompt, identical user prompt asking for status of the conjecture); score each emission against the registered true-form via primary-citation match; if ≥30% (configurable threshold) produce a recognizable false-form, INSERT into `agora.anti_anchor_candidates` with full `sample_emissions` JSONB.
- Conjecture catalog seed (v0): the 10 candidates the BACKLOG already enumerates — Schinzel-Zassenhaus/Dimitrov 2019, Catalan-Mihailescu 2002, Vinogradov/Wooley-BDG 2016, Mertens/Odlyzko-te-Riele 1985, Sato-Tate sym^k/Newton-Thorne 2021, ternary Goldbach/Helfgott 2013, Saxl-cube state, Sensitivity/Huang 2019, Riemann zero pair-correlation (still open, but verify LLM doesn't claim "proven"), bounded gaps vs twin primes / Zhang.
- Conjecture catalog growth: each Pythia DR report tagged `AA-VERIFY-*` adds rows to the catalog automatically (foreign-key reference to `agora.research_queue.id`).

**Self-plumbing submodule.** Native. The catalog *is* the self-plumb mechanism — Lethe never needs an external queue. Growth via Pythia DR reports is automatic; manual additions go through `python -m charon.lethe.catalog add ...`.

**Anti-capture safeguard.** Track `cumulative_emission_rate` per conjecture over time. If a conjecture's false-form emission rate drifts to zero over 90 days (LLM training updates), Lethe marks it `DECAYED` and demotes it from the active rotation but keeps the historical record. If a `DECAYED` conjecture re-fires the false-form, alarm — that's evidence of training-data regression worth recording.

**Harmonia dependency.** Heartbeat helper. Otherwise self-contained; ~350 LOC.

### 3. Acheron — HARD-5 coordinate-collision detector

**Purpose.** Find places in the prose substrate where distinct mathematical coordinates are silently treated as one (the eight-rank example in README §5: tensor / border / cactus / border-cactus / slice / partition / analytic / geometric — each a distinct primitive). Inverse signal to Iris (Iris detects paraphrastic agreement → promote to symbol; Acheron detects paraphrastic disagreement on coordinate meaning → flag HARD-5 violation).

**Orchestration.**
- Layout: `charon/acheron/{daemon.py, config.py, corpus_scanner.py, coordinate_dictionary.py, collision_detector.py, journals/, state/, tests/}`.
- Cron slot: nightly (shares wall-clock budget with Iris; coordinate via Harmonia).
- CLI: same.
- Tick loop: load `coordinate_dictionary` (curated YAML: each ambiguous term mapped to its registered distinct-coordinate set); diff harmonia/memory/ + roles/ + aporia/docs/ + pivot/ + recent commits vs last-processed-sha; for each new/modified file, scan for dictionary terms; for each hit, extract surrounding context (±200 chars) and classify which coordinate the prose is asserting; if ≥2 distinct coordinates fire on the same term within one file or one paragraph cluster, INSERT into `agora.collision_candidates`.
- Coordinate dictionary v0: the eight rank coordinates from README §5; the two Lehmer conjectures (tau vs Mahler); Schinzel-Zassenhaus vs Schinzel-general; Catalan vs Tijdeman-Zagier vs Pillai; Sato-Tate elliptic vs sym^k vs genus-2; binary vs ternary Goldbach; bounded gaps vs twin primes; Mertens-conjecture vs Mertens-function-bounds. Each entry has a registered list of distinct-coordinate strings + a regex that catches typical confusion phrasing.
- Coordinate dictionary growth: Pythia DR reports flagging coordinate ambiguity feed it; substrate vocabulary additions in `aporia/doctrine/substrate_vocabulary/primitives/` auto-import.

**Self-plumbing submodule.** Native. The corpus is the substrate; the dictionary self-populates from the vocabulary directory. No external queue needed.

**Anti-capture safeguard.** False-positive tracking: Iris adjudicates collision_candidates that Acheron flags. If Acheron's reject-rate from Iris exceeds 30%, the daemon auto-raises its match-strictness threshold (require ≥3 distinct-coordinate hits per file, not 2). Conversely, if Iris escalates Acheron flags ≥80% of the time, threshold lowers. Self-tuning via Iris feedback closes the loop.

**Harmonia dependency.** Heartbeat helper + (optional) shared prose-diff infrastructure with Iris (would be elegant if Iris and Acheron share a nightly diff pass and split the analysis). ~500 LOC standalone.

### 4. Moros — cross-pollination automator

**Purpose.** Automate CHARTER §6 (the multi-frontier-model adversarial pass that the program insists on before promoting any load-bearing artifact). Currently manual; runs ~$0.50–$5 per round; the bottleneck is that James or Charon has to remember to fire it before an artifact gets ingested by downstream agents. Moros makes the protocol mechanical — every load-bearing artifact gets the pass without anyone remembering.

**Orchestration.**
- Layout: `charon/moros/{daemon.py, config.py, artifact_detector.py, model_dispatch.py, response_capture.py, meta_analyzer.py, journals/, state/, tests/}`.
- Cron slot: bi-hourly poll on git + Phylax-pending-promotion notifications.
- CLI: same shape + `python -m charon.moros.fire --artifact <path>` (manual one-shot).
- Tick loop: scan git for new/modified files matching the load-bearing-artifact pattern (`harmonia/memory/architecture/*.md`, `pivot/*.md`, candidate symbol filings, foundational doc edits >50 lines); deduplicate against `agora.cross_pollination_jobs` by `artifact_sha`; for each new artifact, INSERT a `pending` row; claim the row; dispatch the artifact verbatim to N=3-5 frontier model APIs in parallel (Claude, GPT-4-class, Gemini, optionally Grok/DeepSeek per arsenal capability matrix); capture raw responses to `pivot/feedback_<artifact-slug>_<date>.md`; run the meta-analyzer on the responses (extract convergence triage: high ≥3 models / medium 2 / singleton); write `pivot/meta_analysis_<artifact-slug>_<date>.md`; if any PATTERN_* candidates emerge, file them as `primitive_proposal` rows; mark job `meta_analyzed`.
- Load-bearing-artifact pattern is configurable; v0 trigger set: every commit touching `harmonia/memory/architecture/`, `pivot/*.md`, `roles/*/CHARTER.md`, `aporia/doctrine/`, files >50 modified lines.

**Self-plumbing submodule.** Yes — `charon/moros/self_plumb.py`. Backfill mode: walk historical commits over a window (e.g., last 30 days) for load-bearing artifacts that don't have a matching `pivot/feedback_*` file, queue them as `source='self_plumb'`. Lets Moros catch up on the backlog of historically un-cross-pollinated docs without James having to enumerate them.

**Anti-capture safeguard.** Moros records its own kill-rate against load-bearing artifacts: how many runs produce a high-convergence revision (≥3 models flag the same structural defect)? If the metric drops below threshold (e.g., 20%) over a rolling 90-day window, the artifact-selection or model-mix is wrong — either Moros is firing on non-load-bearing artifacts (false positives) or the models are all converging into agreement (correlated-mutation failure mode from PATTERN_CORRELATED_MUTATION). Daemon raises a SELF_AUDIT_NULL alarm and refuses to mark new jobs `complete` until the alarm is acknowledged.

**Harmonia dependency.** Heartbeat helper, processed-files ledger primitive (for git-watch dedup). Otherwise standalone; ~600 LOC. The expensive part is the API key plumbing and rate-limit handling, which can crib heavily from Pythia's existing model-dispatch code.

**Cost note.** Per-fire ~$0.50–$5 depending on artifact size and model mix. At 1-2 fires/day = $20-$100/month. Acceptable; substantially cheaper than the agent-time saved.

### 5. Hecate — continuous gradient archaeology over the kill ledger

**Purpose.** Take the one-shot 0.725-bit MI result (314K kills, gradient archaeology, README §thesis) and turn it into a continuous health-and-emergence signal. Every night, re-run the analysis on the growing kill_ledger, track MI(kill_pattern, operator_class) drift, detect emerging cluster separation that signals new operator-class differentiation, emit `primitive_proposal` candidates when a kill_pattern accumulates ≥N members with high local MI.

**Orchestration.**
- Layout: `charon/hecate/{daemon.py, config.py, archaeology.py, mi_estimator.py, clustering.py, null_baseline.py, journals/, state/, tests/}`.
- Cron slot: nightly (low-priority; runs at 02:00 local when no other agent is firing).
- CLI: same shape + `python -m charon.hecate.report --since 2026-04-01` (regenerate gradient report over a window).
- Tick loop: read `agora.kill_ledger_entries` (full history; cache last-night's analysis); compute MI(kill_pattern, operator_class) on current ledger; compute null-permuted MI baseline (shuffle operator_class column N=1000 times); compute `mi_z = (mi_observed - mi_null_mean) / mi_null_std`; cluster kill_patterns by KillVector embedding (HDBSCAN or similar); detect cluster separation drift via Hopkins statistic over time; for any cluster with ≥50 members and local-MI ≥ 0.5 bits, emit a `primitive_proposal` candidate (the kill_pattern is now a candidate emergent operator-class); INSERT into `agora.gradient_archaeology_runs`.
- Output artifacts: `charon/hecate/reports/<DATE>.md` with the MI snapshot, cluster summary, alarm flags, and any primitive_proposals filed.

**Self-plumbing submodule.** Native. The kill_ledger is the substrate; Hecate consumes whatever's grown since last run. No external trigger needed.

**Anti-capture safeguard.** Publishes null-permuted MI alongside observed MI every night. The moment `mi_z` shrinks below threshold (e.g., 2.0) for ≥7 consecutive nights, Hecate raises an alarm: either signal is decaying or the operator_class taxonomy has gone stale and needs Aporia/Techne attention. Hecate does NOT continue to report flat numbers as if everything is fine; degradation is a first-class output.

**Harmonia dependency.** Heartbeat helper. Otherwise pure analytics; ~400 LOC. The MI-estimation and HDBSCAN dependencies (numpy / scipy / sklearn / hdbscan) are already in the project.

## Build order

Same as my prior recommendation, refined with dependencies:

1. **Stygian first.** Lowest infrastructure cost — already specced in BL-C-011/012 of my BACKLOG; the queue table is straightforward; emit shape is well-defined. Produces the kill_ledger volume that Hecate needs. ETA: ~2 days post-Harmonia-push.
2. **Hecate second.** Just consumes Stygian's output. Standalone otherwise. ETA: ~1.5 days.
3. **Lethe third.** No upstream dependencies. Catalog is curated initially. ETA: ~1.5 days, plus initial catalog curation pass.
4. **Moros fourth.** Depends on Phylax (Harmonia's promotion-gate) ideally being live so Moros and Phylax form the upstream/downstream pair. If Phylax slips, Moros can run standalone on git-watch only and add the Phylax-trigger later. ETA: ~2.5 days (the API plumbing is the bulk).
5. **Acheron last.** Depends on Iris's prose-diff infrastructure being established (so Acheron can crib it) and on a curated coordinate-dictionary v0 (~1 day of upfront curation). ETA: ~2 days.

Total raw build: ~9-10 person-days for me. Can compress to ~5-6 if some Harmonia components arrive shipped-and-tested.

## Closing posture

The five agents collectively do what Charon does manually today, on a permanent loop, with telemetry. The substrate-passive-consumer warning still applies — each daemon emits substrate blocks per tick or raises a SELF_AUDIT_NULL alarm; silence is the failure mode.

The validation ladder applies to these agents themselves. Stygian rediscovers the v10 battery's existing kill discipline; that's the calibration rung. The withheld-rediscovery rung lands when Aporia files a synthetic problem with known-correct kill pattern and Stygian recovers it. The open-discovery rung lands when Stygian or Hecate flags a kill pattern that wasn't in any prior taxonomy and survives Phylax/Moros review. Phase 0 success: all five running, all five emitting non-trivial substrate blocks daily.
