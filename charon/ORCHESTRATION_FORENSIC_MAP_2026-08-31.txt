1. EXECUTIVE SUMMARY - why the organism is idle despite abundant queued work
============================================================================

Prometheus is not deadlocked on a lock or a crash. It is idle because the only process anything keeps alive is the reporter, and the reporter executes no science. The apparatus that would drain the backlog was always human-launched Claude Code sessions plus hand-started persona daemons; those stopped around 2026-05-28 and nothing restarts them. The backlog kept growing from committed source files; nothing consumes it.

Six mechanical facts, each verified:

1. There is a reporting engine, not an execution engine. One Windows Task Scheduler job (PrometheusIntelligenceWatchdog, every 30 min) restarts scripts/intelligence_loop.py, which every 4h regenerates a status brief and emails it (intelligence_watchdog.ps1:23,40; intelligence_loop.py:328-364). The actual work executor, engine/driver/run.py, is not scheduled by anything, and even if run it processes only WORK.jsonl items whose cmd is a placeholder echo - real execution is delegated to a reasoning session via ask() -> claude -p (run.py:49-57,76-85), and no session loop runs.

2. The "queue" is a report, not a work engine. engine/queues/BACKLOG.jsonl is regenerated idempotently from on-disk sources by backlog_gen.py. It has no dependency edges - blockers are free-text gate strings (backlog_gen.py:58-63). There is no runtime unparker: a thread leaves PARKED only when backlog_gen.py is re-run AND the upstream source it was gated on has changed (backlog_gen.py:248-281). Nothing autonomously changes those sources.

3. The largest blocker (492 test_spec) has no worker at all. "SPEC-AUTHOR-BATCH lane / batches of 10" is documentary fiction - there is no spec-authoring program. Specs are authored by hand-editing aporia/mathematics/triage.jsonl, a file rewritten wholesale (triage_classifier.py:497). 490 catalog problems classified in May with empty specs sit permanently PARKED.

4. An advisory review became a hard gate (self-inflicted). Elenchus/shadow review is documented "never a gate; no finding halts the loop" (roles/Elenchus/RESPONSIBILITIES.md:9,40-42), yet backlog_gen.py:82-83 hard-gates AUTHORED-AWAITING-ELENCHUS-REVIEW. The 9 authored specs that exist are blocked on a reviewer seat that went dark 08-21; "the loop's research capacity is gated on its reviewer seat" (aporia/.../ALLOCATION_P137_2026-08-22.md:36).

5. Human gates fan out and the human disengaged. 29 profiling threads and the R12 shot park behind one $0-budget decision; 15 retry batches behind one Charon co-sign session; 2 explicit HITL decisions (ratify PROMETHEUS-0; budget envelope). The documented death mode is exactly this: the fleet "died of exhausting its operator's willingness to keep pushing it" (liveness.py:1-8).

6. "1 ALIVE" is a red herring. It is a 300-second process-uptime cutoff (agora/config.py:46) applied to a fleet that was never meant to hold processes open. Personas are Claude Code sessions, not daemons (portfolio_monitor.py:98-110; roles/Lexis/ROLE.md:6). No code binds a ticket to a named agent (run.py:96-104) - a generic worker can execute any ticket. The organism's own real liveness metric (consumed commits, liveness.py) says ALIVE but warns consumed/emitted = 0.02 - "production outpacing consumption... stop producing."

One-sentence answer: Work enters by regenerating a backlog file from sources; it parks on free-text gates; the parties who were supposed to unpark it (Claude Code sessions and hand-launched daemons) are gone and nothing reschedules them; the only surviving cron just describes the stall in an email.

16. SCIENTIFIC RISKS OF PARALLELIZATION
=======================================

Safe to parallelize (independent, no shared frozen state):
- Spec authoring for disjoint qid ranges (append-only shards).
- Independent Elenchus/shadow reviews of different passes.
- Independent catalog attacks (CAT-MATH-*), independent question generation.
- GPU sweeps (already serialized correctly by agora.gpu_reservations lease).
- Rolling re-verification of independent anchors.

Potentially unsafe - must stay serial or guarded:
- Concurrent writes to triage.jsonl (wholesale rewrite -> clobber). Guard: shard or append-only.
- Two run.py instances popping the same WORK item -> duplicate execution under one id. Guard: atomic claim (hook C).
- Concurrent writes to one lineage-scoped memory / registry.
- Changing a ruler/instrument during an active canonical run (freeze-during-run).
- Charon co-sign is a scientific gate - do NOT parallelize it away. Its serialization is correct; only its *non-execution* is the problem.
- Anything that would let an attack consume a self-authored, unreviewed spec (self-grading) - keep the provisional-until-reviewed guard.

Do not confuse experimental isolation with fleet serialization: the frozen-experiment gates (cosign, ruler-freeze, self-grading) are scientific and stay serial; the queue/claim/spec-author/report serializations are accidental and should be parallelized.
