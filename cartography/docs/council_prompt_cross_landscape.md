## The Question

Can structure in one landscape predict or correspond to structure in another?

Specific sub-questions:

### A. OEIS <-> mathlib
Integer sequences appear in theorem statements and proofs. The Catalan numbers (A000108) appear in theorems about polygon triangulations, lattice paths, and binary trees -- different mathlib namespaces. If we map which OEIS sequences appear in which mathlib namespaces, does the OEIS cross-reference graph predict mathlib's cross-namespace imports?

Testable: grep mathlib source for OEIS sequence IDs or known sequence values. Build a bipartite graph (OEIS sequence <-> mathlib namespace). Does the OEIS cross-reference structure predict which mathlib namespaces will share imports?

### B. Finite Groups <-> OEIS
The number of groups of order n is OEIS sequence A000001. Character table entries generate many OEIS sequences. The order statistics of finite groups (number of elements of each order) generate sequences. If we embed groups by their character tables and embed sequences by their terms, do the embeddings align? Does proximity in group-space predict proximity in sequence-space for the sequences generated by those groups?

Testable: for each group G up to order 100, compute the sequence "number of subgroups of order d for d | |G|" and match against OEIS. Do groups that are close in character-table space produce close sequences?

### C. LMFDB <-> mathlib
The modularity theorem connects elliptic curves to modular forms. This is a theorem in mathlib (or should be). The LMFDB relationship graph encodes this connection as edges. Does the structure of the LMFDB modularity edges predict anything about the structure of the mathlib proof of modularity?

More broadly: LMFDB's relationship types (isogeny, twist, modularity, base change) correspond to mathematical operations. Each operation is a theorem or construction in mathlib. The difficulty of the mathlib proof (measured by proof depth or dependency count) might correlate with the rarity of the LMFDB relationship type.

Testable: for each LMFDB relationship type, find the corresponding mathlib theorem. Rank by proof complexity. Rank LMFDB types by frequency. Do rare relationships correspond to complex proofs?

### D. L-function zeros <-> OEIS
The zeros of L-functions are real numbers, but their statistical properties generate integer sequences (e.g., the number of zeros below height T, gap distribution histograms, nearest-neighbor counts). Some of these sequences might already be in OEIS. If the spectral statistics of a new L-function family match a known OEIS sequence, that's a bridge between spectral theory and whatever mathematical domain generated that sequence.

Testable: compute the zero-counting function N(T) for EC L-functions at integer T values. Check if this sequence (or its differences) appears in OEIS.

### E. The Meta-Question
All five landscapes are projections of "mathematical knowledge" into different representational spaces:
- OEIS: numerical shadows of mathematical objects
- mathlib: logical dependencies between mathematical statements  
- Groups: algebraic structures classified by representation theory
- LMFDB: arithmetic objects classified by L-function theory
- Zero geometry: spectral statistics of analytic objects

If two objects are "close" in one landscape, are they close in another? Is there a universal notion of "mathematical proximity" that all five landscapes approximate from different angles?

This is probably too ambitious for current data. But: is there a MINIMAL version of this question that's testable with what we have? What's the smallest cross-landscape prediction we could test today?
