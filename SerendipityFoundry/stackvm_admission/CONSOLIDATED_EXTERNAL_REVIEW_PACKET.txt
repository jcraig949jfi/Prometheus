--------------------------------------------------------------------------------
0. ORIENTATION (self-contained; no prior context assumed)
--------------------------------------------------------------------------------
Prometheus runs a CONSERVED-RISK ADMISSION LEDGER. A scientific test purchases
a threshold K at price 1/K from a permanent lifetime budget ALPHA_LIFE = 0.1,
so at the scientific floor K_MIN = 1000 the program can buy roughly ONE HUNDRED
admission tests EVER. Purchases are irrevocable. Admission evidence must derive
from a public randomness beacon whose value did not exist until after the
registration was committed and externally anchored. The guarantee is

    E[# false admissions over the instrument lifetime]
        = SUM_c P(ADMIT_c | H0_c) <= SUM_c 1/K_c <= ALPHA_LIFE

with a Markov corollary P(any false admission ever) <= ALPHA_LIFE.

TWO CONSTITUTIONAL RULES, both established by earlier adversarial review:

  RULE A.  HINDSIGHT IN THE HYPOTHESIS IS FREE.
           HINDSIGHT IN THE NULL IS FATAL.
    A candidate may be selected using unlimited historical knowledge: it is
    corpus-measurable, and for a null whose distribution GIVEN the candidate
    does not depend on the corpus, P(reject|H0) <= 1/K survives ANY
    corpus-measurable selection rule. No multiplicity is owed for the search.
    That premise dies the moment the reference sampler, matching law, context
    family, or exclusions are FITTED to the same corpus.

  RULE B.  FRESH INPUT IS NOT FRESH EVIDENCE.
    In a deterministic substrate, beacon-derived future inputs do not seal a
    test if the registrant can compute the VERDICT before registration.

THE SUBSTRATE. stackvm-v1 is a metered stack/register VM. Its design charter
makes EVERY BYTE SEQUENCE A LEGAL PROGRAM (opcode = byte % 33; operand bytes
past the end read as 0; empty-stack pop = 0; div/mod by zero pushes 0;
addresses wrap mod 256; registers mod 8; arithmetic mod 2^64). There are no
invalid programs and no exceptions. run_program is bit-deterministic in
(code, inputs, max_steps).

THE MISSION. Build the machinery that would make a future stackvm-v1 claim
scientifically stateable WITHOUT deriving its null from the historical corpus:
a native canonical reference sampler and context family from corpus-independent
sources only; a provenance type system; a verdict-entropy harness; a
qualification of the proposed "H >= 0.5 bits" standard; and a hostile test.
Explicitly NOT to test the five frozen archaeological candidates, and NOT to
purchase a right.

3. THE SEVEN FINDINGS THAT FORCE THE DOWNGRADE
--------------------------------------------------------------------------------

C1  R1 IS NOT A VALID RANK NULL (mathematical, not empirical).
    R1 drew references as mutate(candidate, seed_i). The joint law of
    (C, ref_1..ref_m) is NOT permutation-invariant: C is the PARENT and the
    references are its CHILDREN, drawn from a law conditioned on C. A rank
    p-value has NO 1/(m+1) bound under a non-exchangeable joint law, so any
    test using R1 has an UNDEFINED level regardless of what any harness
    measures. My justification -- "the operator law is the substrate's own
    definition of a neighbour" -- is a statement about semantics that does not
    establish exchangeability. RETIRE R1, or rebuild it on a pivot: draw a
    parent P, then assign the candidate's role uniformly among
    {C} union {mutate(P, seed_i)} so all arms share one parent.

C2  R3's SUPPORT HOLE VOIDS EXCHANGEABILITY.
    I presented "R3's support is [16,96] and is DELIBERATELY NOT BROADENED" as
    principled restraint (a protocol that refuses an interesting claim is
    better than one reverse-engineered to admit it). It is ALSO a mathematical
    hole: a candidate outside that range has reference-measure ZERO, so
    exchangeability fails outright and p0 <= 1/(m+1) is not loose but
    UNDEFINED. Correct handling is a FOLD-TIME SUPPORT-CONTAINMENT CHECK that
    REFUSES the specification, not a note that R3 is "inapplicable".

C3  R1 AND R2 ARE SELECTION-DETECTORS, NOT EVIDENCE-DETECTORS.
    Measured: 12 programs hill-climbed on final stack depth using the verbatim
    spec-default mutate operator -- a pure stand-in for "selection acted",
    with no scientific content -- reject at nominal 1/200 in 10 of 12 cases
    under BOTH samplers; unselected controls reject 0 of 12. Every candidate
    that will ever be nominated is BY CONSTRUCTION the output of a selection
    process, so both nulls are FALSE A PRIORI for every real candidate.
    Rule A does not rescue this: it guarantees P(reject|H0) <= 1/K, but here
    H0 is uniformly false, so the bound is VACUOUSLY SATISFIED WHILE THE
    LEDGER PAYS K FOR A TAUTOLOGY. A rejection certifies "this artifact was
    optimized" -- knowable before the beacon is drawn, and not the claim.

C4  SPEC-MENU MULTIPLICITY (I understated this as a residual).
    3 samplers x 5 observables x 2 tails x arity choices x max_steps choices
    gives a menu J ~ 10^2 - 10^3. Each element individually carries clean tags
    and individually has level <= 1/K; the SELECTION AMONG THEM is untyped,
    because the type system types PARAMETER VALUES, not the choice of which
    typed object to instantiate. Max-selection gives P(reject|H0) <= J/K, i.e.
    a TRUE LEVEL of 0.1 - 1.0 against a price of 0.001. My verdict-entropy
    harness is STRUCTURALLY BLIND to it, because it conditions on the frozen
    spec -- the very object that was selected. Rule B recurs one level up: the
    beacon randomizes WHICH DRAW, never WHICH TEST.
    FIX (elegant, and exactly level-preserving): commit the FULL MENU
    pre-beacon; the BEACON selects the index uniformly. Then
    P(reject) = (1/J) SUM_j P(reject_j) <= 1/K, and stuffing the menu cannot
    help because every element is individually bounded.

C5  "PROTOCOL_CONSTANT" ARITY RESTRUCTURES THE NULL BY THREE ORDERS OF
    MAGNITUDE. Measured, uniform 64-byte programs, max_steps = 20000:
        arity 0 -> median steps    29
        arity 3 -> median steps 20000  (the ceiling)
    Mechanism is pure program semantics: LOOP pops its iteration count from
    the stack, and a uniform 64-bit input word exceeds LOOP_ITER_MAX = 65535
    with probability 1 - 2^-48, so every reachable loop clamps to maximum.
    A VALUE CHOSEN PER TEST AFTER CORPUS INSPECTION IS NOT A CONSTANT OF THE
    PROTOCOL; IT IS A FREE PARAMETER WEARING A CONSTANT'S TAG. My type system
    accepted it because I tagged it PROTOCOL_CONSTANT with the justification
    "fixed by protocol" and never pinned it in a versioned bundle.

C6  THE ENTROPY GATE IS FORMALLY VACUOUS, not merely empirically weak.
    My original packet argued from measurement. There is a stronger formal
    result: for any threshold h < 1 there exist specifications with
    H(verdict) >= h and ZERO claim entropy. Proof: take V = A AND N with N an
    independent fair coin; then H(V) = 1 bit regardless of A, including
    P(A) = 1. VERDICT ENTROPY IS INVARIANT UNDER COMPOSITION WITH INDEPENDENT
    RANDOMIZATION, so it cannot separate claim entropy from nuisance entropy.
    It certifies only that SOME coordinate of the beacon moved.

C7  THE DECOY LAW IS ITSELF AN UNTYPED NULL-PATH OBJECT.
    p0 and p1 are both measured UNDER the decoy law, so my own type system
    should have tagged it and did not. Synthetic decoys differ from the real
    beacon law (which carries version fields, monotone timestamps, chained
    values) and an attacker can branch on the difference; decoys derived from
    real beacon history are corpus-adjacent. Clean resolution: REMOVE DECOY
    MEASUREMENT FROM THE CRITICAL PATH -- under a genuinely exchangeable
    construction p0 is exact combinatorics (1/(m+1)) needing no draws at all.
    Retain decoys only for the beacon-dependence check.

4. THE RESULT THAT STANDS, AND IS STRENGTHENED: THE ENTROPY STANDARD IS DEAD
--------------------------------------------------------------------------------
The mission instructed me to treat "H(verdict) >= 0.5 bits" as a hypothesis to
qualify, not a constant. It does not survive, and this section is unaffected by
the retraction.

MANDATORY NEGATIVE CONTROL (preserved as required): the offline-oracle attack.
On this substrate the cheapest instance is a SATURATING PROGRAM -- `JMP 0`,
two bytes, a legal program by spec -- whose `steps` observable is pinned at the
ceiling on every context the beacon can produce, so the attacker knows the
verdict before registering. Measured over 300 decoy beacons:

    Shannon entropy H              0.869 bits   -> PASSES a 0.5-bit gate
    min-entropy H_inf              0.494 bits
    attacker best-prediction       0.710
    empirical level p0             0.160        (target 1/K = 0.001)

THE 0.5-BIT SHANNON GATE WAVES THE ATTACK THROUGH. Shannon entropy is an
average code length, not a bound on prediction; a distribution with 0.71 mass
on its modal class has H = 0.869.

THE OBVIOUS REPAIR -- min-entropy >= 1.0 bits -- rejects the attack (0.494) but
ALSO REJECTS EVERY HONEST TEST. Honest specifications in the same run had
p1 = 0.000 and attacker accuracy = 1.000: a correctly calibrated test at
threshold K admits with probability 1/K, so its verdict is overwhelmingly
predictable ("it will refuse"). PREDICTABILITY OF THE VERDICT IS THE SIGNATURE
OF CORRECT CALIBRATION, NOT OF AN EXPLOIT.

Both directions fail because two different unknowables were being conflated:
  * IS THE VERDICT UNKNOWN? -- irrelevant. Knowing you will lose is no exploit.
  * CAN THE REGISTRANT CHOOSE A (candidate, spec) PAIR WHOSE ADMISSION
    PROBABILITY UNDER A TRUE NULL EXCEEDS 1/K? -- this is the whole question,
    and the only thing the conserved-risk arithmetic depends on.

ANSWER TO THE MISSION'S QUESTION -- "what exactly must remain unknowable before
purchase for the 1/K guarantee to retain its meaning?"

    NOTHING ABOUT THE VERDICT NEED BE UNKNOWABLE.

What must hold is a property of the TEST, not of the attacker's knowledge:
  (1) LEVEL. P(ADMIT | subject null-true under the canonical reference law)
      <= 1/K, measured by the HARNESS (never the registrant) with the
      candidate REPLACED BY A REFERENCE DRAW.
  (2) BEACON DEPENDENCE. Evidence is genuinely a function of the beacon --
      distinct evidence hashes across decoys -- so the admission event is not
      constant on the beacon fibre.
  (3) NULL PROVENANCE. Every null-path element is
      SPEC_DERIVED | PROTOCOL_CONSTANT | EXTERNAL_RANDOMNESS, never
      CORPUS_DERIVED.
  (4) [ADDED BY THE REVIEW] NON-SELECTION. The specification itself must not
      have been max-selected from a menu (C4), and the null must not be false
      a priori for the candidate class (C3).
Entropy appears nowhere in the final standard.

would have revealed this.

general fact, and a future substrate lacking it cannot reuse this approach.
