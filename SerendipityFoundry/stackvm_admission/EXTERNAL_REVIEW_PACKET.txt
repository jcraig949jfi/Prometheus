1. THE HEADLINE RESULT: THE PROPOSED ENTROPY GATE IS REFUTED
--------------------------------------------------------------------------------
Mission section 5 told me to treat "H(verdict) >= 0.5 bits" as a hypothesis to
qualify rather than a constant. It does not survive.

MANDATORY NEGATIVE CONTROL (the offline-oracle attack, preserved as required):
a saturating program -- `JMP 0`, two bytes, a legal program by spec -- whose
`steps` observable is pinned at the ceiling on every context the beacon can
produce, so the attacker knows the verdict before registering.

Measured over 300 decoy beacons:

    Shannon entropy H            0.869 bits   -> PASSES a 0.5-bit gate
    min-entropy H_inf            0.494 bits
    attacker best-prediction     0.710
    empirical level p0           0.160        (target 1/K = 0.001)

THE 0.5-BIT SHANNON GATE WAVES THE ATTACK THROUGH. Shannon entropy is an
average code length, not a bound on prediction; a distribution with 0.71 mass
on its modal class has H = 0.869. Any threshold on H is satisfiable by a
distribution whose mode is highly predictable.

The obvious repair -- min-entropy >= 1.0 bits -- rejects the attack (0.494)
but ALSO REJECTS EVERY HONEST TEST. Honest specs measured in the same run had
p1 = 0.000 and attacker accuracy = 1.000: a correctly calibrated test at
threshold K admits with probability 1/K, so its verdict is overwhelmingly
predictable ("it will refuse"). Predictability of the verdict is the SIGNATURE
OF CORRECT CALIBRATION, not of an exploit.

Both directions fail, so the framing is wrong. The two unknowables were being
conflated:

  * is the verdict unknown?  -- IRRELEVANT. Knowing you will lose is not an
    exploit.
  * can the registrant choose a (candidate, spec) pair whose admission
    probability UNDER A TRUE NULL exceeds 1/K? -- this is the entire question,
    and it is the only thing the conserved-risk arithmetic depends on.

THE REPLACEMENT STANDARD. The harness -- never the registrant -- measures
    p0 = P(ADMIT | subject drawn from the canonical reference law)
over independent decoy beacons and refuses unless p0 <= 1/K with a stated
one-sided confidence bound. p0 is the admission rate when the candidate is
REPLACED BY A REFERENCE DRAW: a subject null-true by construction. It is
exactly P(ADMIT | H0). It models no attacker, because it measures the test.

On the attack spec p0 = 0.160 against 0.001: refused by a factor of 160.
The gate that works is the one that was already there. Entropy appears
nowhere in the final standard.

TWO AUXILIARY CONDITIONS the level check does not cover:
  (a) BEACON SENSITIVITY -- two decoys must produce different evidence hashes,
      or the verdict is constant on the beacon fibre (catches predictions
      entailed by statically-readable bytecode invariants);
  (b) MEASUREMENT ADEQUACY -- with N decoys and zero admissions the 95% upper
      bound on p0 is ~3/N, so certifying 1e-3 needs N ~ 1e4. See L1.

ANSWER TO THE MISSION'S QUESTION -- "what must remain unknowable before
purchase?" -- NOTHING ABOUT THE VERDICT. What must hold is a property of the
TEST: (1) level p0 <= 1/K measured by the harness; (2) evidence genuinely
beacon-dependent; (3) every null-path element non-CORPUS_DERIVED. Full
derivation in VERDICT_ENTROPY_THEORY.md.

2. WHAT THE LEVEL CHECK IMMEDIATELY EXPOSED
--------------------------------------------------------------------------------
Applied to my own default configuration, it found a two-order-of-magnitude
error before any science was attempted:

  n_refs  n_blocks   K      p0(attack)  p0(honest)  level OK
     3      24     1000       0.160       0.000       no
     3      12     1000       0.070       0.000       no
     3       8     1000       0.010       0.000       no
     7       8     1000       0.020       0.000       no
     7       6     1000       0.010       0.000       no
    15       5     1000       0.000       0.000       yes*
    15       4     1000       0.000       0.000       yes*
  * "no admissions in 200 decoys" = p0 <= 0.015 at 95%, NOT a 1e-3 certification.

Mechanism: under a true null the subject ranks top with probability
1/(1+n_refs). At n_refs=3 that is 1/4, and ~5 consecutive tops inside 24
blocks reaches K -- far more likely than 1/1000. THE CONFIGURATION I WOULD
HAVE SHIPPED BY DEFAULT WAS MISCALIBRATED BY ~160x. No entropy measurement
would have revealed it.

3. THE NATIVE CANONICAL ADMISSION FAMILY
--------------------------------------------------------------------------------
THE SPEC PROPERTY THAT MAKES THIS POSSIBLE AT ALL: stackvm-v1 is designed so
that EVERY BYTE SEQUENCE IS A LEGAL PROGRAM (opcode = byte % 33; operands past
the end read as 0; empty-stack pop = 0; div/mod by zero pushes 0; addresses
and register indices wrap). Therefore the UNIFORM MEASURE OVER BYTE STRINGS is
a well-defined corpus-independent measure on program space. On a substrate
where most byte strings were invalid, the only available "distribution over
programs" would have been the programs that actually occurred -- i.e. the
corpus -- and Rule A would have made a corpus-independent null IMPOSSIBLE IN
PRINCIPLE. This is a property of this instrument's design, not a general fact.

REFERENCE SAMPLERS (all corpus-independent):
  R1 MUTATION-LOCAL      spec-default mutate(candidate, beacon_seed), verbatim
  R2 LENGTH-MATCHED      uniform bytes of the CANDIDATE'S OWN length
  R3 CANONICAL CREATE    spec-default create_random, support [16,96], NOT
                         BROADENED even though known candidates fall outside

THE SUBTLEST DISTINCTION IN THE DESIGN, offered for scrutiny: "match the
candidate's own length" is a function of the HYPOTHESIS (free under Rule A);
"match to the 401-700 band" is a function of the CORPUS (a type error). Both
mention length. Only one is legal.

CONTEXT FAMILY: beacon-derived uniform 64-bit machine words. The historical
task battery is CORPUS_DERIVED and is therefore unavailable.
OBSERVABLES: intrinsic ExecResult fields only (steps, halt class, output,
|opcodes_executed|, |memory_written|, stack depth). TASK SUCCESS IS NOT A
CANONICAL OBSERVABLE.

7. LIMITATIONS AND RESIDUAL RISK
--------------------------------------------------------------------------------
  L1 Level certification incomplete (200 decoys -> p0 <= 0.015 only).
  L2 Wall-clock backstop (halt == "wall") is a host-dependent nondeterminism
     channel; it must be excluded from admissible observables or treated as
     INFRASTRUCTURE_ABORT. NOT YET IMPLEMENTED.
  L3 Observable degeneracy unmeasured: for uniform random short programs some
     intrinsic observables may be near-constant, making them useless in
     practice. A distributional survey under R2 is required before any
     specification is registered.
  L4 Samplers are TRANSCRIBED from the spec, not imported from it, so a spec
     change could silently desynchronize them. The production sampler must
     execute the cited source with a pinned hash.
  L5 Tags are asserted; citation verification confirms file hash and symbol
     existence but not that the VALUE matches the cited symbol (attack A2).
  L6 Sampler-selection smuggling (attack C1) is closed only by protocol, not
     by type.
