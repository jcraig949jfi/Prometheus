safety:                 gen2/ is OUTSIDE the release allowlist, so building it did NOT

known limitations:
  - Resource accounting meters only what a caller explicitly reports via
    consume_budget; enforceable limits are enforced, but executors do not yet
    auto-measure wall/cpu/mem/tokens (those remain 'measured'/'estimated'/
    'unavailable' -- never fabricated as enforced).
  - No full replay/restore engine: checkpoints capture chain position + state
    hash + object counts; fork inherits the EVENT history by reference but does
    NOT re-execute. A world cannot yet be re-run from a checkpoint.
  - Single machine only (SQLite by design); no distributed mode.
  - DELAYED_SHARING is a named policy but is delivered as immediate policy-gated
    import; there is no background sharing scheduler.
  - Auth is token->client ownership; there is no finer per-session scope model.
  - The canary driver exercises imports + all object types + accounting; the
    failure-metabolization CONSUMED_BY edges are exercised by T13, not by the
    canary run (imported failures are recorded, not claimed-consumed there).
  - executor isolation: reference executors run in-process; subprocess/remote
    executor isolation is not implemented.
