1. WHAT THE SERENDIPITY FOUNDRY IS (first-time explainer)
---------------------------------------------------------------------
The Foundry is Prometheus's instrument for doing falsification-
grade science on EXECUTABLE EVOLUTIONARY SUBSTRATES -- small
program-like organisms (stack-machine programs, GP trees, Push
programs) that are randomly created, mutated, recombined, executed,
and selected. Its design premise, in two lines from its own README:

  Discovery fails OPEN: useless artifacts, failed programs, dead
  code and unexplained traces are preserved, never deleted for
  being currently useless.
  Adjudication fails CLOSED: no claim is earned by novelty,
  clustering, frequency, or surprise -- only by frozen causal
  tests (absence, provenance, ablation, matched random controls,
  transfer, hostile intervention); anything less is FOSSIL_ONLY.

It exists because Prometheus's north star is not a better archive
or benchmark but a machine that can acquire NEW REASONING
OPERATIONS whose future use measurably expands what it can reach.
The Foundry is where candidate mechanisms for that claim get
executed, measured, and mostly killed.

Physically: two machines. M1 (192.168.1.202) runs the instrument
-- the single EXECUTION AND PROVENANCE AUTHORITY. M2 (the research
console, this repo) holds preregistrations, drives experiments
through a thin client, and performs statistics over M1-produced
canonical artifacts. M2 never executes substrate code locally; a
locally improvised substrate is constitutionally forbidden as a
replacement for the instrument.

2. BACKEND ARCHITECTURE (what a reviewer should picture)
---------------------------------------------------------------------
From the release source (D:\ZeusD\serendipity-foundry-0.1.1) and
the captured OpenAPI surface (39 routes):

  donor ecosystems (pyribs, PyshGP, QDax, ...)
      | isolated adapters, semantics preserved, contract-tested
      v
  EngineAdapter / Archive / SearchDriver --> APPEND-ONLY EVENT
      |                                      LEDGER (hash chain)
      v                                          |
  FOSSIL STORE (content-addressed, tiered)       v
      |                              analytics projection
      v
  FrozenCorpus --> competing IndexBuilders (raw ... low-rank)
      |            queries consume raw TaskEvidence ONLY
      v
  downstream acquisition --> specimen nomination --> COURT
                                               (fail-closed)

Key properties, each load-bearing for D-14:
  RELEASE IDENTITY. /v0/version reports a source_tree_hash; every
    client pins it and refuses a mismatched instrument. D-14 runs
    against 50b5c232... (git 71b29593, 211 files), the release
    D-13 closed on.
  CONTENT-ADDRESSED ARTIFACTS. Programs are artifacts with sha256
    ids; genotypes are fetchable (base64) with their own
    genotype_addr = sha256(genotype bytes). Creation is recorded
    with op, seed, config hash, event_seq -- full lineage.
  ENGINES. stackvm-v1 (in-house metered stack VM; the D-14
    subject), treegp-deap, push-pyshgp. Capabilities are
    manifested per engine (create_random, mutate, recombine,
    evaluate, trace, step_meter, behavior...).
  WORLDS AND BATTERIES. Registry-validated causal worlds (D-12/13
    used seq_transducer_v1 with an affine_residual oracle at
    horizon 4) and evaluation batteries (x_uniform / x_ecological
    / x_interventional, sizes <= 64).
  SEARCH PHYSICS (observer side). Endpoints that measure
    variation->consequence physics without driving search:
    displacement, locality, heritability, improvement, trace.
    D-13's channels (neutral fraction, K_positive@0.25, induced
    fault rate, decoupled retention) came from here.
  SEARCH DRIVERS own selection (random, objective, novelty,
    map_elites); native engine selection is disabled -- selection
    provenance is driver-side by design.
  TASKS AND EVALUATE. Content-addressed IO-example tasks; evaluate
    returns fitness, per-run output_hash, a behavior descriptor,
    resource accounting, and a typed failure record.
  EVIDENCE FIREWALL. Index queries may consume raw machine task
    evidence ONLY -- oracle distances, target diffs, subgoals,
    semantic embeddings and problem NAMES are forbidden by
    construction (the "D-7 firewall").
  COURT. Fail-closed adjudication of nominated specimens with
    frozen causal tests. Not exercised by D-14.
  ADMIN. Health, events, per-trace lookup, environment; an
    append-only ledger with event_seq underpins /v0/replay.

3. THE CLIENT, AND WHY IT LOOKS PARANOID
---------------------------------------------------------------------
M2 drives M1 through one stdlib-only file, remote.py (sha256
bdd6f077...), whose two invariants are constitutional:
  1. RELEASE PIN: refuse to run against any other instrument
     identity; D-13 policy re-verifies the pin every 25 calls
     (adopted after incident H-1, when M1 hot-swapped releases
     mid-campaign and a runner served 221 calls under a stale pin).
  2. THE NETWORK IS NEVER A SCIENTIFIC RESULT: timeouts and 5xx
     raise TransportIndeterminate carrying a trace id; the caller
     reconciles against the server ledger to learn whether the
     operation committed. Only a fully received 2xx is a result.
Credentials: a bearer token and a private CA cert live in an
operator kit outside every repo (C:\ZeusD-var\d11\remote\), loaded
as environment variables; values are never journaled or committed.
D-14 recovered this mechanism from D-13's own bootstrap report
rather than from memory, and used it unchanged.

5. D-14 DESIGN (frozen 2026-08-31, commit 67a295618)
---------------------------------------------------------------------
PRIMARY: middle_mass = P(site influence in (0, 0.25]) over all
measured sites; <= 0.05 -> D14_PREDICTION_SURVIVES; > 0.05 ->
D14_MECHANISM_FALSIFIED; exact value reported either way; no
alternative statistic, interval, threshold, subgroup, or
classifier may adjudicate (no-rescue, frozen).
HONESTY CONDITIONS (both in the freeze): (a) D-13's empty local
band is known context, not a D-14 prediction; (b) DECLARED at
freeze time: under the inherited intervention the primary
statistic is closely related to D-13's kpos025 channel, so the
prediction is riskier than retrodiction but less risky than the
Gen-3 packet implied; the genuinely novel content is the fresh
sample, SITE RESOLUTION, and the zero-vs-high decomposition.
SITE: one position of the native serialized genotype (stackvm
programs are byte sequences, observed length 84).
CANONICAL INTERVENTION: the native single-byte point change, with
a frozen first-hit selection rule per (parent, site); influence =
changed_cases / evaluable_cases over a frozen 8-case battery
(the task charter's exact formula), all execution and output
hashing server-side; the client compares hashes only.
CONTROLS: replay determinism (evaluate and mutate), no-op class
(zero-diff children must be behaviorally identical), intervention
locality (per-pair genotype diff == 1), comparator provenance,
content-address hand-check. SUPPORT GATES: >= 100 clean parents,
>= 1000 measured sites, influence must vary; any failure ->
D14_INDETERMINATE, never a scientific verdict.
