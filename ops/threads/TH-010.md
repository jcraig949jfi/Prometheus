# TH-010 -- Aether as a known-answer benchmark for Prometheus task machinery

Status: OPEN (parked; ready to use). Owner: Aether. Opened 2026-09-27. Origin: C-002 E-007; parent TH-006 (evidence portability).
Question: can Aether's frozen workloads serve as the standing correctness benchmark for any Campaign/Task execution path
(dispatch, duplicates, retries, missing-unit detection, cross-host determinism), independently of Aether's open science?
Why it matters: E-007 showed that exact-integer units with expected hashes derived from committed evidence make every queue failure
mechanical to detect (19 attempts, 4 hosts, Windows/Linux, Python 3.11/3.13, NumPy 1.26/2.4, 0 disagreements). A known-answer lane
tests the machinery without asking science to prove queue correctness.
What exists: Aether/observatory/aeth03_unit.py, aeth03_lane_reduce.py (+ tests), ops/campaigns/C-002/E-007/known_tasks.json,
Aether/runpod/aether_units (pinned remote execution).
Constraint: the benchmark must never masquerade as science; its tasks carry lane = known and produce no scientific claim.
