PROMETHEUS MASTER WORK ORDER -- MWO-0003

Date: 2026-09-29 America/New_York
Purpose: Fleet Micro-Probes. Run a small end-to-end conformance probe across the live Prometheus machinery, and
pause D2 repair/audit cycling while its operator gate is open.

This order is intentionally small.

----------------------------------------------------------------------------------------------------------------

0. STANDING POLICY AND PUBLICATION

MWO-0001 and MWO-0002 policies, scientific gates, custody rules, blindness rules, spend restrictions, the Fabric
v0.2 freeze, and MWO-0002 section 2 (authoring / approval / publication) remain in force, except as stated below.

Publisher for MWO-0003: Aporia, by operator designation, for this publication only. Publishing confers no
steward, coordinator, scheduling or adjudication authority.

Publication uses the two-commit protocol of MWO-0002 section 2:

Phase A -- publication commit P
1. Write this order byte-identically, LF line endings, to ops/work_orders/CURRENT.md and to
   ops/work_orders/archive/MWO-0003_2026-09-29.md.
2. Commit only those two canonical files. This commit is P.
3. Push P to origin/main.
4. Verify both committed blobs from origin/main and compute their identical SHA-256.
MWO-0003 is authoritative at P.

Phase B -- notification and record commit R
5. Send one fleet-wide broadcast: MWO ID, P, archive path, blob SHA-256, and
   "fetch origin/main:ops/work_orders/CURRENT.md and adopt".
6. Append the publication row to ops/work_orders/PUBLICATIONS.md.
7. Update the publisher's WORK_STATE with mwo_id = MWO-0003 and mwo_commit = P.
8. Commit and push these records as R.
9. Verify R on origin/main. The publisher then returns to its MWO-0003 duties or HOLD.

----------------------------------------------------------------------------------------------------------------

1. FP-001 -- ONE MICRO-PROBE PER LIVE SEAT

A LIVE seat is one on the MWO-0002 section 3 roster rule: a seat with a roles/<Seat>/WORK_STATE.json pushed after
the MWO-0001 publication, or any seat that becomes live for its own reasons while MWO-0003 is current. No dormant
or parked seat is woken merely for FP-001. A seat that stays dormant is recorded centrally as NOT_LIVE, not as a
failure.

Every live scientific or infrastructure seat runs exactly one small probe through machinery it already owns.

Choose the smallest existing deterministic smoke test, replay, fixture, verifier, scorer, ruler, engine test, or
other bounded executable path that genuinely exercises the seat's machinery.

Constraints:
* use existing code and existing semantics;
* no new scientific hypothesis;
* no threshold or preregistration change;
* no sealed or withheld input;
* no new campaign or wave;
* no paid external compute;
* target <= 10 minutes wall time;
* do not invent a large test merely to participate.

If no suitable existing probe exists, report NO_EXISTING_MICRO_PROBE. That is useful evidence.

Seats with a section 5 probe (Odysseus, Aporia) file that probe as their FP-001 result.

----------------------------------------------------------------------------------------------------------------

2. EXECUTION PATH

If the probe is portable to currently available Fabric capability:
* submit one Fabric Task;
* request two independent replicas where supported;
* compare result/artifact digests.

If it is not currently portable:
* run one native execution, using the canonical Fabric lease where a substantial resource claim is needed;
* record the exact reason Fabric could not host it.

Do not modify Fabric to make a probe pass.

----------------------------------------------------------------------------------------------------------------

3. DISCOVERY TEST

Each seat records how it discovered MWO-0003.

No bespoke per-seat prompt should be sent merely to announce this order.

Record one of:
* own_loop_fetch
* publication_broadcast
* bespoke_prompt
* other

A publication broadcast is normal and counts as successful autonomous discovery.

ODYSSEUS -- Fabric recovery probe. Odysseus runs one disposable Fabric recovery probe:
* the first Attempt fails intentionally;
* retry/reap machinery must produce or permit a clean successor Attempt;
* verify that leases, artifacts and task state converge correctly.
Use synthetic data only.

APORIA -- cold-start probe. Aporia runs the cold-start probe:
* a fresh worker/session;
* only the ordinary repository and bootstrap material available to a seat;
* no bespoke MWO path supplied;
* determine whether it discovers ops/work_orders/CURRENT.md and its authorized work.
Do not repair the boot path before recording the result.

8. END

After one normal loop, central coordination reviews the pushed FP-001 results directly from Git.

The review asks only:
1. Did each live machine actually execute something?
2. Did MWO discovery work without bespoke prompting?
3. Did portable execution work through Fabric?
4. Did independent replicas agree?
5. Did native fallback use the correct authority?
6. Did recovery work?
7. Could a genuinely fresh seat discover the control plane?
8. Which shared defects are worth repairing once for the entire fleet?

Then FP-001 ends. The D2 pause (section 7) continues until the operator resolves S1 or a later MWO changes it.
