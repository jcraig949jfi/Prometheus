### A.3 What an OBSERVATION carries

- Wire shape `ObservationCreate` (`api.py:130-141`): `exp_id`, `content: dict[str, Any]`, `outcome`, optional `pred_id`, `work_id`, `retrospective`, `replication`. Route `POST /v2/worlds/{wid}/observations` (`api.py:810-824`) with `Idempotency-Key`.
- Stored (`runtime.py:2014-2020`) as `json.dumps(content)` in one TEXT column; returned whole by `_observation_dict` (`runtime.py:3907-3914`) on `list_observations` (`:1571-1582`), inside the audit envelope (`:1420-1422`, `:1468`) and on `/v2/read/observations` (`:3654`).
- Write returns the causal anchor: `{obs_id, event_id, entry_hash, event_seq, world_index, evidence_class, evidence_role}` (`runtime.py:2059-2064`, D-ANCHOR-1).
- **Size limits: none in the engine.** No `max_length`/body cap in `api.py`, `serve.py` or `runtime.py` (grep, only `error[:500]` truncation at `runtime.py:1191`); uvicorn is launched with defaults (`serve.py:81-83`); SQLite TEXT default cap is 10^9 bytes. Practical limit = every read path returns content whole.
- `content` must be a JSON **object** (dict) — a bare list is a 422 — but any nesting inside is accepted and never interpreted. So today, with zero engine change, an observation CAN hold: a witness vector (`{"witness": {"positions": [...]}}`), a bounded raw trajectory (`{"trajectory": [...]}`), a lineage pointer (`{"parent_obs_id": "obs_..."}`), a blob reference (`{"artifact_id": "...", "blob_hash": "sha256:..."}`). **None of those are typed, validated, resolved, or followed by the engine**; the only typed pointers on the row are `exp_id`, `pred_id`, `work_id`.
- The `OBSERVATION_RECORDED` event (`runtime.py:2006-2013`) carries `refs={obs_id, exp_id, pred_id, work_id?, result_hash?}` and **passes no `artifacts` list** — the events column exists (`store.py:113`) but observations never populate it; only `ARTIFACT_CREATED`/`ARTIFACT_IMPORTED`/`WORLD_FORKED` do (`runtime.py:2190-2192`, `:2429-2442`, `:2580-2584`).
- `record_observation(replication=True)` (`runtime.py:1878-2067`): the FIRST observation of an experiment (or of a prediction) is ORIGINAL; any later one on the same experiment/prediction is a repeat (`:1989-1995`) and is a **409 unless `replication=True`** (`:1996-2001`); a repeat is recorded `evidence_role=REPLICATION` and never re-adjudicates (`:2002`, `:2030`). Order is preserved by `created_seq`; the v7 test `tests/test_sfe_v7_contracts.py:541-582` records 4 ordered repeats per cell with `repeat_index` inside `content` and asserts `pred_prospective` is true for all four ("prospectivity is a fact about the PREDICTION's ordering", `:576-582`). Paired refusal test at `:585-601`.
- `evidence_class`: `ENGINE_WORK_RESULT` iff `work_id` names a COMPLETED work item of this world enqueued for this experiment (`runtime.py:1946-1963`); `require_attestation` worlds refuse unattested observations at the write (`:1936-1945`).

### A.4 Experiments, analysis, source-observation links

- `create_experiment` (`runtime.py:1675-1796`): `spec` freeform, sealed as `content_hash(spec)` (`:1753`); `commit` (default true) crosses the irreversible boundary in the same transaction; `enqueue` requires commit (`:1698-1701`); work payload is the spec itself (`:1840`).
- **Analysis = an experiment with a declared source set** (`api.py:102-121`, `runtime.py:1702-1731`). Rules: `source_set` requires `unit_of_analysis` (`:1714-1718`); `unit_of_analysis`/`declared_n` without `source_set` is a 422 (`:1719-1722`); `source_set_hash = content_hash(sorted(ids))` — order- and world-independent (`:1724-1731`); **only the hash is stored** (`api.py:115-118`, doc `docs/SCIENTIFIC_PROVENANCE.md:172-177`); `ANALYSIS_REGISTERED` sealed with `verified_n`, `sources_submitted`, `sources_unresolved`, `unit_mismatch` (`:1755-1778`); strict profile refuses a mismatch (`:1766-1774`). `is_analysis` is derived from `source_set_hash` (`runtime.py:3903`).
- `_verify_units` (`runtime.py:3146-3195`) resolves ids prefixed `obs_`, `exp_`, `wld_` **across any world of the same client** (`:3165-3186`); a source owned by another client, or a non-string, counts as `unresolved` (`:3184-3186`).
- **So yes: an experiment can reference another experiment's observation** — cross-world within one client — via `source_set`. What it gets is a sealed hash and a count, not a per-source edge; the set itself is recoverable only if the caller also puts it in `spec`.
- Lineage edges: written by `_edge` (`runtime.py:2125-2136`); the public `add_lineage_edge` (`:2138-2143`) and `consume_failure` (`:2107-2123`) **have no HTTP route** — `api.py` exposes only `GET /v2/worlds/{wid}/lineage` (`api.py:755-763`). Over the wire the only edge ever written is the automatic `hypothesis -TESTS-> experiment` edge at `runtime.py:1779-1781`. `descendants`/`ancestors` BFS is world-scoped (`runtime.py:3819-3853`).

A path may point at a list or dict (found=True, value=that object); `in_declared_range` is computed only for numeric, non-bool values (`:3394-3398`, `:3662-3665`).

### B.2 Read scopes (what replaced group-scoped grants)

- Why: the first v7 cut scoped grants to `topology_group`; that was withdrawn in `642736763` because the group gates `_may_cross`, so a read grant would have conferred artifact-import eligibility, and the corpus needing grants was 189 existing worlds (98 in no group) whose `topology_group` must not be mutated (`store.py:417-426`; `docs/SCIENTIFIC_PROVENANCE.md:393-404`; contract `integration/SFE_CONTRACT_FOR_ARCHAEON_AND_VIVARIUM.md:167-174`). Note the section comment at `runtime.py:3409-3413` still says "scoped to a TOPOLOGY GROUP" — stale prose; the code below it uses read scopes.
- Tables `read_scopes(scope_id, owner_client_id, name, note)`, `read_scope_worlds(scope_id, world_id)`, `read_grants(grant_id, scope_id, grantee_client_id, granted_by, note, created_ts, revoked_ts)` UNIQUE(scope, grantee) (`store.py:427-455`).
- Owner side: `create_read_scope` (`runtime.py:3415-3435`); `add_scope_worlds` adds only worlds the owner owns, silently reporting others as `not_yours` and **writing nothing on the world** (`:3437-3465`); `grant_read` owner-only, no self-grant, re-grant after revoke replaces the row (the prior revoked row is DELETED at `:3511-3513`; the `READ_REVOKED` foundry event `:3540-3544` remains the durable record); `revoke_read` sets `revoked_ts` (`:3527-3547`). Routes `api.py:1105-1145`.
- Grantee side: `read_worlds` (`:3566-3594`) and `read_observations` (`:3596-3689`) return **only worlds the caller does not own** (`:3586`, `:3624`), in scopes actively granted (`_granted_scopes`, `:3561-3564`); an ungranted scope yields EMPTY, never 403 (`:3577-3581`). Filters: `scope` (query param name, `api.py:1160-1175`), `world_id`, `evidence_class` (validated against the closed set, `:3609-3612`), `measurement`, `limit` (default 1000).
- **"Resolve the outcome without guessing"** (commit `be65b0efa`): passing `measurement=<id or identity_hash>` makes `read_observations` walk each row's `content` along the measurement's `value_path` and attach a `measured` block `{measurement_id, identity_hash, value_path, found, value, direction, unit, in_declared_range?}` (`:3639-3667`) — resolved on the `/v2/read/*` surface rather than by widening the owner-scoped per-observation route (`:3635-3638`). A measurement with no `value_path` is a 422 here (`:3642-3646`). Test `tests/test_sfe_v7_contracts.py:673-707`.
- **The census beside rows**: `corpus = {worlds, scopes, by_client[{client_id, observations}], by_evidence_class[{evidence_class, observations}], filtered_evidence_class, measurement{... resolved, unresolved} | null, truncated}` (`runtime.py:3668-3689`); `truncated = len(rows) >= limit`. `read_worlds` returns `corpus_tenancy` (`:3588-3594`). Rationale `:3602-3608`.
- Read grants are READ-only (no write/claim/work/budget) and do not widen `GET /v2/worlds` — tests `tests/test_sfe_v7_contracts.py:287-308`; contract `:175-188`.

## E. Explicit MUST-NOT-CHANGE statements found

Engine (Daedalus):
- "Nothing in this release changes an existing contract. Every field is optional, every route is new, and an unmodified v5 client keeps working with byte-identical results." (`docs/SCIENTIFIC_PROVENANCE.md:7-9`); "every migration is purely additive and back-fills nothing" (`:5-6`, `:374-377`; `store.py:674-683`, `698-705`, `720-738`).
- The one rule: "The engine compares hashes, counts distinct things, and checks containment of declared sets. It never computes a variance, fits a model, chooses an estimator, or judges whether a design was adequate." (`docs/SCIENTIFIC_PROVENANCE.md:13-25`; `runtime.py:2592-2608`). ## D. Contract-level requirements for six expansions

Owner key: **Daedalus** = engine, **Vivarium** = executors/queue/runner, **Mnemosyne** = PEW, **Harmonia** = design/adjudication. "Works today" = no code change in that seat.

### D.1 Observation carrying a witness vector (which positions differ)
- **Engine: works today.** `content` is a freeform object (`api.py:132`; §A.3): `{"result": {"score": ..., "witness": {"positions": [3,7,11], "length": 24}}}` is stored, returned whole, sealed into the envelope, and readable cross-seat. A measurement can be registered with `value_path="result.witness.positions"` (found=True, value=list; no range check for a list, `runtime.py:3394-3398`). Not addressable per position — `_check_value_path` forbids indices (`:250-264`); a per-position scalar needs one key per position or a bitmask string.
- **Vivarium: new executor or engine result field.** The reference `BitStringExecutor` returns only `{bits, score, solved, length}` and keeps the target private (engine `executors.py:73-89`); Vivarium's `evaluate_bitstring` wraps it verbatim (`viv/executors.py:105-127`). Smallest change: Daedalus adds `"witness": [i for i in range(n) if bits[i] != target[i]]` to the reference result (in-process, deterministic, no schema change; **changes the result dict shape and hence `result_hash` for every future bitstring run** — an executor version bump, not a contract change), or Vivarium registers a new kind `evaluate_bitstring_witness_v0` (§C.4). `outcome_rule` on a list field only supports `==`/`!=` (else indeterminate, `spec.py:450-466`), so the rule should still target `score`/`solved`.
- **PEW: works today in jsonb, invisible to queries.** Rides in `resources_used`/`ecology` with no validation; a queryable column needs additive `witness jsonb` + `FOSSIL_FIELDS`/`FossilEncounterIn`/`_ENC_INSERT` edits (`service.py:801-807`, `:820-850`, `:1070-1077`).
- **Harmonia:** registers the measurement `(name, version, implementation_hash, value_path)` so the vector resolves without guessing.

### D.2 Observation carrying a bounded raw trajectory
- **Engine: works today two ways, neither typed.** (i) Inline in `content` — no size limit (§A.3), travels in the envelope and on `/v2/read/observations`; cost is that every read of the world's observations carries it. (ii) As an artifact: `create_artifact(kind="trajectory", data=bytes, meta={"exp_id","obs_id","steps":N}, expected_blob_hash=...)` (`runtime.py:2146-2202`), then reference `blob_hash` inside `content`. The engine has no typed observation→artifact link and `OBSERVATION_RECORDED` passes no `artifacts` list (`:2006-2013`). **Smallest engine change (Daedalus, additive, optional field):** accept `artifact_refs: list[str]` on `ObservationCreate` and pass them as `events.append(..., artifacts=...)`, mirroring `failures.artifact_refs` (`store.py:270`; `api.py:155`) — makes the blob hash part of the sealed event without touching `observations`' columns.
- **Vivarium: works today for the repeat-shaped trajectory** (`repeats[]` with `state=persist` and `budget.max_observations`, `runner.py:364-379`; `spec.py:83-84`); a per-step trace inside one repeat is a field in the result dict, bounded only by the executor. Vivarium never writes artifacts (no `c.artifact` call in `viv/`); using route (ii) needs a runner step.
- **PEW: doctrine conflict.** Storing raw content contradicts reference-only (`005:3-4`); the compliant path is `output_digest` in a seal envelope (`closure.py:298-304`) with the bytes as an SFE artifact. A `trajectory jsonb` column with a byte cap is a doctrine change (Mnemosyne + Harmonia sign-off), not just schema.
- **Harmonia:** declares the bound (N steps / bytes) in the spec so it is sealed (`SFE_CONTRACT…:225-240`).

### D.3 World whose target derives from another world's (relatedness)
- **Engine: typed relation exists only via `fork`** (`parent_world_id`, `fork_point`, `WORLD_FORKED` with freeform `interventions`, seed_root overridable per child; `runtime.py:2485-2589`; requires a checkpoint; child starts CREATED — Harmonia trap T3). Without a fork, relatedness can be sealed but not traversed: put the derivation in `spec` (`{"target_from": {"world_id","seed_root","transform","positions"}}`) and/or in a `comparison`/`campaign` family manifest with `member_kind="world"` members (`runtime.py:2651-2694`, manifest sealed). `lineage_edges` are world-scoped (`store.py:285`) and have no POST route (§A.4), so a cross-world DERIVED_FROM edge is **not small** (schema + route + BFS change).
- **Vivarium: the target is `sha256("target:<seed>:<length>")`** (engine `executors.py:73-76`) so "derived target" today means "derived seed_root", which the requester computes and records in `source_evidence` (provenance only). A `world.parent` key would extend `_check_world` (`spec.py:148-166`) and change what `spec_hash` covers; an executor that transforms a parent target (flip k positions) needs a new kind whose payload names the parent seed and the transform explicitly (no defaults).
- **PEW: works today.** `fossil_worlds.parent_world` accepted on POST (`service.py:1340`); `fossil_edges` FORK; missing only an edge-write endpoint, a FK, and a relatedness relation term (relation is free text, so no migration).
- **Harmonia:** owns the derivation vocabulary (what counts as "related") and whether a fork or a fresh world is the honest container.

### D.4 Experiment consuming a prior observation as input (data injection / fixed-target series)
- **Engine: works today, three routes.** (i) Fixed-target series: put the target/prior value in `spec` — sealed in `spec_hash`, delivered to the executor as the work payload (`runtime.py:1840`). (ii) Typed citation: `source_set=[obs_id]`, `unit_of_analysis="observation"`, `declared_n=1` (`:1711-1731`) — cross-world within the client, seals `source_set_hash` and `ANALYSIS_REGISTERED` with `verified_n`; **caveat:** this marks the run `is_analysis=True` (`:3903`) and analyses are what claims cite, so a data-injection run and a statistical analysis become indistinguishable at the engine level. (iii) Artifact import: `import_artifact` gives `origin=IMPORTED` + `source_world/source_artifact/source_hash` and an `ARTIFACT_IMPORTED` event (`:2364-2452`) — same client or bilateral registered topology group, and the payload must have been placed as an artifact first.
- **Vivarium: only route (i) is admissible.** The executor sees exactly the sealed spec (`executors.py:141-142`; blinding `runner.py:270-276`); there is no runtime fetch and adding one crosses the blinding boundary. Copy the prior value into `work.payload` as a declared parameter and cite the source via `replication_of`/`source_evidence` (design, not execution). Route (ii) would need `unit_of_analysis/declared_n/source_set` threaded through `runner.py:303-305` (client already supports them, `sfclient/client.py:194-199`).
- **PEW: no field.** Encounter→encounter needs either a `fossil_edges` row `relation='TRANSFER'` (kinds allow `encounter`, `005:94`, but `dst_id` cannot carry the `(encounter_id, run_key)` pair — the reason 007 chose typed columns) or additive `parent_encounter_id`/`parent_encounter_run_id` + generated key + FK mirroring 007/009 (Mnemosyne).
- **Harmonia:** rules which route is honest per design (a fixed target is a sealed parameter; a consumed observation is provenance) and whether route (ii)'s `is_analysis` conflation is acceptable.

### D.5 Population executor emitting per-generation lineage records
- **Engine: works today without new types, with a semantic cost.** Options: (i) one observation per generation, `replication=True` for g>0, `content.generation=g` — ordered by `created_seq` (test `test_sfe_v7_contracts.py:541-582`), but generation 0 becomes the ORIGINAL adjudication and later generations are typed REPLICATION, which is not what they are; (ii) one observation with `content.generations=[...]` (bounded); (iii) one artifact per run holding the lineage table (JSONL bytes, content-addressed) + a summary observation. `lineage_edges` model research objects, not organisms, and have no write route. A first-class `evidence_role='SERIES'` or `sequence_index` column would touch the CHECK constraint (`store.py:243-244`) = migration (Daedalus, not small).
- **Vivarium: new stateful kind** (§C.4 steps 1-2; extend `new_state`, `executors.py:131-135`); generations map naturally to repeats under `state=persist` (`spec.py:255-261`), which already yields one SFE observation per generation (`runner.py:440-455`) — i.e. option (i) is what Vivarium would do today with no runner change. Herakles' rule "grade recorded per OBSERVATION, not per tool" applies (`INBOX_HERAKLES…:93-94`).
- **PEW: partial.** `fossil_players.lineage_id/generation/parent_player` and ANCESTOR/MUTATION edges exist (`006:59-64`; `005:92-105`) but there is no edge-write endpoint, Vivarium writes no players, and one encounter is written per run. Needs an edge/`lineage_records` write path keyed `(lineage_id, generation, run_id)` (Mnemosyne).
- **Harmonia:** decides the unit (organism / generation / run) before any row is written — the `unit_of_analysis` vocabulary today has no "generation" (`runtime.py:118-119`).

### D.6 Program-interpreter executor with an execution trace
- **Engine: works today.** Program bytes as an artifact → `blob_hash` doubles as `player_identity_hash` in the attestation (contract `:399-402`); trace inline in `content` or as a second artifact (D.2); scalar outcome registered as a measurement with `value_path`; `executed_config` must equal the sealed spec or `CONFIG_DIVERGENCE` fires (`runtime.py:1128-1150`); reproducibility must be declared honestly — an interpreter that touches wall-clock or an external service is not BIT_DETERMINISTIC (`executors.py:10-12`).
- **Vivarium: new stateless kind** with payload naming program + inputs explicitly (§C.4). **No executor may spawn a process today** (§C.3); an out-of-process interpreter needs the `external_backend_v0` contract Herakles sketched (`INBOX_HERAKLES…:73-94`), plus lease sizing/heartbeat (`runner.py:92-161`). Reproducibility grade must come from the executor per result, not be pasted through (`BOUNDARY_REVIEW…:259-263`).
- **PEW:** same posture as D.2 — `action_id`/`output_digest` in the seal, trace as an SFE artifact; a trace column needs doctrine sign-off (Mnemosyne).
- **Harmonia:** registers the trace-derived measurement and the trace bound.
