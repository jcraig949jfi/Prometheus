## 3. Claim 1 — the navigability gate, the experiment both chains skip (E3)

Both M0 ("can the selector recognize novelty") and M1 ("does a model metabolize the
kill-geometry") assume the kill-geometry carries structure to recognize / metabolize.
That is the residue-eligibility question Charon already owns
(`feedback_residue_must_be_navigable_not_logged`: residue counts only if it changes a
routing distribution, localizes a boundary, falsifies a prior signature, or adds tensor
rank — else it is exhaust). At the data level, the answer is not yet "no" — it is **"the
object was never built"**:

- **`kill_vector` is populated for 0.0% of 5,412,015 sampled corpus records.** The field
  designed to hold the navigable geometry is empty everywhere.
- The kill-geometry exists only as `kill_pattern` **string labels**: 33.6% `None`,
  10,833 distinct, but heavily concentrated in `a1_relation_*_violated` (parity/relation
  violations) + `d2_margin_*`. This is the same a1 monoculture, now visible in the kill
  channel.
- Techne's "proto-tensor" (the `signature_index`) is shape-keyed dedup classes with the
  verdict baked into the key — also not a vector geometry; not navigable on its own
  (provenance gap, quantified in the census).

So the honest status of "the kill-geometry is navigable signal" is: **the navigable
representation (KillEmbedding, CC-6) has not been computed**, and the one live signal
both chains lean on — the **0.725-bit MI** (Harmonia T0.3 GREEN) — has, to my knowledge,
**never been run against a null that perturbs the axis the MI varies on**
(`feedback_null_must_perturb_the_statistics_axis`). Even the crown-jewel number is
unverified against the right null.

**The gate (cheaper than M1, decisive for it):** compute `kill_vector` over a corpus
slice, then run the 4-criteria residue test against a feature-axis null. If the
kill-geometry is navigable, Techne's metabolization bet has fuel — build M1. If it nulls,
M1 would metabolize noise and Harmonia's progress-meter would measure movement through
noise — and we learned it for days of compute, not a quarter.

## 4. Claim 2 — the monoculture is in the VALUE FUNCTION; coordinate with a shared score

James's ask — "tune every component away from monocultured substrate; expand and score
the value of what's produced" — is a falsification-instrument problem, i.e. mine. Both
prior perspectives reach for **contraction** (Harmonia: one spine + retirement court;
Techne: one decisive experiment). James wants the opposite: keep the breadth, tune it,
expand it, and *score* it. The reason monoculture happened is not too many components —
it is that **every component scores itself on "survived MY gate"**: binary, local,
mutually incomparable. There is no shared, cross-component **value** metric, so
"diversity" is diversity of gate-flavors, not of value produced.

**Build the coordination substrate as a shared value-score, not a shared gate.**
Per live component, one graded number every component reports into:

```
value(output) = w1 * navigability      # does it change routing / localize / falsify / add rank
              + w2 * null_survival      # survives the RIGHT null (feature-axis, not row)
              + w3 * downstream_delta    # a consumer's held-out metric moves, ablation-positive
```

- This makes the monoculture **visible as a number** — components clustering in
  value-space — and gives a gradient to nudge them apart. It is sharper than Harmonia's
  objective-entropy dashboard (v2 §3a), which counts diversity of mechanism *labels*;
  this measures whether the diversity produces **value** or varied flavors of null.
- It lets James **expand safely**: a new generator earns its keep by occupying empty
  value-space, not by adding a gate flavor. Retire only what scores null **and**
  duplicates — never what is merely exploratory.
- It is the battery's natural evolution: from "did X survive a gate" (binary, per-
  component, monocultured) to "what is X worth" (graded, shared, comparable). It is also
  the operationalization of Harmonia's "closer than yesterday" — applied to **every
  component at once**, not a single external candidate. That is the walk-and-chew-gum
  Techne wants, with an instrument that serves all of it.

   value-score's `downstream_delta` term, not a separate apparatus.

   a repoint (Ergon), not a shim.
