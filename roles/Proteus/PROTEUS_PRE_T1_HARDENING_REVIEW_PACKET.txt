4. DEFECTS INTENTIONALLY NOT FIXED, AND WHY
--------------------------------------------------------------------

D3  `random` in proteus/v0_6/equilibrium.py -- NOT FIXED, DELIBERATELY.

    BLAST RADIUS, MEASURED NOT ASSUMED. stationary_empirical() is called from
    exactly two places, both in v0_6/run_full.py:
        (a) the empirical-occupancy cross-check   -- NON-ADJUDICATED
            (an external check by preregistration, never a gate)
        (b) the matched-trajectory arm            -- NON-ADJUDICATED
            (explicitly discounted in V0.6 section M as under-converged)
    NOT called by the numerical replay contract, which uses stationary_power,
    so the cross-runtime byte-identity result is untouched.
    NO ADJUDICATED V0.6 NUMBER DEPENDS ON THIS IMPORT.

    WHY NOT FIXED. Swapping to SplitMix64 changes those two published numbers.
    This pass is forbidden to alter published V0.6 results, and a repair that
    silently moves a published figure is worse than a documented defect.

    WHAT WAS DONE INSTEAD. Gate G1 pins the blast radius: `random` may appear
    only inside stationary_empirical(). If anyone later uses it elsewhere in
    that module, the published bounded-blast-radius statement would become
    false, and the suite fails instead.

    A FROZEN HISTORICAL RECORD LEFT ALONE. The V0.6 final packet also states
    "no registry exists". That document is a sealed scientific record, true at
    its date, and is NOT amended. Only the living consumer document was
    corrected. Flagged here so a reader is not surprised by the discrepancy.

7. ARCHAEOLOGY REQUIREMENTS
--------------------------------------------------------------------

Machine-readable at proteus/integration/ARCHAEOLOGY_REQUIREMENTS.json, schema
proteus.archaeology_requirements.v1. GENERATED FROM LIVE ARTIFACTS, not
transcribed, so it cannot drift from what it describes. Regenerate with
`python proteus/integration/run_archaeology_requirements.py`.

PRINCIPLE. An archaeologist starting from a single evidence id must reach a
specimen and prove it unaltered, without living memory, without Proteus
internals, and without trusting any write echo.

  IDENTITIES TO RECOVER (8)
    organism_id, entry_id, registry_id, lineage_id, generation_manifest_id,
    foundry_identity, population_seed, encounter_id -- each with the rule that
    reconstructs it and what it is recoverable from.

  HASHES THAT MUST REMAIN STABLE (10)
    grammar / runtime / affordance / registry_id / registry serialization /
    first specimen organism_id and entry_id / both published packet hashes.
    RULE: changing grammar, runtime or affordance hashes invalidates every
    specimen identity derived under them and requires a NEW registry version
    plus an explicit identity transition -- never a silent refresh.

  SOURCE-QUALIFICATION FIELDS THAT MUST PROPAGATE (9)
    deterministic_generation, semantic_quarantine, mutation_neutrality,
    mutation_current_source, operational_significance, permitted_use,
    prohibited_use, plain_statement, evidence.
    RULE: this block travels inside every registry. Dropping, flattening or
    summarising it downstream is a contract violation.

  DETERMINISM / QUARANTINE PROPERTIES THAT MUST STAY QUERYABLE (12)
    Each with the exact command that answers it -- manifest identity is
    file-independent; population rebuild is deterministic; replay excludes the
    nondeterministic path; the known random defect stays in its blast radius;
    no forbidden imports package-wide; protected surface has zero exemptions;
    audit freshness; semantic quarantine; no taxonomy in the registry;
    extrinsic writes cannot alter identity; no tracked generated artifacts;
    the consumer document does not deny the registry.
    NOTE RECORDED THERE EXPLICITLY: audit_identity covers proteus/foundry ONLY
    and does NOT cover proteus/integration, which is why the hygiene test
    exists.
