3. SPECIMEN IDENTITY CONTRACT
----------------------------------------------------------------------
Normative: proteus/contracts/SPECIMEN_AND_COMPOSITION_IDENTITY.md
Vectors:   proteus/compose/GOLDEN_VECTORS.json

  CANONICAL SERIALIZATION -- the whole rule, no other knowledge needed

    canonical_bytes(obj) =
      json.dumps(obj, sort_keys=True, separators=(",", ":"),
                 ensure_ascii=True).encode("utf-8")
    digest(obj)  = sha256(canonical_bytes(obj)).hexdigest()   # lower
    blob_hash    = "sha256:" + digest(manifest)

    keys sorted at every depth, no whitespace, non-ASCII escaped, UTF-8

  HASH ALGORITHM ............ sha256, lowercase hex, no prefix
  SCHEMA CONTRIBUTION ....... schema_version is INSIDE the hashed
                              manifest, so a schema bump changes the id
  REGISTRY CONTRIBUTION ..... NONE to organism_id. This is the gap.
                              See section 4.

  WHAT CHANGES CONTENT IDENTITY
    any genome word; any envelope field (n_regs, tape_words,
    code_writable, persist, tick_budget, out_cap); schema_version

  WHAT DOES NOT CHANGE CONTENT IDENTITY
    a segment label; anything written into `extrinsic`, phenotype
    included; line endings (ids hash memory, never a file); the
    affordance table (that is the defect, not a feature)

  WHAT PLACEMENT CHANGES
    artifact_id in a world. Harmonia already proved the separation is
    clean: same specimen, two worlds -> identical blob_hash, distinct
    artifact_id. That boundary is preserved untouched by this work.

  WHAT COMPOSITION CHANGES
    a new organism_id (new bytes) AND a new composition_id (which
    parts, in which order). Both are recorded; neither substitutes for
    the other, because concatenation is not injective on component
    boundaries.

  GOLDEN VECTORS: 8 vectors, 10 identities. Each ships the document,
  the exact byte string hashed, its length, and the digest. A consumer
  in any language reproduces them with sha256 and a canonical-JSON
  serialiser and never imports Proteus.
    verify: python -m proteus.compose.golden verify

  GATE (closes Proteus's side of I-CLIENT-GATE-UNENFORCED)
    proteus/integration/specimen_gate.py -- verify_specimen()
    separates and never collapses three questions:
      BYTES   do these bytes hash to the claimed id?
      SHAPE   are they a manifest the frozen runtime accepts, AND are
              they CANONICAL (non-canonical bytes rehash differently on
              the next hop and silently break content addressing)?
      MEANING were they produced under the runtime/table we replay
              against? Reported UNVERIFIED when the caller declares
              nothing -- never silently true.
    Refuses Harmonia's exact probe: corrupt bytes + plausible
    blob_hash -> False. Locked by 12 tests.

5. PRIMITIVE IDENTITY CONTRACT
----------------------------------------------------------------------

  A PRIMITIVE (segment) is a contiguous run of whole instructions.
  Purely STRUCTURAL. Nothing knows or asks what it computes. Directive
  section 5 permits exactly this and V0 takes it.

    segment_id = digest({schema_version, words})
    a label is NOT hashed: renaming a primitive must never move its id

  THE SIX OPERATIONAL REQUIREMENTS, and how each is met

    reconstruct it ......... decompose() re-hashes the composed bytes
                             and REFUSES on mismatch ..... 200/200
    insert it .............. compose() ................... 200/200
    remove it .............. ablate(), position-preserving  200/200
    hold it fixed .......... other components asserted
                             byte-identical per report .... 200/200
    mutate something else .. ranges declared and disjoint . asserted
    identify it inside a
      composition .......... components[].segment_id +
                             offset_instructions ......... round-trip

  NOT REQUIRED and NOT SUPPLIED: semantic interpretation. A segment is
  not claimed to do anything.

6. COMPOSITION IDENTITY CONTRACT
----------------------------------------------------------------------

  V0 admits exactly ONE glue: "concat.v0". Components laid end to end,
  no separator, executed from ip=0, ip advancing by 4, wrapping mod
  tape_words. This is the only join that needs NO new runtime
  semantics, which is the entire reason it is the only one built.

  A composition document answers every required question:

    which exact A ......... components[i].segment_id
    which exact B ......... components[j].segment_id
    ordering / topology ... offset_instructions (total order)
    glue .................. "concat.v0"
    resulting player bytes  manifest.genome; organism_id=digest(manifest)
    deterministic? ........ YES; compose() is a pure function of
                            (components, envelope, glue)
    own content identity? . YES, composition_id, distinct from
                            organism_id
    reconstructable? ...... YES, decompose(), which refuses on mismatch

  ORDER MATTERS: A+B != B+A, shipped as a golden vector
  (organism_id_AB != organism_id_BA).

  PREPARED FOR, NOT IMPLEMENTED
    A+B+C .......................... works today (ordered list, any n)
    A->B / B->A as CONTROL FLOW .... NOT implemented, needs a new glue
    conditional activation ......... NOT implemented, needs a new glue
    world-conditioned activation ... NOT implemented, needs a new glue

  No universal graph language was built. A+B did not prove one
  necessary, and the directive says not to until it does.

7. EXACT ABLATION CONTRACT
----------------------------------------------------------------------
Source: proteus/v0_7/RESULT_ABLATION_EXACTNESS.json, RESULT_AB_READINESS.json

  ABLATION IS NOP-SUBSTITUTION, NEVER DELETION.

  Why: deleting a component's words shifts every later component's tape
  address. LD/ST address the tape by register contents and jumps are
  signed instruction offsets, so a shift silently changes what every
  surviving instruction reads and where every jump lands. The ablated
  system would then differ in the removed component AND in the
  addresses of everything after it -- exactly the confound forbidden.
  Substitution preserves length, offsets, envelope, and every other
  component's words byte for byte.

  WHAT IS PROVEN PER ABLATION (structural, exact, unconditional)
    original A+B identity known .............. composition_id + organism_id
    ablated composition identity known ....... both recomputed
    intended component removed ............... words_changed ==
                                               instructions_in_component
    unrelated components unchanged ........... byte-identical, asserted
    change attributable to the operation ..... changes_outside_declared
                                               _range == 0, and
                                               changes_to_operand_words == 0
    size/budget consequences measurable ...... length preserved;
                                               meter vector reported

  THE RESIDUAL CONFOUND, AND THE GATE THAT CATCHES IT

  Substitution is still not perfectly inert: the genome is copied into
  the tape, so an opcode word is ALSO a datum LD can read. Since every
  word w with w mod 25 == 0 decodes to NOP, ablating to 0, 25 and 50
  are three operations that are INSTRUCTION-IDENTICAL and
  DATA-DISTINCT. Disagreement means the ablation moved a data channel.

    class knockout over the registry ....... 343 pairs tested
      identical under all three aliases .... 342
      CONFOUNDED ........................... 1  (0.29%, halt_yield)
    constructed A+B pairs .................. 200
      certified EXACT ...................... 200/200
      decompose exact ...................... 200/200

  THREE VERDICTS, never a bare boolean:
    EXACT / CONFOUNDED_BY_DATA_CHANNEL / STRUCTURALLY_INEXACT

  HONEST LIMIT: the certificate is ENSEMBLE-RELATIVE and is a LOWER
  BOUND on confounding. It detects a data dependence only if that
  dependence reaches the transcript on the probes actually run.

  THE GATE IS PROVEN ABLE TO FAIL. test_data_channel_confound_is_
  detected_when_present builds a reader that LDs its neighbour's opcode
  word; it reports CONFOUNDED_BY_DATA_CHANNEL with 3 distinct
  transcripts while remaining structurally clean.

8. R ~= 0.000001 RETENTION V0
----------------------------------------------------------------------
Normative: proteus/contracts/RETENTION_AND_MEASUREMENT_V0.md

  THE ONE IDEA: EVICTION IS NOT DELETION.

    ACTIVE RESERVOIR   bounded, R_MAX. What compositions are drawn from.
    ARCHIVE            unbounded, append-only, ids + records only.
                       A segment NEVER leaves it and stays permanently
                       resolvable by segment_id.

  This is what defeats both failure modes at once. Premature pruning is
  impossible because nothing is deleted. The noise museum is avoided
  because the ACTIVE set is bounded, and the archive costs ~100 bytes
  of record per evaluation.

  RECORDS (immutable, append-only; a later evaluation appends)
    EvaluationRecord { segment_id, context_id, observable, activation,
                       marginal_effect, ablation_verdict,
                       recorded_at, recorded_by }
    context_id = digest{composition_id, envelope, ensemble_identity,
                        world_id|null, runtime_hash, affordance_hash}

  context_id is MANDATORY and is why "no effect" can never be stored as
  a bare fact. A record always reads "no effect IN CONTEXT C".

  Composition-result records: same shape, keyed on composition_id.
  Negative controls: retained under a separate quota the eviction
  policy may not touch. A segment that showed no effect is EVIDENCE.

  DETERMINISTIC EVICTION, when |active| > R_MAX, ties by segment_id:
    1. contexts_evaluated                       DESC
    2. distinct contexts with effect == CHANGED  ASC
    3. segment_id                                ASC

  Note the direction of rule 1: it evicts the MOST-EXAMINED and
  least-productive, not the untested -- because that is the segment the
  archive already knows most about, and re-admitting it costs one
  lookup.

  HARD GUARDS
    G-COVERAGE     contexts_evaluated < K_MIN -> never evictable.
                   Untested is not useless. V0 K_MIN = 3 contexts.
    G-CONTROL      negative-control quota is exempt.
    G-NEVER-DELETE eviction writes an EVICTED record and archives.
                   There is no delete path in V0.

  V0 PARAMETERS (round numbers, sufficient for the first experiment,
  deliberately NOT tuned): R_MAX 4096, K_MIN 3, control quota 256.

  NOT SOLVED, DELIBERATELY: open-ended evolution; any value model; any
  rule letting a SCORE drive retention. There is no fitness scalar in
  this contract and adding one is a contract change.

9. RAW MEASUREMENT SURFACE  ***CONTAINS THE REAL BLOCKER***
----------------------------------------------------------------------
Source: proteus/v0_7/RESULT_TRANSCRIPT_DEGENERACY.json

  THREE LEVELS, KEPT SEPARATE
    RAW OBSERVABLE   exact, mechanical, no interpretation  <- Proteus
    DERIVED METRIC   a function of raw observables         <- Harmonia
    SCIENTIFIC INTERPRETATION                              <- adjudication

  THE FINDING. The probe transcript -- the observable the V0 signatures
  are built on -- is DEGENERATE at this scale:

    population                     classes  largest   emitting >=1 value
    2-instruction segment players     3      87.5%          4 / 56
    full committed specimens         12      60.9%         10 / 64

  52 of 56 segment players emit NOTHING; their transcript is the
  per-tick status word and nothing else. THIS is why A+B differed from
  both parents in 0/200 pairs. That is a fact about the INSTRUMENT, not
  about composition.

  The internal resource vector is NOT degenerate on the same population:

    observable            distinct classes (n=56)   largest share
    probe transcript                3                  87.5%
    ops_by_category                37                  10.7%
    full meter vector              39                  10.7%

  ~13x richer. THEREFORE: the first emergence measurement must read the
  METER VECTOR, not the transcript alone. A transcript-only experiment
  at this scale would be measuring a near-constant.

  WHAT PROTEUS EXPOSES (all exact, all per-encounter, already built)
    ops; ops_by_category; branches_taken; code_region_writes;
    in_reads; out_writes; out_dropped; rnd_draws; ticks;
    budget_exhausted_ticks; footprint_words; persistent_state_words;
    wall_s / cpu_s (NEVER an identity input, not deterministic);
    gpu = literal "unavailable", never fabricated;
    proxy_search_expenditure = branches_taken     (DECLARED PROXY)
    proxy_adaptation_expenditure = code_region_writes (DECLARED PROXY)
    activation_evidence(); ablation_report(); transcript + its hash

  ACTIVATION, AND ITS ONE DECLARED BLIND SPOT
    No runtime instrumentation was added -- instrumenting vm.py would
    change runtime_hash and therefore every frozen specimen's
    interpretation identity. Activation is a DIFFERENTIAL: if a
    component never executes, ablating it to NOP cannot change what the
    runtime does, so ops_by_category is identical. ANY difference
    proves execution.
    Exception, reported not guessed: a component already entirely
    halt_yield class -> INDETERMINATE_COMPONENT_IS_ALREADY_NOP_CLASS.
    Verified both directions (behind-a-HALT -> NOT_ACTIVATED).

  NOT AVAILABLE (genuine NOs, see section 10)
    per-instruction execution counts localised to a component
    composition activation ORDER
    internal state transitions per tick

  THE DISTINCTION THAT MUST SURVIVE CONTACT
    ACTIVATED means instructions executed. It does NOT mean the
    component mattered. Measured: 200/200 ACTIVATED, but only 30/200
    changed the transcript -- 170/200 (85%) ACTIVATED WITH NO MARGINAL
    EFFECT. SUPPORT and INCREMENTALITY are different questions and the
    surface reports them separately, by construction.

  WHAT THE ARENA DOES NOT NEED

    CONSTRUCTOR: it emits ordinary manifests the frozen runtime

  WHAT THE ARENA MUST NOT DO
    Read or write phenotype. Filter for "interesting" specimens.
    Harmonia's first draw was a silent budget-burner recorded as a

16. HANDOFF TO HARMONIA
----------------------------------------------------------------------

  WHAT A PLAYER NOW MEANS
    A manifest of 8 fields whose canonical bytes hash to organism_id,
    interpreted by a frozen tape machine. Median 622 bytes, median 11
    instructions. It is fully specified by the TRIPLE
    (organism_id, runtime_hash, affordance_hash) -- and by organism_id
    alone it is NOT, because 94.87% of instructions re-decode under a
    one-opcode table change that leaves organism_id identical.
    Your existing boundary properties are preserved untouched: content
    identity vs placement identity stays clean, blob_hash is still
    "sha256:"+organism_id, and a second unknown organism still crosses
    generically with no bespoke editing.

  WHAT A PRIMITIVE NOW MEANS
    A contiguous run of whole instructions with its own content hash.
    STRUCTURAL ONLY. It can be reconstructed, inserted, removed, held
    fixed, mutated around, and located inside a composition. It is not
    claimed to compute anything.

  WHAT A COMPOSITION NOW MEANS
    An ordered concatenation under glue "concat.v0", with its own
    composition_id separate from the resulting organism_id, fully
    reconstructable, order-sensitive (A+B != B+A). A+B+C works. Control
    flow, conditional and world-conditioned activation do not exist and
    would each need a new declared glue.

  WHAT CAN BE ABLATED EXACTLY
    Any named component, by NOP-substitution, position-preserving.
    200/200 certified EXACT on constructed pairs; 342/343 on class
    knockout over the registry. The certificate is ensemble-relative
    and a LOWER BOUND -- a CONFOUNDED verdict is a refusal, not a
    warning. Deletion-based ablation is not offered and should not be
    built: it moves every later component's tape address.

  WHAT MUST STILL NOT BE CALLED "REASONING"
    Everything above. Specifically:
      - a structural primitive is not a reasoning primitive
      - ACTIVATED means instructions executed, nothing more; 85% of
        activations had no marginal transcript effect at all
      - a transcript difference is an inequality on a NOISE ensemble
        with no task in it; it is not a capability
      - and "A+B adds nothing" is NOT supported by the 0/200 result.
        That number is an instrument reading. Fix the observable before
        anyone reads it as a finding about composition.

  THE ONE THING TO DECIDE BEFORE RUNNING
    Declare the meter vector, not the probe transcript, as the primary
    observable, and publish its chance floor first. The transcript
    resolves 3 classes at 87.5% concentration; the meter resolves 37 at
    10.7%. Every other piece of the experimental object is exact and
    waiting.
