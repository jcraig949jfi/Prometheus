FIVE ARTIFACTS

1. generate_sfe_contract.py
   A GENERATOR, not a document. Re-run it after ANY SFE deploy and diff the
   output. It derives everything from the live engine, so the contract cannot
   drift the way a hand-written route list has already drifted twice here.
   Session scoping is DERIVED by probing every route with a malformed session
   key against a scratch engine of the identical build. It refuses to run if
   the probe engine's build hash differs from the live one.

2. sfe_contract.json
   All 50 routes with path params, required body fields, required query params,
   and whether each needs a session key. Auth rules, the session error taxonomy
   (421/428/422/401/409/403), and every vocabulary you will need: outcome,
   unit_of_analysis, family kinds and roles, claim statuses, the six
   replication booleans, budget enforcement values.

3. sfe_traps.json
   TEN behaviours that will cost you time. Every single one was a real defect
   in one of MY OWN instruments before it was written down. This is the
   cheapest file in the package. Read it before you write a client.

4. epistemic_bounds.json
   What Archaeon MAY and MAY NOT infer. Non-negotiable; see below.

5. conformance_check.py
   The gate. Run it BEFORE EVERY BATCH.
       exit 0  conformant, proceed
       exit 1  DRIFT -- STOP THE LOOP
       exit 2  unreachable
   It checks reachability, build hash, ledger identity, schema, the live route
   set against the contract's, a session-scoping sample, and profile/
   enforcement. Verified in both directions: CONFORMANT against live M1, and it
   correctly reports DRIFT against a scratch engine of the IDENTICAL BUILD on
   ledger identity and profile while passing the build hash. Same code,
   different engine is exactly the confusion session affinity exists to prevent.

   NOTE FOR VIVARIUM: I have twice seen a bare request to SFE return empty and
   succeed on retry. Retry a transient before treating exit 2 as a stop
   condition, or your loop will halt on network noise. Exit 1 is different --
   never retry past drift.

THINGS YOU WILL GET WRONG IF YOU SKIP sfe_traps.json

  * spec_hash is NOT in the POST /experiments response. It is on the READ path
    only: GET /v2/worlds/{wid}/experiments/{eid}. Reading it from the POST
    gives None for every experiment and N distinct specs collapse to one.
  * POST /v2/work/claim returns the item NESTED under a "work" key, not flat.
    Reading it flat scores zero claim winners and looks like a broken queue.
  * FORKED CHILDREN ARE CREATED, NOT RUNNING. The experiment path enforces
    RUNNING, so nothing enqueues until you POST .../start on each child.
  * Every list and read is OWNER-SCOPED. A fresh client sees zero worlds. There
    is no cross-client view through the REST surface at any endpoint.
  * Content-Type: application/json is REQUIRED on every POST or the body is
    never parsed.
  * outcome is FALSIFIED | SURVIVED | INCONCLUSIVE. There is no CONFIRMED.
  * Register the prediction BEFORE committing the experiment or it is not
    prospective, permanently.
  * Pass work_id on the observation or it is CLIENT_ASSERTED rather than
    ENGINE_WORK_RESULT.
  * STANDARD base64 only for data_b64. URL-safe is 422 now and was SILENTLY
    TRUNCATED before 2026-09-04.
  * budget.enforcement defaults to "measured", WHICH ENFORCES NOTHING.

  AND THE v6 CHANGE THAT WILL BITE FIRST: families and claims are now
  SESSION-SCOPED. It is 44 scoped and 6 exempt, against 33 and 5 under v5.
  Anything touching /v2/families or /v2/claims needs a session key. The exempt
  six are POST /v2/clients, POST /v2/sessions, POST /v2/sessions/{sid}/close,
  POST /v2/topology-groups, POST /v2/audit/verify-anchor, GET /v2/version.

VIVARIUM: THE OBLIGATIONS THAT ARE YOURS ALONE

I inventoried all twelve v6 science checks and asked who supplies the boundary
each one ranges over. Nine are the claimant's, one is the engine's, and TWO ARE
THE EXECUTOR'S. Those two are yours and nobody else can satisfy them:

    NO_EXECUTION_ATTESTATION
    CONFIG_DIVERGENCE

On POST /v2/work/{id}/complete send:

    "attestation": {
       "executed_config":            <the config you ACTUALLY ran>,
       "entry_state_hash":           "sha256:...",
       "player_identity_hash":       "sha256:...",
       "measurement_identity_hash":  "sha256:..." }

SEND THE CONFIG, NOT THE HASH. I demonstrated that echoing the sealed spec_hash
back as executed_config_hash passes with NO findings -- an executor that ran
nothing is indistinguishable from a faithful one on that path. If you send the
config, it is canonicalised the same way spec_hash was, so a faithful executor
matches by construction and a divergence is caught mechanically.

entry_state_hash is a claim against a claim: the engine never sees your state.
Send it anyway, and know its limit -- a CONVERGED stateful player enters every
world from the same fixed point, so identical entry hashes prove nothing on
their own. They are only meaningful against a DECLARED reset discipline.

THE EPISTEMIC BOUNDARY -- NON-NEGOTIABLE

  YOU MAY
    infer prospective vulnerability of a claim from SUBMITTED fossils
    derive a candidate comparison universe from spec_hash and report the
      DIFFERENCE against a declared source_set or family
    report that a check was silent

  YOU MAY NOT
    infer that the absence of a selection fossil means selection did not occur
    treat the silence of any v6 check as evidence of soundness
    treat a derived candidate universe as complete
    report "no selection signal found" where the true statement is "this region
      is archaeologically unobservable"

  WHY. I measured it. PEW fossilizes only selection whose candidate EXECUTIONS
  were submitted to the engine of record. Of eight realistic selection
  mechanisms, seven leave a record structurally IDENTICAL to an honest single
  shot. Retrying six times inside the engine leaves 6 worlds and 54 events;
  the same six rehearsed on a private engine and submitted once leaves 1 world
  and 9 events, which is exactly what an honest single shot leaves. The class
  of invisible selection is not a list, it is a closure: any mechanism becomes
  invisible by being performed elsewhere.

  Separately, all TWELVE v6 science checks can be silenced by a minimal
  adversarial record. Silence is not evidence. Report findings; never report
  their absence as reassurance.
