## Population — say it first

`forge/verdicts/*_verdict.json`, the **rebuilt** T2/T3 forge (2026-04-03 → 2026-04-12),
joined to tool sources in `forge/candidates/`.

- 203 verdict files; **198 carry an `ablation` block**; **2,103 primitive ablations**, 3 errors.
- **Not** `forge/v2/hephaestus_t2/forge/` — that is the superseded pre-rebuild population, and
  `CONTROLS.md` §2 was wrong to call it the live tree (see G0, Consequence 1).

The ablation protocol is the forge's own, in `forge/tester.py:122`: stub each imported primitive
to `return None`, re-run the battery at `seed=42, n_per_category=2`, record
`delta = baseline − ablated`. Compute is matched by construction — same battery, same seed,
same tool, one primitive removed. This satisfies G2 within the tool; it is *not* a
library-vs-no-library comparison and is not offered as one.

## Result — the raw number, then the honest one

**Raw, all 2,103 ablations:**

- delta exactly 0.000: **1,887 (89.73%)**
- flagged `load_bearing` (|delta| ≥ 0.20, the pre-committed bar): **125 (5.94%)**
- delta > 0 (removal hurt the tool — the primitive helped): 192 (9.13%)
- delta < 0 (removal *helped* the tool — the primitive hurt): 24 (1.14%)
- among nonzero deltas: median |delta| 0.2500, p90 0.3750, max 0.5000

A zero delta has two causes that must not be pooled, so the raw 89.73% is not yet a finding.

**Decomposition (n = 2,093 classifiable):**

- **214 (10.22%)** — delta ≠ 0. The primitive changed at least one answer.
- **543 (25.94%)** — **dead import.** Imported and never called anywhere in the tool. Stubbing
  it cannot do anything. This is an R2 failure, not an R4 one.
- **0 (0.00%)** — unstubbable. Every primitive is called bare-name, so
  `tester.py:_stub_function`'s import-shadowing stub binds in every case.
- **1,336 (63.83%)** — **decoration.** Called by bare name, successfully stubbed to `return None`,
  and the tool's answers did not change.

**Confound direction, stated before the number was read:** a stub that fails to bind can only
manufacture a *false zero*, never a false nonzero — so any stubbing failure would inflate the
decoration count. The unstubbable category measures exactly that, and it is **empty**. There is
nothing to subtract.

**The conservative reading — restricted to rows where the ablation was a valid experiment
(primitive actually called, stub actually binds), n = 1,550:**

> **86.19% of called primitives are decoration. 13.81% change any answer at all.**

And per tool: **121 of 198 tools (61.1%) have *every single* primitive delta at exactly 0.000.**
Total decoration, at the tool level, in the majority of the rebuilt population.

## G1 verdict: **FIRES.** The rebuild did not fix the failure it was built to fix.

`forge/ARCHITECTURE_T2_T3.md` §1 lists failure mode 2 as *"Winning tools used 0% of their own
primitive libraries — primitives were decoration,"* and §1 closes: *"This rebuild makes each
failure mode structurally impossible through the Five Iron Laws."*

Measured on the rebuild's own output: decoration moved from 0% usage to **13.8% of called
primitives having any effect**, and **5.94% clearing the pre-committed impact bar**. Better than
zero. Nowhere near a consumer. The failure mode was not made structurally impossible; it was
made 6% less total.

ROLE.md's G1 pre-commitment was *"usage < 10% means the admission criterion is the problem, not the
primitives."* At the rung the gate was re-specified onto — R4 — the load-bearing rate is **5.94%**
of all ablations. **Under 10%. G1 fires as written.** The admission criterion is the problem.

R2 is now shown to be worthless as a proxy on this population, exactly as `CONTROLS.md` §2
predicted it would be: the 82% static call rate and the 13.8% effect rate are the same tools.
Quoting the 82% as primitive usage would have been a six-fold overstatement.

## The sharper finding: the anti-decoration gate cannot fire on decoration

This is worth more than the percentage, because it explains it.

`forge/tester.py:410–420` is the entire ablation gate:

```python
deltas = [abs(v["delta"]) for v in ablation.values() if v.get("delta") is not None]
total_delta = sum(deltas) if deltas else 1
ablation_ok = True
for name, result in ablation.items():
    if result.get("delta") is not None:
        budget_share = abs(result["delta"]) / total_delta if total_delta > 0 else 0
        if budget_share > thresholds["max_ablation_budget_share"]:   # 0.60
            ablation_ok = False
```

Three defects, in increasing severity:

1. **`min_ablation_impact` (0.20) is never gated on.** It is computed into the `load_bearing`
   flag inside `run_ablation`, written to the verdict file, and then never read by the verdict
   logic. The one pre-committed threshold that measures *whether a primitive does anything*
   is decorative itself.

2. **The gate's predicate has the wrong sign.** It fails a tool when **one** primitive carries
   more than 60% of the ablation budget — a contribution-*concentration* check. A tool where
   every primitive does nothing has no concentration and sails through.

3. **It is unreachable in the direction it was built for.** For a fully decorative tool,
   every `delta` is 0, so `total_delta = 0`, so every `budget_share` evaluates to 0, so
   `ablation_ok` stays `True`. **All 121 fully-decorative tools pass the ablation gate by
   construction.** This is `feedback_gate_must_be_shown_reachable` in its strongest form — not
   a threshold set beyond the attainable range, but a predicate that is *anti-correlated with
   its own stated purpose.*

Measured consequence: the gate would flip `ablation_ok = False` for **26 of 198 tools (13.1%)** —
all on the concentration branch — and **`FAIL_ABLATION` appears zero times in
`forge/verdicts/`**, because reaching that branch requires `passes_battery and passes_seed`
first, and all 26 had already failed the battery.

So the forge shipped a pre-committed ablation gate in April 2026, ran it on 198 tools, produced
2,103 measurements that unambiguously show 86% decoration, and the gate returned PASS on every
one of them. **The measurement was right and the decision procedure downstream of it was
inverted.** Nobody read the numbers the gate itself had already written.

## What this does and does not license

- **Does not** license "the forge is broken, retire it." The forge's *measurement* apparatus is
  sound and produced the dataset that convicts it. That is unusual and valuable.
- **Does** license recommendation 1 to James (freeze tier-ratchet admission): T3 mints primitives
  from a T2 pool whose load-bearing rate is 5.94% and whose gate cannot detect that.
- **Does** sharpen the fix, and the fix is one line of predicate, not a redesign: gate on
  `min_ablation_impact` — *every admitted primitive must move at least one answer* — which is
  data the forge already computes and already stores.
- **Does not** touch the question of whether a *better* primitive would be consumed. Decoration
  here is a property of the generated tools, not proof that the primitives are useless. That is
  what STEP 3's comparison arms test.

**Not executed, per the standing no-touch constraint.** This is a recommendation to James, not
a work order to Hephaestus.
