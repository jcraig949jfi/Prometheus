4. RESULTS
--------------------------------------------------------------------------------
  4.1  Closure test (48 rows; 16 points)

       arm  operators                       found (depth)                  evals
       ---  ------------------------------  -----------------------------  -----
       A0   frozen primitives, no routing   impossible by arity: a single      0
                                            f(d,s) yields one column; the
                                            three quantifier columns differ
                                            at (d,s)=(0,0): T, T, F
       A1   frozen primitives + routing     existential      = s
         (1)  156
                                            negative_univ.   = pigeonhole_
                                                               check(1, s)   (1)
                                            universal        = coin_flip_
                                                               independence
                                                               (s, d)        (1)
       B    generic boolean language        eq(d,s); eq(s,0); s            (1)
         152
       C    v3 kernel (10 lines)            48 / 48 correct                 --

       Reading of A1's universal solution: comb(s, d) / 2^s is non-zero exactly
       when s >= d, and s <= d always, so its truthiness equals "s == d" on the
       table, and it returns 1.0 at (0, 0). This is a truthiness COINCIDENCE,
         not
       a mechanism -- but it is inside the closure G(C) of the frozen set, which
       is the question asked. The mechanism form, pigeonhole_check(s,
       all_but_n(d, 1)) i.e. s >= d, is depth 2 and also inside G(C).

       VERDICT (by the rule fixed in advance): A1 synthesises the table =>
       the kernel is a LEVEL-1 COMPOSITION of frozen primitives under per-
       quantifier routing. MINT-0001 was a routing / representation problem,
       not a missing operator. What was actually missing: (a) routing on a
       quantifier slot; (b) a semantic state that carries domain_size and
       satisfier_count at all. The "fourth kernel rule" suggested by adversarial
       item D1 ("there are no chipped marbles" with a non-empty domain) is an
       ADAPTER mapping (satisfier_count := 0), not a kernel rule.

6. WHAT THIS DID NOT ESTABLISH
--------------------------------------------------------------------------------
  - That the frozen set can compute the kernel FROM TEXT. Arm A was given
    semantic state (d, s, q). Nothing in the frozen set produces that state
    from natural language; that is the representation problem now routed out.
  - That v3's adapter generalizes. On dev v2 it abstains on the entire
    PREDICATE_EXTENSION_EMPTY kind and on 16 of 20 adversarial phrasings. Its
    conditional correctness stays 1.000: it does not guess.
  - That the A1 depth-1 "universal" solution is a mechanism. It is a truthiness
    coincidence of a probability primitive. The classification rests on the
    closure question ("is the function in G(C)?"), which it answers; it does not
    rest on that expression being sensible.
  - Anything about Apollo's post-E9 evaluator, which is still unnamed; nothing
    here was run inside Apollo's blackboard.
  - Anything measured on an independent held-out. Charon's six blind items were
    not read by any code in hephaestus/.
  - That MINT-0004 is a composition; that is a prior, and the semantic-injection
    question has not yet been asked of it by execution.

9. QUESTIONS FOR THE EXTERNAL REVIEWER
--------------------------------------------------------------------------------
  Q1  Is "inside G(C) under truthiness coercion" the right criterion for
      "already expressible"? A1's universal solution is a numerical accident of
      a probability primitive. Would you require the mechanism form (depth 2,
      also found in G(C)) before reclassifying, or is membership enough?
  Q2  Arm A was granted per-quantifier routing on the grounds that Apollo's
      guarded operators provide it. Is that a fair grant, or does it smuggle in
      the very "if-then-else" that Arm B has and Arm A should not?
  Q3  The reclassification moves the whole wall to "representation". What would
      falsify THAT -- i.e. what observation would show a reasoning kernel is
      still missing once semantic state is supplied?
  Q4  Dev set v2 was authored by the same seat that authored the candidate. It
      failed the candidate (0.9125). Does that failure make the harness more
      credible, or is it still inadmissible as evidence about the candidate?
  Q5  The (coverage, conditional correctness) split reports v3 as (0.9125,
      1.000) on dev v2 and (0.20, 1.000) on adversarial phrasings. What should
      the queue DO with a candidate of that shape -- keep widening the adapter
      with cheap models, or stop and wait for semantic-state worlds?
  Q6  Mechanism coverage now depends on candidates declaring their own
      ABLATIONS. A dishonest or lazy candidate declares none and gets
      PASS_DEV_UNVERIFIED_COVERAGE. Should unverified coverage block state
      change entirely?
  Q7  What in this block should we STOP doing? Candidates: the adapter-widening
      mode (it improves a parser for a wall no longer classed as reasoning); the
      four-hourly cheap-model attempts (nothing is in APPRENTICE-TESTING);
      maintaining the historical-walls replay before any second wall exists.
  Q8  Is one wall, fully anatomised and reclassified, a sufficient first test of
      the Forge Queue process, or should a second wall of a different shape be
      run through triage before drawing any process conclusion?
