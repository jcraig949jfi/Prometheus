TEMPLATE_ID: ai_scientist_training.v0
FIELD: AI Scientist systems
KIND: train_llm_idea_v0
QUESTION: Can a language model take a working machine-learning training script,
  write a modification to it, and have that modification actually run and reach
  a target validation loss?
MECHANISM: Start from a small working codebase and its known baseline numbers.
  A language model brainstorms a research idea against that codebase, checks
  the idea against a literature search for prior art, then a coding agent edits
  the source files to implement it. The edited code is executed under a fixed
  compute budget; if it crashes, the error text is fed back and the agent gets
  a bounded number of repair attempts. Numbers that survive are collected into
  plots and a write-up, which a second language model then scores. The loop is
  generate, edit, execute, observe, repair, report.
CANDIDATE: The model-authored code diff, and behind it the idea it encodes.
  What varies is which idea is attempted; what is judged is whether the diff
  executes at all and what validation loss the modified script reaches.
WORLD: A concrete template repository plus its dataset, its baseline run, and a
  wall-clock or GPU budget. The world supplies executability, a loss curve, and
  a reference baseline to be beaten.
WHAT_CHANGES: idea_id, which selects one of three template codebases, and
  training_steps, which sets the compute budget per attempt. The parameter
  values for training_steps were destroyed in ingest and are unknown.
MEASURED: Two things in the real method, which is already a problem for this
  bench: a boolean execution outcome and a continuous validation loss. The
  literature also reports a reviewer score on an ordinal scale.
INFORMATIVE_FAILURE: Highly informative. A failed run leaves the exact diff and
  the exact traceback, which categorize into a real error taxonomy: import and
  API misuse, shape and dtype errors, silent no-ops where the diff changed
  nothing on the execution path, and runs that finish but are worse than
  baseline. That last class is the valuable one, because it separates
  cannot-implement from implemented-and-useless. A corpus of failing diffs is a
  reusable artifact even if not one idea ever beats baseline.
SOURCE_CHECK: VERIFIED. The AI Scientist, Lu, Lu, Lange, Foerster, Clune and Ha,
  2024, Sakana AI. The three named idea_id choices match the paper's own
  template set: a nanoGPT language-model template, a grokking template, and a
  2D diffusion template. Confirmed from established knowledge, not re-fetched
  this session.
SHARED_MECHANISM: generate_and_execute_program
ROUTES: R-BACKEND, R-EXECUTOR, R-SUBSTRATE
BLOCKER: R-BACKEND, the missing thing is an execution capability, namely a
  sandboxed subprocess with a model API and accelerator access that the engine
  calls and whose diff, stdout and metrics it fossilizes; nothing about bench
  internals has to change for this; R-EXECUTOR, an adjudication capability is
  missing, because the honest outcome is a conjunction of executed and
  loss_at_or_below_target, and the outcome rule is one scalar comparison on one
  field, so any adapter must collapse the pair into a single field, for example
  validation loss with a sentinel of positive infinity on crash, and that
  collapse is a design decision that must be stated in the spec; R-SUBSTRATE, a
  control-flow capability is missing, since the repair loop feeds the executor's
  own error output back into its next input, which is output-to-input chaining,
  and no sealed spec can do that.
FAITHFUL: A faithful implementation needs a real repository, a real dataset, a
  model endpoint, an isolated writable checkout per attempt, and a bounded
  repair loop with the traceback as input. It must fossilize the diff, the
  environment lockfile and the full log alongside the metric, or the run is not
  reproducible. It also needs a contamination control, because all three named
  templates are public and a model may have memorized both the code and the
  known good modifications to it.
REDUCTION: A reduction exists but it is a null-world instrument check, not a
  capability test, and it must be labelled as such. Freeze one world seed and
  one length, say length 64 as a NEW DESIGN CHOICE. Tell a language model the
  exact scoring rule, including that the target is derived by hashing the seed
  together with the length, and ask it for one bitstring. Seal that bitstring as
  the bits payload of an evaluate_bitstring spec. Run a matched spec with a
  uniformly random bitstring of the same length on the same seed. Repeat across
  many seeds using linear_index repeats, and across several lengths using
  separate specs. WHAT IT PRESERVES: the outer discipline of the AI Scientist
  loop that Prometheus actually cares about, which is propose, seal, execute,
  score, fossilize, with the proposal committed before the target can be seen;
  and it supplies the one control the real system lacks, because a hash-derived
  target cannot appear in any training corpus, so the null is exactly a
  fair-coin match rate and contamination is impossible by construction. WHAT IT
  LOSES: everything that makes the method a method, namely code, compilation,
  training dynamics, the repair loop and the reviewer. It also loses the fact
  that real machine-learning landscapes have exploitable structure while a hash
  target has none, so a model that is genuinely good at ideas cannot show it
  here. WHICH CLAIM: only a negative one, that model-authored sealed candidates
  score at chance on an unmemorizable target. If they do not, the producer
  pipeline is leaking the target, and the leak is found before an expensive
  backend is built on top of it. Worth running first, and honestly all this
  reduction can support.

TEMPLATE_ID: artificial_curiosity.v0
FIELD: Artificial Curiosity
KIND: model_building_controller.v0
QUESTION: If an agent is rewarded for surprising itself, does it seek out the
  parts of its world it does not yet understand, and does it lose interest once
  it has learned them?
MECHANISM: Two networks share a world. A model network watches the current state
  and the action taken and tries to predict the next state; it is trained to
  reduce its own prediction error. A controller network chooses actions and is
  rewarded by exactly that prediction error, so it is trained to increase it.
  The two are in direct opposition. The consequence is a moving target: a region
  that is initially surprising pulls the controller toward it, the model learns
  that region, the error falls, and the controller leaves. That departure is
  boredom, and it falls out of the arithmetic rather than being programmed. The
  known failure is a region whose unpredictability is irreducible, such as pure
  noise, where the model can never reduce error and the controller never leaves.
CANDIDATE: The controller, judged by where in the world it spends its time and
  whether that allocation tracks the model's residual error.
WORLD: An environment with observations, an action interface, and temporal
  structure, so that a next state exists to be predicted. The environment
  supplies both learnable regularity and, in the interesting version, at least
  one region of irreducible noise.
WHAT_CHANGES: hidden_units, which sets model capacity and therefore what counts
  as learnable, and delayed_reward_steps, which sets how far ahead the
  prediction reaches. Both parameter value sets were destroyed in ingest.
MEASURED: Prediction error over time, on a continuous scale, and the
  controller's occupancy over regions, as a distribution. The claim lives in the
  coupling between the two, not in either one alone.
INFORMATIVE_FAILURE: Useful. If the controller parks permanently in the noisy
  region, that is the noisy-television result and it is a positive finding about
  the drive rather than a null. If prediction error falls to zero everywhere
  with no change in occupancy, the environment had no differential structure to
  find, which indicts the world and not the agent. The one failure that leaves
  nothing behind is a controller that never learns at all, because then
  occupancy says nothing about the drive.
SOURCE_CHECK: VERIFIED. Schmidhuber, A possibility for implementing curiosity and
  boredom in model-building neural controllers, in the 1991 Simulation of
  Adaptive Behavior proceedings. The dual-network arrangement, the reward on the
  model's prediction error, and the explicit treatment of boredom are all in
  that work. Confirmed from established knowledge.
SHARED_MECHANISM: two_module_adversarial_learning
ROUTES: R-COMPOSE, R-WORLD, R-SUBSTRATE, R-BACKEND
BLOCKER: R-COMPOSE, an adjudication capability is missing for the full claim,
  because the finding is a relation between an error curve and an occupancy
  distribution while the outcome rule is one scalar comparison, so any verdict
  must be computed downstream and the specs can carry only raw observations;
  R-WORLD, the missing thing is the world itself, specifically an action
  interface, since neither existing kind lets anything choose what to do next
  inside a run, and without actions there is no controller; R-SUBSTRATE, a state
  capability is missing, namely learner weights that persist and update across
  steps, plus output-to-input chaining so the model's error becomes the
  controller's reward; R-BACKEND, no capability of substance is missing, an
  existing reinforcement-learning library could run this and the bench would
  only have to call it and fossilize the curves.
FAITHFUL: A faithful implementation needs a small environment with actions and
  observations, two trainable modules with persistent parameters, and a reward
  wire from the model's error to the controller. It must contain at least one
  learnable region and one irreducibly stochastic region, or the boredom claim
  and the noise-trap claim cannot be separated. Error and occupancy must be
  logged per step, not only at the end.
REDUCTION: A good reduction exists, and it turns on a bench property that was
  not designed for it. Drop the controller and keep the drive signal. Treat each
  world seed as a region and each evaluate_bitstring call as one observation of
  that region. Have a producer-side predictor forecast the score of the next
  probe bitstring in a region, and define the curiosity signal as the absolute
  error of that forecast. Now use repeat.seed_derivation as the learnability
  switch, which is the whole trick. Under constant, every repeat scores against
  the SAME hidden target, the region is a fixed function, and a predictor that
  has seen enough probes drives its error toward zero, which is boredom observed
  directly. Under sha256_index, every repeat scores against a DIFFERENT target,
  the region is redrawn each time, and no predictor can push its error below the
  spread of the score distribution, which is exactly the noisy television. Run
  both arms at matched probe counts, say 200 probes per arm as a NEW DESIGN
  CHOICE, and compare error trajectories offline. WHAT IT PRESERVES: the
  heterostatic signal itself, the distinction between reducible and irreducible
  uncertainty, the decay of interest, and the trap, which is precisely the
  failure mode the template's own rationale says a SURVIVED verdict would not
  license. WHAT IT LOSES: the controller, and therefore the closed loop. Nothing
  chooses where to go, so this measures the drive signal and not the agent. It
  also loses the adversarial coupling, since the predictor has no opponent.
  WHICH CLAIM: that prediction-error-as-drive separates learnable from
  irreducible variance, and by how much, on a landscape whose irreducibility is
  known by construction rather than assumed. That is a genuine calibration of
  the signal, and it is the precondition for trusting it inside a controller
  later.

TEMPLATE_ID: cegar.abstraction.loop.v0
FIELD: Counterexample-Guided Verification
KIND: cegar_loop_v0
QUESTION: Can you prove a property about a system too big to check directly, by
  checking a deliberately blurred version of it and sharpening the blur only
  where the blur lies to you?
MECHANISM: Build a coarse abstraction of the system that keeps every real
  behaviour and also admits some fake ones, so it over-approximates. Ask a model
  checker whether the property holds on the abstraction. If yes, it holds on the
  real system too and you are done. If no, the checker hands back a
  counterexample trace. Replay that trace on the concrete system. If it
  reproduces, the bug is real and you are done. If it does not, it was an
  artifact of the blurring, and the trace tells you WHICH distinction the
  abstraction discarded; you add that distinction back, refine, and loop. The
  loop terminates because each refinement strictly splits the abstract state
  space.
CANDIDATE: The abstraction. What varies is which distinctions it keeps; what is
  judged is whether it is precise enough to settle the property.
WORLD: A concrete transition system plus a property to check. The world supplies
  a model checker, a concrete replay oracle, and, critically, counterexample
  traces rather than merely a yes or no.
WHAT_CHANGES: initial_abstraction_bits, either 11000000 or 11110000, and
  property_bits, 10101010. These parameter values survived ingest intact and are
  bitstrings of length eight, which strongly suggests an intended encoding onto
  the existing bitstring kind.
MEASURED: In the real method, a three-way outcome, property proven, real bug
  found, or refine again, together with the number of refinement rounds and the
  final abstraction size.
INFORMATIVE_FAILURE: Very informative. A refinement loop that fails to terminate
  within budget leaves the sequence of abstractions it tried, and that sequence
  directly measures how much the counterexample guidance is worth: a loop that
  removes one spurious distinction per round is being guided, a loop that
  thrashes is not. A spurious counterexample that cannot be diagnosed as
  spurious leaves a concrete, nameable gap in the replay oracle.
SOURCE_CHECK: VERIFIED. Clarke, Grumberg, Jha, Lu and Veith,
  Counterexample-Guided Abstraction Refinement, Computer Aided Verification
  2000. The Clarke et al 2000 attribution is correct and the loop described is
  the method. Confirmed from established knowledge.
SHARED_MECHANISM: refine_abstraction_from_counterexample
ROUTES: R-COMPOSE, R-EXECUTOR, R-BACKEND, R-SUBSTRATE
BLOCKER: R-COMPOSE, a measurement capability is missing and it is the decisive
  one, because evaluate_bitstring returns a SCALAR score and never the WITNESS,
  so a producer running the loop across specs learns how many positions
  disagree but never which, and CEGAR without the counterexample is not CEGAR,
  it is blind generate-and-test; R-EXECUTOR, the fix is small and specific, an
  executor or adapter that returns the disagreement mask alongside the score,
  which is a measurement capability; R-BACKEND, no capability is missing, an
  existing model checker could be invoked and its counterexample fossilized;
  R-SUBSTRATE, a control-flow capability is missing for any single-spec version,
  namely a bounded loop with output-to-input chaining, since refinement round
  N+1 must consume round N's trace and no payload may change inside a spec.
FAITHFUL: A faithful implementation needs a transition system, a property
  language, a model checker that emits traces, and a concrete simulator to
  adjudicate spuriousness. It needs a refinement operator that consumes a trace
  and returns a strictly finer abstraction, and the loop must be able to run to
  fixpoint rather than to a fixed count.
REDUCTION: A real and unusually clean reduction exists, and it yields a
  quantitative result about the method itself. Take the template's own numbers
  at face value, length 8, and treat the hidden target as the concrete
  behaviour. One spec is one refinement round: submit the current abstraction as
  bits and read score, the fraction of the eight positions on which the
  abstraction agrees with concrete behaviour. A score below 1.0 means a
  counterexample exists and the property is unsettled; solved true means it is
  settled. The producer holds the loop across specs, flipping bits to raise the
  score, starting from each of the two given abstractions. Now run two arms. Arm
  A is the bench as it stands, where the producer sees only the count of
  disagreements and must refine blind. Arm B is an oracle simulation, where the
  producer is separately told which position disagreed, imitating a real
  counterexample trace. Both arms run to score 1.0 or to a budget, over many
  seeds. WHAT IT PRESERVES: the abstraction as a candidate, monotone refinement
  toward a property, termination as the object of study, and rounds-to-proof as
  the measurable. WHAT IT LOSES: over-approximation semantics, because a Hamming
  score is symmetric and cannot distinguish a false alarm from a missed
  behaviour, so the spurious-versus-genuine adjudication, which is half of
  CEGAR, is simply absent. It also loses scale, and scale is the method's entire
  reason to exist. WHICH CLAIM: the gap between arm A and arm B measures, in
  rounds, what a counterexample witness is worth relative to a scalar oracle.
  For length L a witness-bearing loop should finish in at most L rounds while a
  count-only loop pays a real search cost. Measuring that gap on the current
  bench is a pre-registerable, evidence-backed argument for adding
  witness-returning executors, and it is the version worth running.

TEMPLATE_ID: computational_serendipity.v0
FIELD: Computational Serendipity
KIND: random_walk_v0
QUESTION: How often does an aimless, undirected process stumble into something a
  standing criterion would call valuable?
MECHANISM: The account this template draws on breaks a serendipitous discovery
  into four parts. A prepared mind holds standing interests and evaluation
  criteria. A serendipity trigger occurs, and it is unsought, accidental and
  independent of what the agent was doing. A bridge is then constructed by the
  agent, connecting the trigger to something it cares about. A result follows,
  and the result must have value. The account grades an episode along three
  dimensions: chance, how unlikely and unsought the trigger was; sagacity, how
  much insight the bridge took; and value, how good the result is. Only the
  combination is serendipity.
CANDIDATE: A trajectory of an unguided stochastic process. What varies is where
  the wander goes; what is judged is whether it reaches a state a preset
  criterion calls valuable.
WORLD: A one-dimensional line with a fixed origin and a value threshold placed
  at some distance from it. The world supplies randomness and the threshold, and
  nothing else.
WHAT_CHANGES: steps and step_scale. Both parameter value sets were destroyed in
  ingest and are unknown; the axis names are real.
MEASURED: The signed final position and the displacement from the start, both
  continuous, compared once against a threshold.
INFORMATIVE_FAILURE: Moderately informative and in one specific way very much
  so. A run in which no threshold is ever crossed still supplies the base rate
  of accidental threshold crossing at a given steps and step_scale, and that
  base rate is the null that every other discovery claim on this bench should be
  scored against. What a failure leaves nothing of is the serendipity question
  itself, because nothing here can tell a lucky crossing apart from a
  perceptive one.
SOURCE_CHECK: VERIFIED, with a correction to the description. The work is Pease,
  Colton, Ramezani, Charnley and Reed, A Discussion on Serendipity in Creative
  Systems, Proceedings of the Fourth International Conference on Computational
  Creativity, ICCC 2013, pages 64 to 71. It does define the prepared mind, the
  serendipity trigger, the bridge and the result, and the three dimensions of
  chance, sagacity and value. It is a discussion paper proposing those
  dimensions, not a standards document, and it has five authors rather than the
  two named. Checked this session.
SHARED_MECHANISM: accumulate_trajectory
ROUTES: R-REPAIR, R-COMPOSE
BLOCKER: R-REPAIR, the missing thing is parameter values, since steps and
  step_scale both arrived null and no executor may default a parameter, so the
  spec is rejected until an operator sets them; that is the only thing standing
  between this template and execution; R-COMPOSE, an adjudication capability is
  missing for the actual construct, since chance is measurable here but sagacity
  and the bridge are not, and no downstream analysis of position values can
  recover them.
FAITHFUL: A faithful implementation needs an agent with standing interests that
  were formed before the trigger, a mechanism that can notice an event it was
  not looking for, and a bridge operator that connects that event to an
  unrelated goal. It also needs the value criterion to be capable of being met
  by something not on the agent's current agenda, which is the exact property a
  pre-registered scalar threshold destroys.
REDUCTION: A reduction exists, it is nearly free, and its honest scope is
  narrow. Set steps to 200 and step_scale to 0.1, both NEW DESIGN CHOICES, and
  set the outcome rule to displacement greater than or equal to 2.0 mapping to
  SURVIVED. Use repeat count 200 with seed_derivation sha256_index and state
  reset, so the 200 repeats are independent walks. The crossing frequency is a
  calibrated base rate of accidental value. Sweep steps and step_scale across
  specs to get the rate as a surface. One trap must be flagged: the bench's
  degenerate_by_construction check fires only for a constant seed meeting a
  STATELESS kind, and random_walk_v0 is stateful, so a constant seed with state
  reset and count greater than 1 gives 200 byte-identical walks and will NOT be
  flagged. That configuration must be avoided by hand. WHAT IT PRESERVES: the
  chance dimension exactly, an unguided process with no objective, and the
  prepared mind in its thinnest possible form, since a pre-registered outcome
  rule is literally a criterion fixed before the trigger. WHAT IT LOSES:
  sagacity and the bridge, wholly. Nothing recognises an unsought result,
  nothing connects it to an unrelated goal, and a criterion fixed in advance
  means the agent was in fact looking for exactly this, which is the precise
  negation of serendipity. WHICH CLAIM: only the base rate of luck at a given
  budget. That is not serendipity and must never be written up as such, but it
  is the correct denominator for every serendipity claim the bench later makes,
  and no other template in this chunk supplies it.

TEMPLATE_ID: empowerment.v0
FIELD: Empowerment
KIND: channel_capacity_evaluator.v0
QUESTION: Can an agent decide what to do using nothing but a measure of how much
  control it has over its own future, with no goal given to it from outside?
MECHANISM: Treat the agent's actuators as the input to a communication channel
  and the future state of the world as its output. Fix a state and a horizon of
  h steps. Consider every action sequence of length h. Each sequence induces a
  distribution over the state h steps later. The channel capacity of that
  mapping, the maximum over distributions on action sequences of the mutual
  information between the sequence and the resulting state, is the empowerment
  of the state, measured in bits. It is computed by an iterative algorithm of
  the Blahut-Arimoto family. High empowerment means many distinguishable
  futures are reachable. An agent with no goal can then simply climb the
  empowerment landscape, and in many worlds this reproduces sensible behaviour
  such as staying near the centre of a room or keeping a pole balanced.
CANDIDATE: A state of the world, judged by how many distinguishable futures the
  agent can steer itself into from there.
WORLD: A dynamical system with an explicit action interface, a resettable state,
  and a forward model or simulator that can be rolled out repeatedly from the
  same state under different action sequences.
WHAT_CHANGES: lookahead_horizon, the number of steps in the action sequence, and
  actuator_bits, the size of the action alphabet. Both parameter value sets were
  destroyed in ingest.
MEASURED: A single non-negative real number of bits per state, bounded above by
  the horizon times the actuator bits. In practice a landscape of that number
  over many states.
INFORMATIVE_FAILURE: Informative. An empowerment estimate that comes out at the
  theoretical maximum everywhere says the world is deterministic and fully
  controllable and therefore has no landscape to climb, which indicts the world.
  An estimate near zero everywhere says the action channel is being swamped by
  noise or the horizon is too short, which indicts the parameters. Both are
  diagnostic and both are cheap. A failure that leaves nothing is one where the
  estimator itself is biased, and mutual-information estimators on sparse
  histograms are biased upward, so a random-action-relabelling null must be run
  alongside or the number means nothing.
SOURCE_CHECK: VERIFIED. Klyubin, Polani and Nehaniv, Empowerment: A Universal
  Agent-Centric Measure of Control, IEEE Congress on Evolutionary Computation
  2005. The definition as the channel capacity from an actuation sequence to a
  future sensor state is that paper's. Confirmed from established knowledge.
SHARED_MECHANISM: measure_information_quantity
ROUTES: R-COMPOSE, R-EXECUTOR, R-WORLD
BLOCKER: R-COMPOSE, a measurement capability is missing, because mutual
  information is a functional of a joint DISTRIBUTION and the outcome rule is
  one scalar comparison on one result field with no aggregation across repeats,
  so the estimate can only ever be assembled downstream from many fossils;
  R-EXECUTOR, the missing thing is an estimator, a channel-capacity executor
  that consumes a joint sample and returns bits, which is a measurement
  capability; R-WORLD, the missing thing is the world, specifically an action
  interface, because empowerment is defined over an agent's actuators and no
  existing kind has actuators at all.
FAITHFUL: A faithful implementation needs a simulator with settable state,
  discrete actions, and the ability to be reset and re-rolled from an identical
  state many times. It needs a mutual-information estimator with a bias
  correction and a permutation null. It needs empowerment to be evaluated at
  MANY states, because the entire content of the theory is that the value varies
  over states and that the variation is what guides behaviour.
REDUCTION: A reduction exists, and it is more useful to Prometheus than it first
  looks, because it turns the measure on the bench itself. The bench has no
  actuators inside a run, but a spec's PAYLOAD is chosen by the producer and is
  therefore an action. Fix one world seed. Define an action alphabet of eight
  step_scale values, a NEW DESIGN CHOICE, and run one random_walk_v0 spec per
  action with steps fixed, so steps plays the role of the horizon h. Record the
  final position from each. Discretise position into bins and estimate the
  mutual information between the action and the binned outcome downstream, with
  a shuffled-action permutation null to correct the sparse-histogram bias. Then
  repeat the whole sweep under seed_derivation sha256_index so the outcome is
  redrawn per repeat. The prediction is sharp and pre-registerable: in the fixed
  seed arm the map from action to outcome is deterministic and the estimated
  capacity should approach three bits, the full alphabet; in the redrawn arm it
  should approach zero. WHAT IT PRESERVES: the definition, maximum mutual
  information between an action channel and a future state; the estimator and
  its null; the horizon as an explicit parameter; and the qualitative contrast
  between a controllable and an uncontrollable world. WHAT IT LOSES:
  agent-centricity, since the empowered party is the producer and not anything
  inside the run; state dependence, since one world seed is one state and the
  landscape that the theory is entirely about cannot exist with one seed per
  spec; and any notion of climbing that landscape. WHICH CLAIM: that the
  estimator is correctly built and calibrated against a known answer, plus a
  diagnostic Prometheus genuinely wants, which is how many bits of the result a
  spec's payload actually buys under each seed_derivation setting. Call it what
  it is, an instrument calibration plus a bench diagnostic, not a test of
  empowerment as a behavioural drive.

TEMPLATE_ID: falsification_walk.v0
FIELD: Falsification-Based Search
KIND: random_walk_v0
QUESTION: If you cannot prove a system safe, can you at least hunt hard for an
  input that makes it unsafe, and how much hunting does it take to find one?
MECHANISM: A safety requirement is written in a temporal logic over signals, for
  example that a value never leaves a band for the whole run. That formula is
  given a real-valued robustness rather than a yes or no: positive means
  satisfied with room to spare, near zero means marginal, negative means
  violated, and the magnitude says by how much. Falsification then becomes
  minimisation. A stochastic optimiser, Monte Carlo sampling or simulated
  annealing or cross-entropy, proposes input signals and parameters, simulates
  the system, computes robustness, and steers toward lower robustness. The first
  negative value is a counterexample and the search stops. No negative value
  within budget proves nothing at all; the search is deliberately incomplete.
CANDIDATE: A trajectory, and behind it the input signal that produced it. What
  varies is the sampled input; what is judged is the robustness of the resulting
  trace against the property.
WORLD: A cyber-physical model with a simulator, here surrogated by a
  one-dimensional walk, plus a safety envelope. The world supplies a full trace
  over time, which is what a temporal property is evaluated against.
WHAT_CHANGES: steps and step_scale. Both parameter value sets were destroyed in
  ingest. Note also a schema oddity that must be repaired: step_scale is typed
  as an int_range here while the sibling template types it as choices, and a
  step scale is naturally a float, so the type as well as the value needs an
  operator decision.
MEASURED: In the real method, a continuous robustness value per trace and, over
  a campaign, the number of simulations to first falsification. On this bench,
  only the terminal position and displacement.
INFORMATIVE_FAILURE: Genuinely informative, and this is the rare template where
  failure is the designed output. Not finding a violation leaves a calibrated
  falsification rate at a given budget, which is exactly the floor that any
  smarter search must beat to justify itself. Finding one leaves a concrete
  counterexample trace, which is the most valuable artifact in the whole field.
  The asymmetry is the point and it matches the bench's own posture: FALSIFIED
  is conclusive, SURVIVED is not.
SOURCE_CHECK: VERIFIED. S-TaLiRo: A Tool for Temporal Logic Falsification for
  Hybrid Systems, Annpureddy, Liu, Fainekos and Sankaranarayanan, TACAS 2011.
  The robustness-guided stochastic falsification method and the Monte Carlo
  baseline are that tool's. Confirmed from established knowledge.

  divergence reaches the solution while convergence does not, because the

TEMPLATE_ID: query_by_committee.v0
FIELD: Active Learning
KIND: query_by_committee_v0
QUESTION: If labelling data is expensive, does letting the learner choose which
  examples to have labelled beat labelling examples at random, and by how much?
MECHANISM: Keep the set of all hypotheses still consistent with the labels seen
  so far, the version space. Draw a committee of several hypotheses from it at
  random. Show the committee each unlabelled candidate and see how much they
  disagree about it. A candidate everyone agrees on teaches nothing, because its
  label is already determined; a candidate that splits the committee roughly in
  half is worth the most, because whichever way its label falls, about half the
  surviving hypotheses are eliminated. Query the label of the
  most-disagreed-about candidate, add it, shrink the version space, resample the
  committee, and repeat until the budget is gone. The theoretical result is that
  because each query carries roughly constant information, generalisation error
  falls exponentially in the number of queries rather than polynomially.
CANDIDATE: A query, that is, a choice of which point to have labelled. What
  varies is the selection policy; what is judged is the error, or here the
  identification, achieved per unit of label budget.

  label oracle that answers a bounded number of questions. The world supplies

WHAT_CHANGES: committee_size and query_budget. Both parameter value sets were
  destroyed in ingest.
MEASURED: Generalisation error as a function of the number of queries spent, a

INFORMATIVE_FAILURE: Informative. Active selection that matches random selection

  real and frequently reported outcome rather than a bug. Active selection that

  fraction of declared positives that are true, falls out. The headline

  process, though such an executor would be trivial to write; R-REPAIR,
  parameter values are missing, since study_power and bias_factor both arrived
  null and no executor may default a parameter.
FAITHFUL: A faithful implementation needs a random draw per study governed by
  named, pre-registered rates, and a campaign large enough that the empirical
  ratio has a usable standard error, which must be computed before any threshold
  is chosen. It must keep the four field parameters as explicit, fossilized
  inputs, and it must compare the empirical ratio to the closed-form prediction,
  because the closed form is the ground truth here and agreement with it is the
  only thing that validates the simulator.
REDUCTION: A reduction exists that needs no new executor at all, and it turns
  the bench's own fossil discipline into part of the experiment. First, note
  that evaluate_bitstring with a fixed bits string and seed_derivation
  sha256_index gives, per repeat, a score distributed as the number of matching
  positions out of L over L, which for a uniform hash target is a fair-coin
  count. Thresholding that score in the outcome rule therefore yields SURVIVED
  with a probability equal to a binomial upper tail, and by choosing L and the
  threshold together you can hit a target rate closely: with L equal to 20, a
  threshold of score at or above 0.70 fires with probability about 0.058, close
  enough to a five percent significance level, and lower thresholds give rates
  in the range wanted for power. Build two spec families on that basis, a
  true-relationship arm whose threshold is tuned to the chosen power and a
  false-relationship arm whose threshold is tuned to the significance level,
  with L raised if a finer rate grid is needed, all NEW DESIGN CHOICES. Draw arm
  membership from the pre-study odds in the producer, run several hundred specs
  per arm under sha256_index, and compute the empirical positive predictive
  value downstream against the closed form. Then add the part that is specific
  to this bench and genuinely worth doing: model the bias term by having the
  producer selectively withhold a fraction of FALSIFIED fossils from the
  write-up, and check whether the sealed run index makes that withholding
  visible as a gap. WHAT IT PRESERVES: the exact arithmetic of the model, the
  four field parameters as pre-registered inputs, the closed form as ground
  truth, and pre-registration of power and significance before any run, which is
  the methodological point of the original paper. WHAT IT LOSES: any actual
  data, any actual effect, and any actual analysis, since only the reporting
  process is being simulated; and it loses the multi-team dynamics of a real
  literature, where teams see each other's results. It also depends on an
  assumption that must be checked first, that scores for a fixed bitstring
  across seeds really are binomially distributed, which is a one-spec
  calibration run. WHICH CLAIM: two, and the second is the reason to run it.
  One, that empirical positive predictive value tracks the closed-form
  prediction under known rates, which validates the campaign machinery. Two,
  that a sealed fossil ledger with monotone run indices makes selective
  reporting detectable, which is a claim about Prometheus itself, testable with
  a method drawn from meta-science, and is exactly the kind of self-audit this
  bench should be able to make about its own record.
