TEMPLATE_ID: abduce_set_cover.v0
FIELD: Abductive Reasoning
KIND: abduce_set_cover_v0
QUESTION: Given a set of observed symptoms, can a system pick the smallest set
  of underlying causes that accounts for all of them, and how small can that
  explanation get before it stops covering everything?
MECHANISM: Parsimonious covering theory sets up a two-layer causal network. One
  layer is disorders, the other is manifestations, and a stored relation says
  which manifestations each disorder can produce. A case presents a set of
  observed manifestations. The solver then searches the powerset of disorders
  for subsets whose combined manifestation sets cover every observation, and
  among those covers it prefers the ones of minimum cardinality or the ones
  that are irredundant, meaning no member can be dropped without losing
  coverage. The output is a cover, or a set of competing covers, plus its size.
CANDIDATE: A candidate explanation, which is a subset of the disorder set. What
  varies is which disorders are in the subset and how many there are. What is
  judged is whether the subset covers all observed manifestations and how large
  the subset is.
WORLD: A fixed bipartite causal network. The world supplies the disorder
  inventory, the manifestation inventory, the causal edges between them at some
  density, and one presenting case, that is one particular manifestation set to
  be explained.
WHAT_CHANGES: The number of manifestations presented, the size of the
  hypothesis space of disorders, and the causal density of the network, which
  controls how many disorders can explain any given symptom and therefore how
  ambiguous the case is. Both integer axes arrived null and must be set by the
  operator.
MEASURED: The cardinality of the returned cover, an integer bounded below by 1
  and above by the hypothesis space size, plus a boolean saying whether the
  cover is complete. On the bench only one of those two can be adjudicated.
INFORMATIVE_FAILURE: Rich. A failure to find any complete cover is a direct
  statement about the causal network, namely that at least one presented
  manifestation has no cause in the hypothesis space, which localises the
  defect to a specific symptom. A failure to reach the target parsimony while
  still covering everything yields the achieved size, which is an upper bound on
  the true minimum and is reusable as the preregistered threshold for the next
  run. Failures here are bounds, not noise.
SOURCE_CHECK: VERIFIED. Reggia, Nau and Wang, Diagnostic expert systems based
  on a set covering model, International Journal of Man-Machine Studies 19,
  1983, pages 437 to 460, confirmed by search; the set covering model of
  diagnosis and the notion of parsimonious covers are correctly attributed.
SHARED_MECHANISM: search_over_candidates
ROUTES: R-BACKEND, R-EXECUTOR, R-COMPOSE
BLOCKER: R-BACKEND needs a measurement channel, since no existing result field
  can carry a cover or its cardinality, and the payload cannot carry a causal
  network, so an adapter must both feed the network in and pull cover_size out;
  R-EXECUTOR is the same missing measurement, plus the fact that generating the
  network from one integer seed is a modelling choice nobody has made yet;
  R-COMPOSE is blocked on adjudication, because the interesting statement is a
  comparison of achieved size against a chance baseline, and the outcome rule is
  a single scalar comparison that cannot aggregate across specs.
FAITHFUL: A faithful implementation needs a generator that turns one integer
  seed into a bipartite causal network at a declared density, a declared
  presenting case drawn from that network, and a solver that returns a
  minimum-cardinality or irredundant cover. The result must expose at least
  cover_size and covered_all so the sealed outcome rule has a scalar to compare.
  Off-the-shelf set cover solvers and ILP packages already do the search, so the
  bench only has to build the instance, call out, and fossilize.
REDUCTION: A real one exists, and it is a null rather than a method. Represent a
  candidate explanation as a bitstring over the hypothesis space, one bit per
  disorder, and set length equal to the hypothesis space size. Fix bits to a
  candidate with exactly k ones and run repeats under sha256_index, so every
  repeat scores that fixed k-sparse explanation against an independently drawn
  hidden target set. Because the scorer is bit-match fraction, the score
  distribution for a k-sparse candidate against a uniform target is exactly
  computable, so a sweep over k at fixed length gives the chance baseline for
  how well an explanation of a given parsimony matches an unknown truth. NEW
  DESIGN CHOICE, since the axes are null: hypothesis space size 32, manifestation
  count 8, k swept over 1, 2, 4, 8, 16. WHAT IT PRESERVES: the fixed candidate
  judged against a hidden ground truth, the parsimony axis as an explicit
  independent variable, and the reproducible case identity carried by the seed.
  WHAT IT LOSES: the covering relation itself, and with it everything that makes
  this abduction. There are no manifestations, no causal edges, no coverage
  constraint, and no tradeoff between parsimony and completeness, so the score
  is set similarity and not explanatory adequacy. WHICH CLAIM IT SUPPORTS: only
  the eligibility claim, that an explanation of size k over a space of size L
  reaches similarity s to an unknown truth with probability p by chance. That is
  the denominator any later abduction result has to beat, and computing it first
  prevents freezing a parsimony threshold that chance alone would clear.

TEMPLATE_ID: algorithm_discovery.v0
FIELD: Algorithm Discovery
KIND: evaluate_bitstring
QUESTION: Can a search over encoded sequences of computational primitives find a
  genome that behaves like a target algorithm, rather than merely resembling it
  bit for bit?
MECHANISM: In the PADO line of work, a genome is decoded into an executable
  program, in that case a graph or tree of primitive operations with indexed
  memory. The program is then run on a set of input signals, its outputs are
  read, and fitness is the quality of those outputs on the classification task.
  Multiple such programs are orchestrated, each contributing a confidence, and
  the ensemble decides. The essential step is that the genome is INTERPRETED
  before it is judged; nothing is scored on its syntax.
CANDIDATE: The bitstring genome. What varies across specs is which bitstring is
  submitted and, through length, which landscape it faces. What is being judged,
  on this bench, is the fraction of positions matching a hidden target string.
WORLD: One integer seed, from which the executor derives a hidden target of the
  declared length by hashing the string target, the seed and the length. The
  world supplies nothing else: no inputs, no interpreter, no task.
WHAT_CHANGES: Across the given param_space only the choice between two
  structured 16-bit candidates, period-2 alternation and period-4 blocks, plus
  the length axis, which arrived null. Across specs the seed also varies, which
  redraws the landscape entirely.
MEASURED: score, continuous from 0 to 1, equal to the count of matching
  positions divided by the target length, plus solved, a boolean true only at
  score 1.0.
INFORMATIVE_FAILURE: Thin as an algorithm result but sharp as an instrument
  result. A low score tells you nothing about algorithmic quality because
  nothing was executed. What a run does leave behind is a sample from the
  chance distribution of a structured string against a hash-derived target,
  which accumulates into the bench's own null and is reusable by every later
  bitstring template. A repeated near-0.5 result across many seeds is the useful
  finding that the hash target is unbiased with respect to low-complexity
  strings.
SOURCE_CHECK: PLAUSIBLE. Astro Teller's PADO is real and was developed with
  Manuela Veloso at Carnegie Mellon; search returns a 1995 CMU technical report,
  PADO, learning tree structured algorithms for orchestration into an object
  recognition system, and related 1995 to 1997 papers on algorithm evolution for
  signal understanding. The acronym is expanded as Parallel Architecture
  Discovery and Orchestration in some sources and Parallel Algorithm Discovery
  and Orchestration in others, and no publication with exactly the cited title
  and year 1996 was confirmed, so the method is real but this specific
  attribution is not established.
SHARED_MECHANISM: score_fixed_candidate
ROUTES: R-REPAIR, R-COMPOSE, R-EXECUTOR
BLOCKER: R-REPAIR is blocked only on a missing parameter, the null length axis,
  which is a specification gap and not a capability gap; R-COMPOSE is blocked on
  adjudication, because the ensemble statement over many seeds is an aggregation
  the single scalar outcome rule cannot express and must be read downstream;
  R-EXECUTOR is blocked on a measurement capability, since nothing on the bench
  can decode a genome into operations, run it on inputs, and return output
  quality, and that is the entire method.
FAITHFUL: A faithful implementation needs a decoder from bits to a program in a
  declared primitive set, an interpreter with a bounded step budget so
  non-halting genomes terminate, a set of task inputs supplied by the world, and
  a scalar output-quality measure. Orchestration of several programs is a second
  layer and can wait. Without the interpreter the template is a bitstring
  similarity test wearing an algorithm-discovery label.
REDUCTION: This template is already executable, and the reduction is to stop
  pretending it is about algorithms and use it as instrument calibration. Set
  length to 16, which is a REPAIR and not a design choice, because both supplied
  candidates are exactly 16 characters long. This matters more than it looks:
  the scorer divides matches by the TARGET length while comparing only over the
  overlap, so a 16-character candidate against length 32 has a maximum
  attainable score of 0.5 and any threshold above that can never fire. Then run
  both candidates across many seeds under sha256_index or linear_index repeats,
  never under constant with state reset and count above 1, which the bench flags
  as degenerate by construction. WHAT IT PRESERVES: fixed candidate scored
  against a hidden target derived from the world, and the contrast between two
  candidates of different periodicity. WHAT IT LOSES: interpretation, execution,
  inputs, outputs and orchestration, that is the whole of PADO. WHICH CLAIM IT
  SUPPORTS: that the hidden-target hash is unbiased with respect to structured
  low-complexity bitstrings, tested as an empirical mean against the exact
  binomial null with mean 0.5 and standard deviation 1 over 2 root L, which for
  L equal to 16 is 0.125. That is a genuine bench-hygiene result and is
  available today at near zero cost.

TEMPLATE_ID: bacon_equation_discovery.v0
FIELD: Automated Scientific Discovery
KIND: discover_equation_v0
QUESTION: Can a small set of general heuristics, applied to a table of
  measurements, rediscover the empirical law that generated them, without being
  told the form of the law in advance?
MECHANISM: BACON reads a table of observed variables. It applies a handful of
  data-driven heuristics, one at a time. If a quantity is constant, record it as
  a law. If two quantities increase together, define a new theoretical term
  equal to their ratio. If one increases as the other decreases, define their
  product. Each new term becomes a column in the table, and the heuristics run
  again on the enlarged table. The recursion halts when some derived term comes
  out constant within tolerance, and that constant term is the discovered law.
  This is how BACON reaches expressions of the same shape as the ideal gas law
  and Kepler's third law from raw tables.
CANDIDATE: A derived theoretical term, that is a composed expression over the
  observed variables. What varies is which composition the heuristics build.
  What is judged is whether that term is constant across the rows within
  tolerance.
WORLD: A data table produced by some underlying process, plus a noise level.
  The world supplies the observed variables, their ranges, and the measurement
  error that sets the tolerance for calling something constant.
WHAT_CHANGES: The number of variables in the table and the depth to which the
  heuristics are allowed to recurse before giving up. Both axes arrived null.
  Noise level is the axis the rationale cares about and it is not in the
  param_space at all.
MEASURED: Whether a law was found within the depth budget, the depth at which
  it was found, and the residual variation of the discovered constant. The
  natural scalar is the residual, from 0 upward.
INFORMATIVE_FAILURE: Useful. A failure at a given depth is a lower bound on the
  compositional complexity of the true law with respect to that heuristic set,
  which is a real statement about the data and not just about the run. The
  partial table of derived terms is also kept, and the terms that came closest
  to constant are directional pointers toward the right composition. Failure
  here narrows the search space rather than emptying it.
SOURCE_CHECK: VERIFIED. Pat Langley's BACON is a well established production
  system for discovering empirical laws, first reported in 1977 and developed
  through BACON.1 to BACON.5 and the Scientific Discovery volume with Simon,
  Bradshaw and Zytkow. Confirmation here rests on established literature
  knowledge rather than a fetch, because the session web search budget was
  exhausted; the method and the attribution to Langley are not in doubt, the
  exact 1977 venue was not re-checked.
SHARED_MECHANISM: fit_model_to_data
ROUTES: R-BACKEND, R-COMPOSE, R-EXECUTOR
BLOCKER: R-BACKEND is blocked on a measurement channel, since the world is one
  integer and cannot supply a data table, and no result field can carry a
  discovered expression, so an adapter must generate the table from the seed and
  return residual and depth; R-COMPOSE is blocked on control flow, because the
  heuristic recursion is output-to-input chaining, each derived term becoming an
  input column for the next pass, and a sealed spec cannot chain; R-EXECUTOR is
  the same control-flow blocker moved inside a new kind, where it becomes legal
  because the chaining is then internal to one execution.
FAITHFUL: A faithful implementation needs the world to emit a multi-column data
  table from its seed with a planted law and a declared noise level, an
  interpreter for the heuristic set that can define and append derived terms,
  and a tolerance rule for calling a term constant. It must also record the
  discovered expression itself, because the residual alone cannot distinguish
  the true law from an accidental invariant.
REDUCTION: A good one exists and it uses the walk as a data generator rather
  than the bitstring as a candidate. random_walk_v0 is a genuine stochastic
  process with a known governing law: each step is uniform on minus step_scale
  to plus step_scale, so displacement has mean 0 and variance equal to steps
  times step_scale squared over 3. Run a grid of specs sweeping steps over 10,
  30, 100, 300, 1000 and step_scale over 0.1, 1.0, 10.0, many seeds each, all
  under sha256_index so the repeats are independent draws. Then, downstream and
  outside the outcome rule, apply BACON's own heuristics to the resulting table
  whose columns are steps, step_scale and squared displacement, and see whether
  the ratio heuristic recovers a constant, which it should, at the value one
  third. NEW DESIGN CHOICE: the grid above, and heuristic depth 3, since both
  axes arrived null. WHAT IT PRESERVES: everything except the identity of the
  data source. A real generating process, a planted law that is known exactly in
  advance, genuine measurement noise from finite sampling, term composition by
  ratio, and a constancy test at a declared tolerance. WHAT IT LOSES: the
  richness of a multi-variable physical table, so the discoverable law is a
  single scaling relation and the recursion never goes past depth 2. WHICH
  CLAIM IT SUPPORTS: that the bench's fossil record is sufficient to recover a
  planted scaling law and its constant from observations alone. That is a
  precondition for every discovery template in the inbox and nobody has checked
  it.

TEMPLATE_ID: coevolution.parasites.v0
FIELD: Coevolution
KIND: coevaluate_populations.v0
QUESTION: Does making the test cases evolve against the solutions, instead of
  holding them fixed, keep a search from getting stuck on a local optimum?
MECHANISM: Two populations are maintained at once. Hosts are candidate
  solutions, in Hillis's case sorting networks. Parasites are sets of test
  cases, in that case lists to be sorted. Host fitness is how many of the
  co-located parasite's cases it handles correctly; parasite fitness is how many
  it makes the host fail. Both populations reproduce with variation on a spatial
  grid, so a host that is good only against the currently common cases is
  immediately punished when the parasites shift. The difficulty of the test set
  is therefore a moving function of current host competence, which is what
  prevents the search from converging on a static benchmark it has memorised.
CANDIDATE: Two candidates at once, and that is the point. The host varies in its
  solution structure; the parasite varies in which test cases it presents. Each
  is judged only against the other, so neither has an absolute fitness.
WORLD: A shared spatial arena holding both populations, with locality so that
  hosts meet nearby parasites. The world supplies the interaction rule that
  turns a host-parasite meeting into a pair of fitnesses, and nothing more; there
  is no external objective.
WHAT_CHANGES: Host population size and parasite population size, both offered as
  50, 100 or 200. Implicitly also the generation count and the mutation
  operators, neither of which is in the param_space.
MEASURED: Host performance over generations, and in the honest version the
  quality of the final host against an independent held-out test set rather than
  against the surviving parasites. The scale is a fraction of test cases passed.
INFORMATIVE_FAILURE: Genuinely informative, and this method's failures are
  famous. Disengagement, where parasites become so hard or so easy that fitness
  carries no gradient, is diagnostic and visible in the fitness variance.
  Cycling, where hosts and parasites chase each other around a loop forever, is
  the classic Red Queen failure and leaves a recoverable period. Both failures
  leave a full trajectory of two coupled populations, which is data about the
  coupling even when no good host emerges.
SOURCE_CHECK: VERIFIED. Hillis 1990, Co-evolving parasites improve simulated
  evolution as an optimization procedure, Physica D volume 42, is a foundational
  and correctly attributed paper on coevolving sorting networks with test-case
  parasites. Confirmed from established literature knowledge; the web search
  budget was exhausted before this template, but the attribution is not in
  doubt.
SHARED_MECHANISM: two_population_interaction
ROUTES: R-WORLD, R-COMPOSE, R-EXECUTOR
BLOCKER: R-WORLD is blocked on state, specifically the absence of any second
  organism type and of a population at all, since one spec has one world holding
  one integer and no notion of an opponent; R-COMPOSE is blocked on adjudication,
  because relative fitness is inherently a two-field comparison, host score
  against parasite score, and the outcome rule permits exactly one field and one
  operator; R-EXECUTOR is blocked on state again, since even a new kind would
  need to carry two populations across generations, which is output-to-input
  chaining and therefore really an R-SUBSTRATE request wearing an executor
  costume.
FAITHFUL: A faithful implementation needs two typed populations with heredity
  and variation, an interaction rule that computes both fitnesses from a single
  meeting, and generational chaining so that the output population of one step
  is the input population of the next. It also needs an independent held-out
  evaluation set, because measuring the final host against the final parasites
  is exactly the control that memory says is drawn from the treatment's own
  selection relation and is therefore not a control at all.
REDUCTION: One survives, at the producer layer, and it is more faithful than it
  first appears. The parasite population becomes the SEED POOL, since the seed
  is what determines the hidden target and therefore the difficulty. Run two
  arms across specs with the same candidate-improvement procedure. In the
  iid arm the producer draws each next seed uniformly. In the adversarial arm
  the producer picks each next seed from the set on which the current best
  candidate scored WORST, which is precisely parasite selection: the test is
  selected for host failure. Measure candidate score improvement per spec in
  each arm, downstream. WHAT IT PRESERVES: the defining coupling, that test
  difficulty is a function of current host competence, plus the host and test
  asymmetry, the arms-race dynamic across generations, and a clean iid control
  that is not drawn from the adversarial selection relation. WHAT IT LOSES: the
  parasites have no genotype and no heredity, so they cannot ACCUMULATE
  structure across generations and cannot invent a new kind of hard case; they
  can only be filtered from a fixed pool. That makes this adversarial sampling,
  which is the one-sided half of coevolution, and it cannot exhibit Red Queen
  cycling because only one side has memory. WHICH CLAIM IT SUPPORTS: that
  adversarially selected test seeds slow measured candidate improvement relative
  to iid seeds, and that a candidate tuned on adversarial seeds does or does not
  transfer to held-out iid seeds. That is a real and testable coevolution claim,
  and it needs no bench change at all.

TEMPLATE_ID: curiosity.v0
FIELD: Curiosity-Driven Exploration
KIND: pseudo_count_exploration.v0
QUESTION: In an environment too large to count visits to individual states, can
  a learned density model stand in for a visit counter well enough to tell an
  agent which parts of the world it has not really seen?
MECHANISM: A sequential density model is fit online over observed states. For a
  state just seen, the model gives a probability before the update and a
  probability after being trained on that one observation. The increase, called
  the prediction gain, is large for a state the model finds surprising and small
  for one it already expects. From those two probabilities a pseudo-count is
  derived algebraically, and it behaves like an empirical visit count while
  being defined for states never visited. An exploration bonus proportional to
  one over the square root of the pseudo-count is added to the reward, and the
  agent's policy then pursues that bonus, which is what drives it into unvisited
  regions.
CANDIDATE: The agent's policy, judged by where it goes. What varies is the
  density model class and the bonus scale, and downstream of those, the states
  the agent chooses to visit.
WORLD: A sequential decision environment with high-dimensional observations,
  sparse or absent extrinsic reward, and a large enough state space that
  tabular counting is impossible. The world supplies observations, a transition
  rule responding to actions, and reward.
WHAT_CHANGES: The density model, offered as CTS or PixelCNN, and the bonus
  scale, whose range arrived null.
MEASURED: State coverage and extrinsic return over training, plus the agreement
  between pseudo-counts and true counts where true counts happen to be known.
  Coverage is a count, return is unbounded, agreement is a ratio.
INFORMATIVE_FAILURE: Mixed. A failed exploration run leaves a visitation
  histogram, which is directly informative about where the bonus dried up and
  therefore about which states the density model considered familiar too early.
  That is concrete and reusable. What it does not leave is any separation
  between two very different causes, a bad density model and a bad policy
  optimiser, so a bare failure is not attributable without the estimator being
  measured separately.
SOURCE_CHECK: VERIFIED with a caveat. Bellemare, Srinivasan, Ostrovski, Schaul,
  Saxton and Munos, Unifying Count-Based Exploration and Intrinsic Motivation,
  NeurIPS 2016, introduces pseudo-counts from a CTS density model and the one
  over root pseudo-count bonus. The PixelCNN option in the param_space belongs
  to the 2017 follow-up by Ostrovski and colleagues, count-based exploration
  with neural density models, not to the cited paper, so one of the two axis
  values is attributed to the wrong publication. Confirmed from established
  literature knowledge; the search budget was exhausted before this template.
SHARED_MECHANISM: accumulate_trajectory
ROUTES: R-SUBSTRATE, R-COMPOSE, R-BACKEND
BLOCKER: R-SUBSTRATE is blocked on control flow, and this is the deep one: an
  exploration bonus is only exploration if it CHANGES THE NEXT ACTION, which
  requires output-to-input chaining within a run, and the payload of a sealed
  spec is fixed for the whole spec by construction; R-COMPOSE is blocked on a
  measurement, since to fit any density model downstream the bench must emit the
  per-step state trace and random_walk_v0 returns only the final position and
  displacement, not the intermediate states; R-BACKEND is blocked on the same
  missing trace, plus the absence of any action space for an external RL library
  to act in.
FAITHFUL: A faithful implementation needs an environment with actions and
  observations, a policy that can be updated during a run, an online density
  model over observations, and a reward channel the bonus can be added to. The
  bench would have to allow a run to be a training loop rather than a single
  measurement, which is a substrate change and not an executor change.
REDUCTION: A real one exists, and it works by deleting the agent and keeping the
  estimator. The theoretical core of the paper is that pseudo-counts approximate
  true visit counts, and that claim can be tested with no policy at all. Run
  random_walk_v0 with repeat state persist so the repeats form ONE trajectory,
  sweeping the number of repeats to get streams of increasing length. Bin
  position onto a fixed grid, which makes true visit counts exactly known.
  Downstream, fit a sequential density model over the bin sequence, compute the
  prediction gain and pseudo-count for each observation, and compare pseudo-count
  against the true running count. NEW DESIGN CHOICE, since bonus_scale arrived
  null: steps 1, step_scale 1.0, 5000 persisted repeats, bin width 1.0, and the
  bonus scale is not needed at all because no bonus is consumed. WHAT IT
  PRESERVES: the density model, the prediction gain, the pseudo-count derivation,
  and a ground-truth count to check it against, which is exactly the paper's
  central technical claim. WHAT IT LOSES: the entire agentic half. No actions, no
  policy, no reward, no bonus feedback, so nothing here is exploration. It also
  loses the hard part of the problem, because a 1-D binned walk is nearly
  tabular and the whole motivation was non-tabular state spaces, so success here
  is necessary and very far from sufficient. WHICH CLAIM IT SUPPORTS: that a
  given pseudo-count estimator is consistent on a stream with known counts. That
  is instrument calibration and must not be reported as an exploration result.
  IMPORTANT PREREQUISITE: even this needs random_walk_v0 to expose the per-step
  positions, or the walk must be run with steps equal to 1 so that each repeat
  contributes exactly one observable position, which is the trick that makes the
  reduction possible today.

TEMPLATE_ID: equation_discovery_sindy.v0
FIELD: Equation Discovery
KIND: sparse_regression_sindy_v0
QUESTION: Given a measured trajectory of a system, can you recover the small
  handful of terms that actually govern its motion, out of a large library of
  terms that might?
MECHANISM: Measure the state over time and estimate its time derivative
  numerically. Build a library matrix whose columns are candidate functions of
  the state, typically polynomials up to some order plus trigonometric terms.
  The governing equation is then written as derivative equals library times a
  coefficient vector. Solve that overdetermined system by least squares, then
  zero every coefficient whose magnitude falls below a sparsity threshold, then
  refit least squares on the surviving columns only, and iterate. The procedure
  converges to a sparse coefficient vector whose nonzero entries name the active
  terms, and that is the discovered equation.
CANDIDATE: The coefficient vector over the library, that is the model. What
  varies is which library terms survive thresholding. What is judged is the
  residual error together with the number of nonzero terms.
WORLD: A dynamical system that can be observed over time, plus measurement
  noise and a sampling rate. The world supplies the trajectory, and crucially
  also the coordinate system, since the same dynamics in poor coordinates is not
  sparse in any convenient library.
WHAT_CHANGES: The size of the candidate library and the sparsity threshold. Both
  arrived null, and the threshold is the parameter the whole method's behaviour
  hinges on.
MEASURED: Residual error, from 0 upward, and the count of nonzero coefficients,
  a small integer. Only one of the two can be the outcome rule's scalar, which
  is itself a faithful reflection of the method's real difficulty.
INFORMATIVE_FAILURE: Very informative. A run that returns the empty model at
  every threshold says the library does not span the dynamics in these
  coordinates, which is a statement about the coordinate choice and points at
  the fix. A run whose surviving term set changes wildly with the threshold
  reveals collinearity in the library, and the coefficient path across
  thresholds is a durable artifact. The failure mode names its own cause more
  often than not.
SOURCE_CHECK: VERIFIED. Brunton, Proctor and Kutz, Discovering governing
  equations from data by sparse identification of nonlinear dynamics, PNAS 2016,
  is correctly cited and is the origin of SINDy and of the sequentially
  thresholded least squares procedure. Confirmed from established literature
  knowledge; the web search budget was exhausted before this template, but this
  attribution is not in doubt.
SHARED_MECHANISM: fit_model_to_data
ROUTES: R-BACKEND, R-COMPOSE, R-EXECUTOR
BLOCKER: R-BACKEND is blocked on a measurement channel, since no existing result
  field carries a time series and none carries a coefficient vector or a
  residual, so an adapter must both hand a trajectory to an external solver such
  as an existing sparse-regression package and pull residual and term count
  back; R-COMPOSE is blocked on the same missing per-step trace, because
  random_walk_v0 returns only the endpoint and SINDy needs the path; R-EXECUTOR
  is blocked on adjudication as well as measurement, because the honest verdict
  is jointly about residual and sparsity and the outcome rule can compare only
  one of them.
FAITHFUL: A faithful implementation needs a world that emits a sampled
  trajectory with a declared noise level and sampling rate, a declared library,
  a declared threshold, and a result carrying residual, term count and the
  identity of the surviving terms. The surviving-term identity is not optional,
  because a low residual with the wrong terms is the exact failure the rationale
  itself warns about and the residual alone cannot detect it.
REDUCTION: A strong one exists, and it is a NEGATIVE control, which is more
  valuable than a positive demonstration. random_walk_v0 is a real dynamical
  system whose true governing equation has NO deterministic terms at all: the
  increment is zero-mean uniform noise, so the correct SINDy answer is the empty
  model with every coefficient zero. That makes it a perfect false-discovery

  cause, so a failure is not attributable without a separate reachability check.

ROUTES: R-EXECUTOR, R-COMPOSE, R-SUBSTRATE
BLOCKER: R-EXECUTOR is blocked on a measurement capability, namely the absence of
  any structured payload that could carry an expression and of any result field
  carrying prediction error, and this half is genuinely small; R-COMPOSE is
  blocked on adjudication, because selection and recombination between
  generations are downstream analysis the outcome rule cannot express, though the
  producer may legitimately perform them; R-SUBSTRATE is blocked on state, since
  a population carried across generations is output-to-input chaining and one
  spec holds one candidate against one world by construction.
FAITHFUL: A faithful implementation needs a world that emits fitness cases from
  its seed with a planted target function, a declared function and terminal set,
  an evaluator for a serialised expression returning normalised error, and, for
  the search half, a producer that treats one generation as a batch of specs and
  performs selection and variation between batches. The evaluation half is a
  clean fit for a sealed spec; the search half is not, and should not be forced
  into one.
REDUCTION: Two, one immediate and one small. THE IMMEDIATE ONE, running today
  with no bench change, is to build the CONTROL that Koza's central claim is
  measured against. The claim of interest is that evolutionary search beats
  random search at equal budget, and the random-search arm can be measured
  exactly now: fix a candidate, run many independent landscapes under
  sha256_index repeats, and record the distribution of best-of-n score as a
  function of n. Because the scorer is bit-match fraction against a uniform hash
  target, the null is exactly binomial with mean 0.5 and standard deviation 1
  over 2 root L, so the random-search reference curve can be both measured and
  derived, and any disagreement between the two is itself a bench defect worth
  finding. WHAT IT PRESERVES: the comparator, at full fidelity. WHAT IT LOSES:
  the whole evolutionary mechanism, since no tree, no crossover and no
  generation is involved. WHICH CLAIM IT SUPPORTS: the denominator of every later
  GP claim, built before the treatment rather than after, which is the discipline
  this program keeps having to relearn. THE SMALL ONE is to split the executor
  request in half and ask only for the evaluation kind: payload of a serialised
  expression plus a data seed, returning normalised error from 0 to 1, no
  population and no generations. That kind has exactly the shape of
  evaluate_bitstring, is adjudicable by a single scalar comparison, and lets the
  producer run Koza's algorithm with the population loop hoisted outside the
  spec, which has the side benefit that every individual evaluation becomes a
  separately fossilized, seed-replayable record rather than a line in a log.
