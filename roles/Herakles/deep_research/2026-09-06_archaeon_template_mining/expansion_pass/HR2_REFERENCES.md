# H-R2 REFERENCE VERIFICATION

Task: verify twelve academic references by FETCHING sources.
Date: 2026-09-08. Verifier: Herakles reference audit seat.

METHOD AND ITS LIMITS
The WebSearch budget for this session was already exhausted at the
first call, so every item below was established through WebFetch
against bibliographic APIs and publisher or author hosted files:
Crossref REST, OpenAlex, Semantic Scholar Graph, Europe PMC, plus
direct PDF retrieval where a copy was reachable. Five sources were
read in full text from a fetched PDF. Two sources are closed access
with no deposited abstract anywhere reachable; those are graded
PARTIAL and say so in field 2. Nothing here is written from recall.
Where a fact could not be fetched it is marked NOT VERIFIED rather
than filled in.

Grade meanings used below:
VERIFIED  - source, version and defining content all fetched.
PARTIAL   - bibliography fetched and confirmed, but either the
            defining passage could not be read, or the record is
            imprecise about which paper in a series it names.
MISMATCH  - the cited work does not define what the template says.
RECALLED  - could not be fetched at all. None were graded this way.

## 1. cegar.abstraction.loop  -> kind cegar_loop_v0

1. EXACT SOURCE AND VERSION
Edmund M. Clarke, Orna Grumberg, Somesh Jha, Yuan Lu, Helmut Veith.
"Counterexample-Guided Abstraction Refinement." In Computer Aided
Verification, CAV 2000, Lecture Notes in Computer Science, Springer,
2000, pages 154-169. DOI 10.1007/10722167_15.
Also available as CMU technical report CMU-CS-00-103.
An extended journal version exists and is the one most often cited
in the synthesis literature: "Counterexample-guided abstraction
refinement for symbolic model checking", Journal of the ACM 50(5),
2003, pages 752-794, DOI 10.1145/876638.876643, same five authors.
Confirmed via Crossref, OpenAlex, and the CMU PDF itself.

2. THE PASSAGE OR ALGORITHM
Read in full from the CMU hosted PDF at aladdin.cs.cmu.edu. The
paper's own Abstract states it presents "an automatic iterative
abstraction-refinement methodology in which the initial abstract
model is generated by an automatic analysis of the control
structures in the program to be verified", that abstract models
"may admit erroneous or spurious counterexamples", and that the
authors devise symbolic techniques that "analyze such
counterexamples and refine the abstract model correspondingly".
Section 1 states the loop directly: model check the abstraction,
test whether an abstract counterexample is spurious, report it and
stop if it is not spurious, and otherwise refine the abstraction
function so the spurious counterexample is eliminated. The paper
targets ACTL specifications and is implemented in NuSMV.

3. THE CLAIM SUPPORTED
That an abstraction of a finite state model can be built and then
automatically refined using spurious counterexamples, giving sound
model checking of universal-path properties at a state space far
smaller than the concrete design; demonstrated on a Fujitsu IP core
of about 500 latches.

4. ANY MISMATCH
The attribution is to the right authors, right title, right year,
and right conference. Two cautions, neither of them a wrong-paper
error. First, the record's bare string "Clarke et al 2000" points at
the CAV conference paper while much downstream work, including
Solar-Lezama's dissertation which the next entry rests on, cites the
2003 JACM version; the record should say which. Second, the
template's own operationalisation does not follow the paper: the
paper's abstractions are abstraction functions that partition the
domains of program variables into many degrees of abstraction, while
the template payload is a pair of fixed eight-bit strings named
initial_abstraction_bits and property_bits. That is a toy stand-in,
not the construct the paper defines. The reference is sound; the
template's parameterisation is not traceable to it.

GRADE: VERIFIED
Justification: full text of the cited paper was fetched and read,
and it does define the counterexample-guided abstraction refinement
loop the template names.

## 2. cegis_boolean  -> kind bounded_synthesizer.v0

1. EXACT SOURCE AND VERSION
Armando Solar-Lezama. "Program Synthesis by Sketching." PhD
dissertation, University of California, Berkeley, Fall 2008.
Committee: Rastislav Bodik chair, Sanjit Seshia, Leo Harrington.
Read in full from the author's MIT copy at
people.csail.mit.edu/asolar/papers/thesis.pdf.
The dissertation is also commonly cited as UC Berkeley EECS
technical report EECS-2008-177; that report number could NOT be
verified, because both Berkeley tech report URLs returned 404, so
the number is left unasserted here.
The earlier sketching paper is: Armando Solar-Lezama, Liviu Tancau,
Rastislav Bodik, Sanjit A. Seshia, Vijay Saraswat. "Combinatorial
sketching for finite programs." ASPLOS XII, 2006, pages 404-415,
DOI 10.1145/1168857.1168907. Confirmed via OpenAlex and Semantic
Scholar; the same paper was reprinted in four ACM newsletters, which
is why several near-duplicate DOIs exist for it.

2. THE PASSAGE OR ALGORITHM
The dissertation names and defines CEGIS. Its Abstract says the
SAT-based inductive synthesis procedure "forms the core of a new
counterexample guided inductive synthesis procedure, CEGIS, which
combines the inductive synthesizer with a validation procedure".
Chapter 4 is titled "Counterexample Guided Inductive Synthesis".
Section 4.1 says plainly: "The sketch synthesizer we developed uses
this apparent limitation to its advantage in a technique we have
named counterexample guided inductive synthesis, or CEGIS." Figure
4.1 is captioned "Counterexample driven synthesis algorithm."
Section 4.2 gives the formal statement as "Algorithm 1, CEGIS
Algorithm", with the inductive synthesis phase producing a candidate
from an input set E and the validation phase returning a concrete
failing input that is added to E.

3. THE CLAIM SUPPORTED
That a sketch, a partial program with holes, can be completed
automatically by alternating a SAT-based inductive synthesizer over
a small set of inputs with an external validation procedure that
supplies counterexample inputs, converging in a handful of
iterations even for astronomically large candidate spaces.

4. ANY MISMATCH
The prior reviewer's flag is NOT sustained. CEGIS is coined and
formalised in the 2008 dissertation, not in the 2006 ASPLOS
sketching paper. The ASPLOS 2006 abstract, fetched from Semantic
Scholar, describes SKETCH and combinatorial search using generalized
boolean satisfiability and contains no counterexample loop and no
such acronym. The dissertation does not even cite the ASPLOS paper
in its bibliography; its own Solar-Lezama entries are PLDI 2005,
PLDI 2007 and PLDI 2008. So the record's attribution is correct.
Two refinements the record should carry. First, the citation should
say the source is a PhD dissertation at UC Berkeley, since a bare
"Solar-Lezama 2008" reads as a paper. Second, the dissertation
itself credits the idea's ancestry to CEGAR, entry 1 above, citing
it as the JACM 2003 version; the two records are therefore linked
and should be kept consistent.
Separately, the template is unusable as written: both payload axes,
max_iterations and sketch_size, have null ranges.

GRADE: VERIFIED
Justification: the dissertation's own text naming and formalising
CEGIS was fetched and read, which settles the reviewer's question
against the ASPLOS attribution.

## 3. query_by_committee  -> kind query_by_committee_v0

1. EXACT SOURCE AND VERSION
H. S. Seung, M. Opper, H. Sompolinsky. "Query by committee."
Proceedings of the Fifth Annual Workshop on Computational Learning
Theory, COLT '92, ACM, 1992, pages 287-294.
DOI 10.1145/130385.130417. Confirmed via Crossref and OpenAlex.
The later practical and PAC-style treatment is a different paper:
Yoav Freund, H. Sebastian Seung, Eli Shamir, Naftali Tishby,
"Selective Sampling Using the Query by Committee Algorithm",
Machine Learning 28(2-3), 1997, pages 133-168,
DOI 10.1023/a:1007330508534.

2. THE PASSAGE OR ALGORITHM
Read from the abstract deposited in OpenAlex, verbatim: "We propose
an algorithm called query by committee, in which a committee of
students is trained on the same data set. The next query is chosen
according to principle of maximal disagreement. The algorithm is
studied for two toy models: the high-low game and perceptron
learning another perceptron." The full text was not reachable; the
paper is behind the ACM paywall and no open copy was found. Section
level detail is therefore NOT VERIFIED.

3. THE CLAIM SUPPORTED
That selecting the next query by maximal disagreement among a
committee yields asymptotically finite information gain per query,
so generalization error falls exponentially in the number of
examples, in contrast to the inverse power law obtained from
randomly chosen inputs.

4. ANY MISMATCH
Right paper for the name and for the maximal-disagreement query
rule. But the 1992 paper is a statistical-mechanics analysis of two
toy models, and the template is built on axes the paper does not
provide: committee_size as a swept integer, and a query_budget with
a "target error threshold" verdict. The 1992 result is asymptotic,
in the limit of infinitely many queries, and the committees analysed
are drawn from the Gibbs distribution over version space rather than
sized by a tunable parameter. A template that sweeps committee size
against a finite labelling budget and reads a target error is much
closer to Freund, Seung, Shamir and Tishby 1997 than to Seung,
Opper and Sompolinsky 1992. This is not a wrong-paper attribution,
but the record is citing the origin of the name while the template
implements the descendant. Both payload axes are also null.

GRADE: PARTIAL
Justification: bibliography and the paper's own abstract were
fetched and confirm the method's origin, but the full text could not
be read and the template's finite-budget, swept-committee framing
tracks the 1997 follow-up rather than the cited 1992 paper.

## 4. version_space_search  -> kind version_space_search_v0

1. EXACT SOURCE AND VERSION
Tom M. Mitchell. "Version Spaces: A Candidate Elimination Approach
to Rule Learning." Proceedings of the Fifth International Joint
Conference on Artificial Intelligence, IJCAI-77, volume 1, 1977,
pages 305-310. No DOI. Affiliation on the paper: Heuristic
Programming Project, Department of Computer Science, Stanford
University. Read in full from the IJCAI proceedings PDF at
ijcai.org/Proceedings/77-1/Papers/048.pdf, cross-checked against
OpenAlex.

2. THE PASSAGE OR ALGORITHM
The paper's own Abstract describes "an approach ... guaranteed to
find, without backtracking, all rule versions consistent with a set
of positive and negative training instances", using "a
representation of the space of those rules consistent with the
observed training data", modified per instance "by eliminating
candidate rule versions found to conflict with each new instance".
Section 2, "Version Spaces", defines the rule version space of the
positive set and the negative set as the set of all rules consistent
with both, and gives the compact representation: a general-to-
specific ordering on the pattern space lets the version space be
represented by its extremal sets, called in this paper the
maximally general versions MGV and the maximally specific versions
MSV. Figure 1 is captioned "A Version Space Represented by it's
Extremal Sets". The worked application is Meta-DENDRAL, learning
rules for carbon-13 NMR spectroscopy.

3. THE CLAIM SUPPORTED
That the set of all hypotheses consistent with the data can be
represented finitely by two boundary sets and updated incrementally
by elimination, with no backtracking and no re-examination of past
instances, and that this is workable in a real rule-learning system.

4. ANY MISMATCH
Correct paper, correct year, correct venue, correct title. Two
precision notes. First, this 1977 paper calls the boundary sets MGV
and MSV; the now-standard S and G notation comes from Mitchell's
later work, so any implementation commentary that says "the S set
and G set as defined in Mitchell 1977" is quoting the wrong
vintage. Second, the template's SURVIVED condition is "the version
space size dropping to exactly one", a cardinality counter; the
paper's whole representational point is that the version space is
held as its two extremal sets precisely because enumerating members
can be intractable or infinite. Counting members is not what the
cited algorithm does, though convergence to a single hypothesis is
within its scope. Both payload axes are also null.

GRADE: VERIFIED
Justification: the full text of the exact cited paper was fetched
and it does define both the version space and the candidate
elimination procedure the template names.

## 6. evodevo.bias  -> kind boolean_network.v0

1. EXACT SOURCE AND VERSION
Sean Psujek and Randall D. Beer. "Developmental bias in evolution:
evolutionary accessibility of phenotypes in a model evo-devo
system." Evolution and Development, volume 10, issue 3, 2008,
pages 375-390. DOI 10.1111/j.1525-142X.2008.00245.x. PMID 18460098.
Affiliations on the paper: Psujek, Department of Biology, Case
Western Reserve University; Beer, Cognitive Science Program,
Department of Computer Science and Department of Informatics,
Indiana University. Confirmed via OpenAlex, Semantic Scholar and
Europe PMC, and the full text PDF was fetched from Beer's own
publications page at rdbeer.pages.iu.edu and read.

2. THE PASSAGE OR ALGORITHM
Read in full. The model is defined in the section headed "The
developmental model" and summarised in the section beginning "In
summary, our model of neural development proceeds through three
stages", with Figures 2, 3, 4 and 5. What it actually is:
- A genome of eight or nine genes, each a fixed string of 57 bases
  over a two-letter alphabet written as A and C. Each gene has a
  regulatory section, containing two repression sites, two
  activation sites and a threshold region, and a coding section
  encoding one of four protein types plus a modifier region.
- A fixed planar grid of cells whose number and positions never
  change. Development is seeded by inserting one symmetry-breaking
  transcription factor into a single cell.
- Extracellular signalling proteins spread by a static exponential
  decay function, and genes respond at up to seven concentration
  thresholds. This is a chemoaffinity and morphogen-gradient model
  in the Sperry tradition, implemented in Mathematica.
- The phenotype is the resulting connectivity matrix of a three
  neuron circuit; with six possible directed connections there are
  64 possible phenotypes. Twenty million random genotypes produced
  only 27 of them.
The paper contains no occurrence of "Boolean network", no
occurrence of "CTRNN" or "continuous-time recurrent neural
network", and no citation to Kauffman anywhere in its reference
list. The words "steady state" appear once, describing gene
expression ceasing during the differentiation window, and the
authors explicitly say they did not need an equilibrium detection
function and simply capped the number of time steps.

3. THE CLAIM SUPPORTED
That a developmental process mapping genotypes to neural
connectivity produces a strongly non-uniform distribution of
phenotypes under uniform single-base mutation; that this bias is
both intrinsic to the system, called global bias, and dependent on
the particular genotype, called local bias; and that the bias
differs even among phenotypically neutral genotypes producing the
same circuit.

4. ANY MISMATCH
MISMATCH, and on two separate counts.
First, against the template. The cited work does not define a
Boolean network, so kind boolean_network.v0 has no basis in it. The
template's rationale says it "evaluates a Boolean network as a
developmental map from an initial state genotype to a steady-state
attractor phenotype" and measures "attractor basin size". The paper
measures none of that. Its genotype is a base string, not an initial
network state; its phenotype is a connectivity matrix read off at a
fixed time cap, not an attractor; and it reports the frequency of
each phenotype over mutational neighbourhoods, not basin sizes of a
dynamical system. There is also no connectivity_k parameter to set:
regulatory wiring emerges from sequence matching, not from a fixed
in-degree. The template's payload of connectivity_k equal to two and
num_nodes of ten or twenty corresponds to nothing in the paper,
whose circuits have three neurons and whose genomes have eight or
nine genes.
Second, against the prior reviewer. The reviewer's stated basis for
retirement, that the model is a CTRNN, is also wrong for this paper.
Beer's better-known work does use continuous-time recurrent neural
networks, but this 2008 paper's model is a discrete gene-regulatory
and chemoaffinity developmental model with no neural dynamics
simulated at all. The right conclusion is still to retire the
template's kind, but the recorded reason must be corrected, or the
next reader will inherit a second false fact.

GRADE: MISMATCH
Justification: the full text was read and the cited paper defines
neither a Boolean network nor an attractor measurement, so the
template's kind and its measured quantity are both unsupported by
the work it names.

## 8. mil_predicate_invention  -> kind metagol_induce.v0

1. EXACT SOURCE AND VERSION
The record string is "Muggleton et al. 2015 Metagol". Two distinct
papers carry the identical title, and the record names the later
one.
Primary conference paper: Stephen Muggleton and Dianhuan Lin, both
Imperial College London, two authors only. "Meta-Interpretive
Learning of Higher-Order Dyadic Datalog: Predicate Invention
Revisited." Proceedings of the Twenty-Third International Joint
Conference on Artificial Intelligence, IJCAI-13, 2013, pages
1551-1557. Read in full from the IJCAI proceedings PDF.
Extended journal version: Stephen H. Muggleton, Dianhuan Lin and
Alireza Tamaddoni-Nezhad, three authors. "Meta-interpretive
learning of higher-order dyadic datalog: predicate invention
revisited." Machine Learning, volume 100, issue 1, 2015, pages
49-73. DOI 10.1007/s10994-014-5471-y. Bibliography confirmed via
Crossref and OpenAlex; the full text could not be read because
Springer redirects to an identity provider, so the journal version's
own wording is NOT VERIFIED.

2. THE PASSAGE OR ALGORITHM
Read in full from the IJCAI-13 version. Its Abstract states that
"New predicate symbols are introduced as constants representing
existentially quantified higher-order variables", and that the work
generalises Meta-Interpretive Learning, MIL, to learning higher-
order dyadic datalog programs. The implemented system is named
MetagolD, described in Section 3, with Section 2 giving the MIL
framework, Section 4 the experiments on robot strategies and on
NELL, and Section 5 related work. MetagolD is implemented in Yap
Prolog as a modified meta-interpreter and uses iterative deepening
so the first hypothesis returned has the minimal number of clauses.
A footnote in the paper records the naming convention explicitly:
MetagolR and MetagolCF learn regular and context-free grammars,
MetagolD learns dyadic datalog programs.

3. THE CLAIM SUPPORTED
That predicate invention can be performed efficiently inside a
meta-interpretive learner by treating new predicate symbols as
constants that instantiate existentially quantified higher-order
variables in metarules; that the higher-order dyadic datalog class
H22 has universal Turing expressivity with an infinite signature and
is decidable with a finite one; and that Knuth-Bendix ordering plus
logarithmic clause bounding lets MetagolD PAC-learn minimal
cardinality H22 definitions.

4. ANY MISMATCH
Two problems with the record as written.
First, the system name. There is no system simply called "Metagol"
in the cited work. The paper's footnote names a family: MetagolR,
MetagolCF and MetagolD, and the system that does the predicate
invention the template wants is MetagolD. The record's bare
"Metagol" label is imprecise, and the kind metagol_induce.v0
inherits that imprecision.
Second, which paper in the series. The 2015 Machine Learning article
is the extended version of the 2013 IJCAI paper of the same title,
which is the primary source and which already names MetagolD and
already defines predicate invention through existentially quantified
higher-order variables. Citing 2015 is defensible for the fuller
treatment but it is not the first appearance, and the record gives
no way to tell the two apart since the titles are identical. The
record should carry both, or carry IJCAI-13 as primary.
Note also that the "Metagol" name itself predates both, arising in
the grammar-inference line of MIL work, which this audit did not
fetch and therefore does not assert.
The template's max_clauses axis is null, matching the paper's
iterative-deepening clause bound only in spirit.

GRADE: PARTIAL
Justification: the method and system were verified from the full
text of the primary IJCAI-13 paper, but the record names the wrong
paper in the series as primary and mislabels the system as Metagol
rather than MetagolD, and the 2015 journal text itself was not
readable.

That two populations, each gated only by its own minimal criterion

GRADE: VERIFIED

minimal-criterion mechanism the template names, though only the
