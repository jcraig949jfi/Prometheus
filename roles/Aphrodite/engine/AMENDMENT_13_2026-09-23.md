# LOCAL ENGINE AMENDMENT 13 -- S2: FAIR META-SELECTION BY COMMON RANDOM
# NUMBERS. FROZEN AND COMMITTED BEFORE ANY S2 CODE IS WRITTEN OR RUN.

Dated 2026-09-23. Second step of the ordered sequence (operator ruling
2026-09-23: proceed through S1..S4 behind declared gates without returning
while gates pass). S1 status at freeze: recorded in the commit that carries
this amendment. Campaign 1 remains FROZEN and UNRUN.

--------------------------------------------------------------------------
0. THE DEFECT
--------------------------------------------------------------------------

Tier 3C scored two libraries with BYTE-IDENTICAL CONTENT at 13,479 and 51,018
charges, because each arm's search order was shuffled by an RNG seeded with a
string containing the library's NAME. The donor's choice between `memorise`
and `abstract` therefore measured the RNG, not the library. Recipients in the
transplant stage were seeded the same way ("T3C-<family>-<arm>-<i>"), so arm
comparisons also carried arm-specific order noise.

--------------------------------------------------------------------------
1. KEYED ORDER (common random numbers)
--------------------------------------------------------------------------

Every ordered list the search walks -- each library entry's inits, bodies and
finals, and the G4 fallback's finals, inits and bodies -- is ordered by a
KEY that depends only on (cell seed, slot, item):

    key(seed, slot, item) = sha256("APHRODITE/S2/ORDER/v1/<seed>/<slot>/<item>")

sorted ascending. `item` is the exact expression string. The key never sees
the library, its name, its entries, its position in a list of candidates, or
the arm. Consequences, by construction:
  - byte-identical libraries walk identical candidate sequences;
  - two items shared by two libraries appear in the same RELATIVE order in
    both;
  - reordering an entry's lists does not change what is searched or in what
    order.
Entry order within a library remains CONTENT (the donor decides priority);
entries are walked in their listed order, then the fallback. Charging is
unchanged: one charge per candidate evaluated.

--------------------------------------------------------------------------
2. PAIRED CELLS
--------------------------------------------------------------------------

A CELL is (family, replicate r). Its development set is
tasks(family, qualified size, dev_entropy("S2-cell/<family>", r)) and its
order seed is search_entropy("S2-cell/<family>/<r>"). Neither contains the
library or the arm. Every candidate library in a meta-selection, and every
arm in a transplant, is evaluated on the SAME cells. Cost per cell is the
censored charge count (escrow if unsolved).

Replicates: R = 8 per validate family in meta-selection (Tier 3C used 3).

--------------------------------------------------------------------------
3. THE SELECTION RULE (frozen)
--------------------------------------------------------------------------

For each candidate library L, d_L = the per-cell paired difference
cost(PRISTINE) - cost(L) over all validate cells. L is ELIGIBLE if the
one-sided 95% lower bound of mean(d_L) is > 0 (mean - 1.645 * SE, SE over
cells). The donor selects the eligible library with the largest mean(d_L);
ties broken by smaller library size, then by sha256. If no library is
eligible the donor selects PRISTINE: no inherited change.

--------------------------------------------------------------------------
4. THE S2 GATE -- ALL MUST HOLD BEFORE S2 PASSES
--------------------------------------------------------------------------

  G-S2.1 IDENTICAL CONTENT: two libraries with identical entries but
    different names score identically on every cell. The Tier-3C case
    (memorise and abstract with no schema formed) is rebuilt from the Tier-3C
    artifact and must score identically.
  G-S2.2 ORDER INVARIANCE: permuting every entry's lists leaves every cell's
    cost unchanged.
  G-S2.3 ARM INVARIANCE: a recipient's cost for a given library does not
    depend on the arm label under which it is run.
  G-S2.4 CHARGE CONSERVATION: for a fixed candidate sequence, charges equal
    the 1-based position of the first accepted candidate (or the escrow),
    checked against a direct enumeration on sampled cells.
  G-S2.5 PAIRING IS INFORMATIVE: reported, not thresholded -- the variance of
    paired differences versus the variance of unpaired differences for
    PRISTINE vs one other library on the same cells.
  G-S2.6 CONFORMANCE (G1) GREEN, and the S1 identity layer unchanged.

S2_PASS if G-S2.1..4 and 6 hold. Otherwise S2_FAIL, reported against this
gate, and the seat returns to the operator.

--------------------------------------------------------------------------
5. SCOPE
--------------------------------------------------------------------------

S2 changes ONLY how order is randomised and how cells are paired. It does not
add families, schemas or operators, and re-scores no earlier result. The keyed
order is used by every later step (S3 meta-selection and S4 transplant).
