# surrogate adjudication)

Dated 2026-09-21, applying the operator's SLICE 2C ruling. Campaign 1
remains frozen and unrun; Tier 3 remains forbidden and is not
self-authorized. Slice 2B's 0/16 is preserved as GRAMMAR_INCOMPLETE and

OUTCOME: the slice STOPS AT THE REACHABILITY GATE. No evolutionary

1. GRAMMAR v2 -- the authorised repair, versioned and hashed separately
--------------------------------------------------------------------------

    slice 2B    GRAMMAR_V1_VERSION = "v1-frontier-asymmetric"   (retained,
                unused by 2C, kept only to reproduce the 0/16 result)
    slice 2C    GRAMMAR_VERSION    = "v2-size-indexed-symmetric"
                grammar_hash        713195e32926e538e2cebb9831359782
                                    854e20f29c227c3fbdd2f1f3f6849d16
                MAX_SIZE = 4 operator applications; terminals are size 0

v1 built each round as op(LEFT from the previous frontier, RIGHT from the
pool), which can never construct op(terminal, deep). v2 enumerates BY
SIZE: for size s, every split (i, j) with i + j = s - 1, in BOTH
directions. The primitive set, task distribution, tribunal and per-attempt
budget are otherwise unchanged.

TWO REPAIRS APPLIED, both declared here rather than buried:
  (a) the repair was extended to EVERY call site of the enumerator. In
      slice 2B the structural search still called the v1 asymmetric
      enumerator, so the repair would have been cosmetic.
  (b) HELPER_CANDIDATE_CAP was 40, an arbitrary truncation this seat
      introduced in slice 2B. The declared helper space (update
      expressions of depth <= 2 over {x, y}) contains 48 distinct helpers
      on two development instances, and EUCLID IS RANK 44. A cap of 40
      silently excluded the only structural witness for numtheory. The
      cap is raised to 1024, i.e. "enumerate the declared space", which
      restores the space rather than enlarging it: the full enumeration
      costs ~3.5M candidate charges, measured below.
Reviewers should weigh (b) carefully: removing a truncation after seeing
it exclude the witness is adjacent to tuning for yield. The defence is
that the truncation was never part of any declared grammar, that the
space it truncated was declared, and that the change is recorded here
with its effect stated before any lineage ran.

--------------------------------------------------------------------------
3. STRUCTURAL ADJUDICATION -- descriptive C6 RETIRED
--------------------------------------------------------------------------

Presence, invocation, looping, AST depth and helper count are TELEMETRY
ONLY (engine.structural_telemetry). A structural component is credited as
LOAD-BEARING only if no substantially simpler causal surrogate preserves
the claimed capability under evaluation. The battery
(engine.surrogate_battery):

    constant outputs         h -> 0, h -> 1
    identity / passthrough   h -> x, h -> y
    trivial expressions      h -> every single primitive application over
                             {x, y}: 28 surrogates
    simplified control flow  loop bound reduced to a single iteration
    removal / bypass         covered by identity and constant surrogates

If ANY surrogate preserves capability, the original structure is not
credited. The search receives no feedback from this adjudication, and it
runs only after the generation-8 freeze.

The slice-2B decorative-loop fossil is preserved as a PERMANENT
REGRESSION FIXTURE and is now adjudicated by the battery rather than by
the retired descriptive criterion.

--------------------------------------------------------------------------
4. THE SLICE STOPS HERE, AND WHY
--------------------------------------------------------------------------

The ruling's objective is to determine whether the process can discover a
load-bearing structural mechanism "when such a mechanism is demonstrably
reachable inside the declared search space". Before running lineages this
seat therefore certified not just reachability but LOAD-BEARING
reachability, by enumerating every helper that enables an exact solution
and subjecting each to the battery:

    structural_success_criterion_satisfiable = FALSE

    class      enabling helpers  load-bearing witnesses
    numtheory         4                  0
    modexp            1                  0

The decisive rows:
  - h = (y | x % y) -- EUCLID, a genuine bounded loop, discovered not
    handed -- solves numtheory at accuracy 1.000 and is DEFEATED BY the
    surrogate expr_gcd(x, y);
  - h = (x*y | x - x) -- a one-iteration product -- solves numtheory at
    1.000 and is defeated by expr_mul(x, y) AND by single_iteration.

THE FINDING: structure can only be load-bearing RELATIVE TO A PRIMITIVE
SET. `gcd` and `pow` are primitives in this grammar, and every capability
class in the declared distribution is one primitive application away from
solved. Any structural mechanism that computes them is therefore
redundant by construction, and the battery correctly refuses to credit
it. No qualifying artifact can exist in this grammar, at any lineage
count, under any entropy.

Running 16 lineages would have produced a second 0/16 whose cause was
already established analytically. The ruling's gate -- "if any
load-bearing class is unreachable, stop before evolutionary search" --
applies in substance, so the slice stops.

WHAT WAS NOT DONE, DELIBERATELY: `gcd` and `pow` were NOT removed from
the primitive set to manufacture a necessity for structure. That would
alter the declared primitive set to produce the result the slice was
hoping for, which is the same move in the opposite direction.

6. RECOMMENDATION (not executed)
--------------------------------------------------------------------------

The next rung the ruling names -- isolation and transplantation of a
discovered structural component -- is NOT recommended yet, because no
structural component can currently be credited.

What would make the question askable is a PRIMITIVE-SET / TASK CO-DESIGN
decision, which belongs to the operator:
  - a capability class whose solution is NOT one primitive application
    away, so that structure is necessary rather than redundant (for
    example a class requiring iteration to a fixed point, accumulation
    over a variable-length input, or a decision procedure with branching
    that no single primitive expresses); with
  - a primitive set that does not already contain that operation.
This is a design question about what "algorithmic discovery" is being
claimed RELATIVE TO. It is the same question in miniature that any claim
about a model discovering an algorithm has to answer, since a base model
that can already do X in one step makes any scaffolding that does X
decorative.
