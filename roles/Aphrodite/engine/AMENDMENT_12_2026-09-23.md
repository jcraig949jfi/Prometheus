--------------------------------------------------------------------------
0. WHAT S1 IS FOR
--------------------------------------------------------------------------

Tier 3C's donor observed body `acc - v*v` with final `first - acc` where the
family's witness is body `acc + v*v` with final `acc + first`. The two are the
same program: one accumulates the negative sum and negates at the end. Tier
3A's donor did the same thing (`acc - v*v`, `last - acc`). Body-level identity
(AMENDMENT 10 s1) cannot see this, because the body is not an invariant unit
(INVARIANT 5): its form depends on its partner.

S1 makes the identity of a program a property of the WHOLE executable program.
It does NOT form abstractions, choose representatives for abstraction, or
change any search, library or arm. It supplies the identity layer that S3 will
abstract over, and a gate showing that the layer is sound.

--------------------------------------------------------------------------
1. THE SEMANTIC OBJECT
--------------------------------------------------------------------------

The object is the WHOLE EXECUTABLE PROGRAM together with its input
convention:

    ('fold', init, body, final)   or   ('expr', final)
    convention: TRAILING (the last prompt integer is the query parameter,
                `last`, and is excluded from the fold) or PLAIN

exactly as basis_v4.run_program executes it. The body and final are never
identified independently of each other or of the init.

--------------------------------------------------------------------------
2. THREE IDENTITIES, ALL RETAINED
--------------------------------------------------------------------------

  source_id     sha256 of the exact evolved representation (the program tuple
                as recorded, sorted JSON) plus the convention. Provenance and
                ancestry. Never mechanism identity.

  structure_id  sha256 of a canonical STRUCTURAL form obtained by the safe
                rewrites of section 3 only. Genotype-level deduplication and
                display. Never mechanism identity.

  behavior_id   sha256 of the program's WHOLE-PROGRAM DENOTATION over the
                frozen primary battery of section 4 under the declared domain.
                This is the mechanism identity.

A record carries all three plus the original source and the structural form.
Two programs sharing a behavior_id keep their own source and structural forms:
genotype and phenotype are separate evidence and neither is overwritten.

REFINEMENT REQUIREMENT: equal structure_id must imply equal behavior_id. The
converse is not required and is not expected -- the Tier-3C pair must share a
behavior_id and must NOT share a structure_id, because no structural rule may
be what collapses it (section 5).

--------------------------------------------------------------------------
3. SAFE STRUCTURAL REWRITES (the complete list)
--------------------------------------------------------------------------

A rewrite is admitted only if it preserves the DSL value AND the DSL failure
disposition of every input, under the declared semantics: Python integer
arithmetic; fdiv and mod FAIL on a zero divisor; floor division and modulo
take Python's signs; gcd(a, b) = math.gcd(|a|, |b|); guarded pow returns 0
for an exponent outside [0, 32]; the 10^40 ceiling is checked on the
accumulator after every body step and on the output, and never inside an
expression.

  R1 canonical primitive names: math.gcd(abs(a), abs(b)) -> gcd(a, b);
     pow(a, b) -> powr(a, b).
  R2 commutative operand ordering for add, mul, gcd. Both operands are always
     evaluated, so a failure in either is a failure of the whole regardless
     of order.
  R3 neutral elements, exact for every integer and failure-preserving because
     x is still evaluated: add(x, 0) -> x; sub(x, 0) -> x; mul(x, 1) -> x;
     fdiv(x, 1) -> x; powr(x, 1) -> x.
  R4 absorbing and cancelling forms, ADMITTED ONLY WHEN x IS TOTAL, i.e.
     contains no fdiv and no mod: mul(x, 0) -> 0; sub(x, x) -> 0;
     mod(x, 1) -> 0; powr(x, 0) -> 1.

Explicitly NOT admitted, because each changes a value or a failure somewhere
in the declared domain: x // x -> 1 and x % x -> 0 (fail at x = 0);
gcd(x, x) -> x (it is |x|); dropping abs outside gcd; any rewrite that moves
an operation across the accumulator (sign, offset or scale conjugation),
because an offset or scale changes where the ceiling is crossed.

AMENDMENT 10's canonical_form admitted x // x -> 1, x % x -> 0 and
gcd(x, x) -> x. semantics.py is left UNCHANGED so that Tiers 3B and 3C remain
reproducible; the S1 layer is a new module and does not import those rules.

--------------------------------------------------------------------------
4. BEHAVIOR: DOMAIN, PRIMARY BATTERY, AUDIT BATTERY
--------------------------------------------------------------------------

DECLARED DOMAIN D (version D_NONNEG_v1): every prompt integer is a
NON-NEGATIVE integer of any magnitude; the fold sequence has length >= 1.
Reason: every declared instance generator in this program (basis_v4, tier3b,
tier3c) emits prompts whose integers are all >= 2, and no declared prompt
template contains a minus sign. D contains that support and extends it
conservatively to 0, 1 and values beyond the ceiling, so it can only SPLIT
classes relative to the generators' support, never merge them. The
accumulator is NOT restricted: it may take any value the program produces,
including negatives. (AMENDMENT 10 probed bodies with non-negative
accumulators only; that is why its body classes merged `v + |acc|` with
`v + acc`. Whole-program evaluation removes the restriction.)

A SENSITIVITY signature over a battery that also contains NEGATIVE prompt
integers is computed and reported for every fixture. It never decides
identity. Collapses that depend on non-negativity are listed by name.

BEHAVIOR VALUE of a program on an input is exactly basis_v4.run_program's
return value, with None (failure or ceiling) recorded as the distinct token
FAIL. There is therefore no second implementation of the DSL inside the
identity layer: behavior is computed by the SAME evaluator the search uses,
which the conformance gate ties to the emitted artifact.

PRIMARY BATTERY B1 (frozen here, generated by a declared deterministic
procedure; its sha256 is recorded with every behavior_id):
  a. small-value grid: lengths 1, 2, 3, 4, 6, sequence values from
     {0, 1, 2, 3, 5, 7, 12, 30, 97} under a frozen seed, including all-zero,
     all-one, zero-first and zero-last sequences; query parameter from
     {0, 1, 2, 3, 7, 32, 33, 97};
  b. exponent-guard band: values 31, 32, 33, 34 in both sequence and query
     position against bases 0, 1, 2, 3;
  c. ceiling band: values C-97, C-30, C-2, C-1, C, C+1, C//2, C//2+1,
     10^20, 10^20+1, 10^13, 3*10^13 (C = 10^40) in sequences of length 1-3
     with small partners, query parameter from {1, 2, 7, 97};
  d. length band: lengths 9, 20 and 60 with values in [0, 30] under a frozen
     seed, and one sequence of 200 copies of 29.
The seed is sha256("APHRODITE/S1/B1/v1"). B1 contains no input chosen by
looking at any fixture program's behavior.

AUDIT BATTERY B2 (frozen here; independent seed sha256("APHRODITE/S1/B2/v1")):
5,000 inputs, lengths 1-60 (geometric, mean 8), each value drawn from a
mixture: uniform [0, 40] (50%), uniform [0, 10^6] (15%), C + uniform[-200, 200]
clipped at 0 (10%), C//k + uniform[-50, 50] for k in 2..5 (10%),
10^20 + uniform[-50, 50] (5%), uniform [28, 36] (10%). B2 NEVER contributes to
a behavior_id. It exists only to catch false merges by B1.

WHAT behavior_id CLAIMS. Equal behavior_id means observational equivalence on
B1 under D, CONFIRMED on B2. It is a tested equivalence, not a proof; the gate
of section 6 measures how often B1 would merge what B2 separates, and requires
zero.
