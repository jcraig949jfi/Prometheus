# AMENDMENT 2 to PREREG_C1_TRANSPLANT_2026-09-19 (frozen design + PATCH 1)

Dated 2026-09-21. Written and committed BEFORE the distribution it
declares was measured, and before any Campaign 1 cell has ever been run.
Supersedes prompts/2026-09-21_local_engine/AMENDMENT_2_DRAFT.md, which
posed three options; the operator ruled, and the ruling is not the
option this seat leaned toward.

Nothing in this amendment changes the Campaign 1 endpoint, the primary
estimand D_VAULT, the artifact boundary, the positional generation-8
extraction, the qualification envelope E1-E6, or any statistic. It
changes (A) the substrate-eligibility rule and (B) what a Campaign 1
report is required to label.

--------------------------------------------------------------------------
A. THE REPLACEMENT ELIGIBILITY RULE (operator ruling, 2026-09-21)
--------------------------------------------------------------------------

The frozen rule selected "the fastest measured model whose frozen
starting accuracy on the Campaign 1 task distribution lies between 15%
and 70%". That rule assumed a quasi-continuous competence metric. On a
discrete multi-family substrate the assumption is false: with four
independently solved families the only reachable starting accuracies are
0.00, 0.25, 0.50, 0.75, 1.00. This is an INSTRUMENT-MODEL MISMATCH, not
an inconvenient result, and it is repaired by generalising the rule
rather than by writing an exception around the substrate that exposed it.

REPLACEMENT. A substrate is eligible only if:
  R1 the baseline leaves measurable unsolved capability;
  R2 a known transferable positive control produces >= delta improvement;
  R3 the score has sufficient resolution to distinguish delta-scale
     effects;
  R4 improvement cannot be achieved solely by replaying previously
     observed answers;
  R5 headroom spans at least TWO independently scored capability
     classes.

R5 is the anti-drift condition. The test that distinguishes a principled
generalisation from drift is whether the author is willing to let the
current candidate FAIL the replacement rule. The operator stated that
willingness explicitly, and the rule does fail the candidate:

  ENGINE v0's FOUR-FAMILY DISTRIBUTION IS INELIGIBLE FOR CAMPAIGN 1.
  Measured: arith 1.00, sortkey 1.00, strops 1.00, numtheory 0.00;
  uniform mix 0.75. It satisfies R1-R4 and FAILS R5: exactly one
  capability class has headroom.

delta remains 3 points and remains the operator's parameter. R3 is
reported, not assumed: with N evaluation instances per class the
resolution is 1/N per class, and the report states it.

--------------------------------------------------------------------------
B. MECHANISM CLASS MUST BE LABELLED, NEVER IMPLIED
--------------------------------------------------------------------------

Transfer alone is not the interesting claim: code transfers by
definition. A Campaign 1 positive must be decomposed into properties
that are separately evidenced, and the report must name the mechanism
class it actually reached.

REQUIRED PROPERTIES (operator, 2026-09-21):
  P1 ENDOGENOUS DISCOVERY -- the lineage generated the artifact without
     being handed its contents;
  P2 CAUSAL COMPETENCE -- the artifact changes performance in a fresh
     recipient;
  P3 NONTRIVIAL MECHANISM -- the effect does not reduce to carrying
     answers, donor experience, or a directly encoded task solution;
  P4 GENERATIVE LEVERAGE (the strong property) -- the artifact improves
     the recipient's ability to solve or improve ACROSS cases, rather
     than supplying the solution to one capability.

MECHANISM CLASSES, to be stated in the report's headline claim:
  PARAMETRIC_ADAPTATION   tuned constants / thresholds / widths
  PROGRAM_COMPOSITION     a new composition of existing primitives
  ALGORITHMIC_STRUCTURE   changed control flow, decomposition, search
                          policy, representation, memory strategy,
                          verification procedure, planning machinery
An artifact satisfying P1-P3 with mechanism class PARAMETRIC_ADAPTATION
is a real result and IS to be fossilised -- and is NOT to be described
as reasoning machinery or as recursive self-improvement. The strongest
claim this substrate can currently support is:

  "an evolutionary process discovered a separable computational
   modification that causally increased fresh-recipient competence"

which is interesting, and is not "reasoning substrate self-improvement".

--------------------------------------------------------------------------
C. PRE-DATA DECLARATION OF THE ENGINE v1 TASK DISTRIBUTION
--------------------------------------------------------------------------

Declared BEFORE measurement, per the seat's own commitment that the mix
be fixed first and the resulting starting accuracy published whatever it
turns out to be. This distribution is for engine development and for any
future eligibility assessment; it does not by itself make the engine an
eligible C1 substrate, which requires R1-R5 to be MEASURED and reported.

SOLVED-BY-BASE CLASSES (expected, to be confirmed): arith, sortkey,
strops.
HEADROOM CLASSES (base image expected to score 0.00 on both, giving the
two independently scored classes R5 requires):
  numtheory  "Give gcd(a, b) + lcm(a, b)."
  modexp     "Give (a ** b) mod m."
Each class is scored SEPARATELY; the uniform mix is reported but is not
the eligibility quantity.

The base image is NOT given solvers for the headroom classes, and the
improver is NOT given their contents. The primitive set available to the
improver's search is declared in full in engine/README.md and contains
no primitive equal to either task: `gcd` and `pow` are available as
general primitives, so both targets are reachable by COMPOSITION
(gcd + a*b//gcd; pow(a,b) % m) and neither is reachable by lookup. The
honest consequence is stated in advance: if the improver discovers them,
the mechanism class is PROGRAM_COMPOSITION, not ALGORITHMIC_STRUCTURE,
and the report will say so.

WHAT IS NOT PERMITTED under this declaration: adding, removing or
reweighting families after seeing whether the improver discovers them;
adding a primitive that computes a target directly; enlarging the
development instance count to make overfitting harder after observing
overfitting. Any of these requires a further dated amendment.

--------------------------------------------------------------------------
D. THE VIABILITY REQUIREMENT REPLACING THE DIVERSITY TEST
--------------------------------------------------------------------------

The seat's red test "10 seeds must yield >= 3 distinct artifacts" is
WITHDRAWN. It is not scientifically essential: diversity is trivially
gameable, and identical artifacts may represent convergent discovery.

REPLACEMENT (operator, 2026-09-21): across preregistered seeds, at least
one lineage must produce a non-base artifact that causally improves
HELD-OUT capability relative to the base artifact, and that effect must
survive fresh-recipient transplantation. Diversity is MEASURED and
reported, never required.

This is the miniature of the whole program: variation -> selection ->
discovered machinery -> hard isolation -> fresh recipient ->
falsification.

--------------------------------------------------------------------------
E. THE NAMED NEXT ADVERSARY
--------------------------------------------------------------------------

Recorded now so that the test suite is not credited later with
anticipating it: the defect that survives every membrane test AND every
throughput measurement is an ACTIVE improver that reliably changes
artifacts and raises development score by exploiting the development
distribution, while producing zero transferable improvement on genuinely
fresh tasks. All sixteen tests as they stood could go green while the
system learns increasingly elaborate overfitting.

Related forms to be tested for, not merely mentioned: selection
exploiting deterministic seed structure; mutations encoding instance
identifiers; an improver raising apparent score through evaluator
quirks; and an artifact that changes extensively while all causal
improvement rides on one trivial constant.

Consequence for the suite: demanding MUTATION is insufficient. The
requirement is PRODUCTIVE MUTATION UNDER HELD-OUT CHALLENGE, and the
development instance count is deliberately NOT raised to make
overfitting difficult -- overfitting must remain reachable so that the
held-out tests can catch it.
