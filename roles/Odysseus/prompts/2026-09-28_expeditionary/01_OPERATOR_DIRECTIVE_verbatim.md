2. TERRITORY D IS NOW THE PRIMARY EXPEDITION

That is not yet accumulation.

Operationalize accumulation.

A candidate event should require something like:

1. a capability or representation arises during the system’s own history;
2. a later process consumes that acquired object;
3. the consumer obtains access to behaviour it could not obtain equivalently from the original substrate under the matched budget;
4. the acquired object survives some change of individual, episode, context or generation;
5. removing or scrambling that object removes the downstream advantage.

Do not freeze this definition merely because I gave it.

Attack it and improve it.

Especially distinguish:

* accumulation from ordinary optimization;
* inheritance from persistence;
* reuse from recomputation;
* compositional growth from repeated rediscovery;
* increasing behavioural ceiling from increasing speed;
* genuine substrate-written structure from an experimenter-provided communication protocol.

Build the measurement before making the claim.

4. BUILD THE ACCUMULATION LADDER

Do not jump directly to culture or open-ended evolution.

Construct a ladder where every rung has a clean falsifier.

Possible rungs:

R0 — persistence
An acquired state survives longer than the process that produced it.

R1 — later reuse
A later episode uses it.

R2 — new consumer
A different individual/lineage/process benefits.

R3 — causal dependence
Deleting or scrambling the object removes the benefit.

R4 — recombination
Two independently acquired objects are used together.

R5 — ratchet
The combined result makes a previously unreachable capability reachable.

R6 — recursive accumulation
A new acquired object improves the system’s ability to create or exploit future acquired objects.

Do not award a higher rung because a label implies it.

Require interventions.

The interesting boundary may occur below R6.

Find it.
