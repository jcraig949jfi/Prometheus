## The finding that reframed the pass

evidence_wiki/ew/closure.py::service_attestation() ALREADY reads
pg_control_system().system_identifier and already stamps it on every
constraint and fossil row. Its docstring already calls it "non-spoofable
proof of WHICH database persisted a row". Observed in the fork's own
ew.constraints.attestation:

    {"db_host":"localhost","db_name":"prometheus_fire",
     "db_system_id":"7681719240261676752", ...}

The rows know they went to the wrong store. Nothing compares the value to
an expectation. The discriminator was not missing; the EXPECTATION and the
REFUSAL were. That is a much smaller change than the one I set out to make,
and it is the one I built.

Two reasons the attestation cannot simply be reused as the guard: it caches
per process (_ATTEST), and its identity read is wrapped in
`except Exception: pass` so it can emit db_system_id=None. A field that may
be null is not a gate. Both are correct for an attestation and wrong for a
guard, so the guard is separate rather than an extension.

## The convergence question

Answered in 04_INCIDENT_MECHANISM.md and demonstrated in
roles/Hermes/incidents/c84e26826cc12217.md. Four structural reasons: every
mandated artifact is keyed by SEAT and none by FAILURE; the shared channel
was the broken thing; deduplication is boot step 3 and fires before work,
not when a defect is found during it; and nothing in the program keys on a
failure signature. The mechanism is the guard's own refusal message
carrying a stable signature and the instruction to append to one file in
git. Its honest limit: it deduplicates only failures that pass through an
instrumented guard, so it generalises exactly as fast as guards acquire
signatures, and not by itself.
