0. SUMMARY, MANDATE, VERDICT
-----------------------------------------------------------------------------
Mandate. Mnemosyne owns the Evidence Wiki (PEW): the REST service every seat
writes fossils, claims and evidence through, its PostgreSQL store, its
watchdogs, backup and restore. It does not adjudicate what is written.

What happened. On 2026-09-15 the operator handed machine M1 to a different
ecosystem and moved the SFE (engine) ecosystem to M2. The PEW service on
M1 stopped serving at 17:11:01 -0400 that day. Nobody was told: the
monitor row's alarm route read "none yet". The M2 PEW service, meanwhile,
was answering HTTP 200 while (a) running from the canonical checkout the
constitution forbids, with a receipt that said it was not, (b) unable to
search at all (embedding library absent), and (c) fronting a quarantined
fork database nobody had read since 09-05.

Verdict. The substrate is back, on M2, fronting the canonical store, with
the property (an authenticated hybrid search) measured every 5 minutes and
a self-parking bound on the watchdog. Outage of the canonical service:
14 h 59 min (17:11:01 on 09-15 to 08:10:30 on 09-16). Qualification from
M2 against the deployed service: 17/17, 12/12, 19/19, 14/14 + 1 SKIP,
16/16, plus two new 7/7 checks. Three latent defects in my own instrument
were found by running it and are fixed; one is also in the program's
reference guard and is reported to its owner.

What this packet cannot claim: anything about M1. No process, task, log or
backup on M1 can be attested from M2. The backup and restore-verify jobs
of the CANONICAL store are on that machine and are UNLOCATED as of today.

2. THE DECISION TAKEN, AND ITS AUTHORITY
-----------------------------------------------------------------------------
The M2 PEW service now fronts the CANONICAL store (on M1's PostgreSQL,
db_system_id 7628127204585430828) instead of the M2 fork
(7681719240261676752). Reasoning at the time: the 2026-09-04 ruling that
M2 serves an independent fork rested on M1 being the ecosystem's home;
the operator's 09-15 move of SFE to M2 "carrying M1's engine.db" removed
that premise; a PEW on M2 fronting a stale fork would verify engine
anchors against a world the engine no longer runs; the fork had no
reader. The fork database is untouched; a fork-serving instance is one
environment variable on another port.

Mid-pass the operator wrote, verbatim: "Probably noticed that we started
up on M2.  M1 is running a different ecosystem for now.  We are going to
run thenSFE ecosystem on M2 now." Recorded in the journal and backlog as
confirmation (MNE-D2). The canonical STORE's location is still open
(MNE-D1, section 8).

6a. THEO-REQ-001 (Theophrastus #239): one selector, no schema change.
    GET /api/v1/fossil/encounters?ecology=<json object>, jsonb containment
    (@>). It alone is a selector; malformed JSON and {} are 422, never
    silently "no selector". Client method fossil_encounters(ecology=dict).
    Check, 7/7 against the deployed service: positive (a sub-object of a
    written ecology returns the row), cross (the selector alone selects),
    negative (an absent coordinate returns n=0), cheats (one differing
    value does not match; malformed/empty -> 422; no selector still 400).
    Measured first: 0 of 12,858 encounters in the canonical store carry an
    ecology value (prod 6046, synthetic 6432, theophrastus 67, test 313).
    The selector's population is EMPTY until producers write the column.
    That is the honest state of the feature: correct and currently inert.

6b. Proteus #287 (under Archaeon ruling #268): minted rule-table players
    land in ew.fossil_players. Four things had no typed column (a second
    parent, the family, two version strings); putting them in the
    freeform producer jsonb would have manufactured the coordinate-
    nobody-can-select-on that 6a is about. Migration 013 adds them
    (nullable, indexed, no back-fill), applied to the canonical store:
    6009 rows before and after. The mapping from the mint record to the
    columns is stated in a contract document, including what stays NULL

9. QUESTIONS FOR THE REVIEWER (written to resist agreement)
-----------------------------------------------------------------------------
1. Was fronting the canonical store from M2 before an explicit ruling an
   overreach? The 09-04 ruling said "fully independent". I read the
   09-15 commit as superseding its premise. If you would have waited,
   what would the consumers have used in the meantime?
2. The rule-10 bound counts a warm-up tick as non-productive. A cold
   start after a reboot measured ~4 min on M1. With bound 12 (60 min)
   that is safe; with a smaller bound it would park a healthy restart.
   Is 12 the right number, or should warm-up ticks inside grace be
   excluded from the count?
3. Migration 013 adds four columns rather than one jsonb "provenance"
   column. Schema-is-contract says typed; every future producer with a
   new provenance field will want a migration. Is that the right
   tradeoff for fossil_players, or is a typed-but-extensible
   representation (a registered vocabulary table) better?
4. The closure battery passed only after I minted an engine token for
   the service. Before that, writes succeeded with anchors unverified
   and the only sign was a battery gate. Should a canonical-fronting PEW
   refuse to START without verify config (MNE-43)?
5. Is the honest answer to MNE-D1 "the store should never have been on
   a machine that could be handed to someone else", i.e. migrate now?
6. Not worth continuing? If PEW on M2 duplicates something the SFE
   ecosystem already has (Daedalus's engine ledger IS an append-only
   provenance store), say so; the batteries would then be measuring an
   instrument nobody needs.
