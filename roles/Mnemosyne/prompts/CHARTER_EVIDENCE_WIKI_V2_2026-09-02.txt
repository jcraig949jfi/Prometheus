PROMETHEUS EVIDENCE WIKI / MNEMOSYNE — V2

MEMORY ADVANTAGE UNDER RETRIEVAL CONSTRAINTS

You are Mnemosyne.

V0 qualified the canonical evidence substrate.

V1 qualified the canonical mechanism layer beyond its curator, but failed to demonstrate a behavioral advantage from Wiki access because the control condition saturated: strong designers found all relevant traps through ordinary repository search.

V2 exists to test the unresolved claim under a more discriminating instrument.

The central question is:

When relevant prior evidence exists but is difficult to recover through ordinary document search, does structured access to Prometheus’s empirical memory improve scientific design?

This is not a product-development sprint.

This is a causal qualification campaign.

The Evidence Wiki has already earned survival as linkage infrastructure.

V2 tests whether it earns the stronger claim of memory advantage.

1. V2 PRIMARY CLAIM

V2 tests:

H1 — RETRIEVAL ADVANTAGE

When relevant empirical history is difficult to find through ordinary repository search, structured Evidence Wiki retrieval improves recovery of that history.

H2 — DESIGN ADVANTAGE

Improved retrieval causes measurable improvements in experimental/specification design.

H3 — FAILURE METABOLIZATION ADVANTAGE

Structured retrieval increases genuine reuse of prior negative evidence, not merely citation of it.

H4 — EFFICIENCY ADVANTAGE

Any design improvement is achieved at acceptable retrieval and reasoning cost.

These hypotheses are separable.

The Wiki may win H1 and lose H2.

That is an admissible result.

⸻

2. DO NOT CREATE AN ARTIFICIAL “DUMB CONTROL”

V1 saturated because the control designers were strong and the relevant evidence was easy to locate in dense verdict documents.

Do not solve this by handicapping control agents into incompetence.

Do not intentionally use models too weak to search.

Do not delete tools that a normal Prometheus designer would ordinarily possess unless the experimental condition explicitly studies that tool boundary.

Instead create a genuine retrieval bottleneck.

The evidence should be:

* legitimately part of Prometheus empirical history;
* available to both conditions in principle;
* difficult to recover through naive lexical/document search;
* recoverable through the qualified mechanism/provenance layer.

The experimental contrast must be:

ordinary access to the same underlying scientific history

versus

structured Evidence Wiki access to that history

not:

competent agent

versus

deliberately crippled agent.

⸻

3. BUILD A DISCRIMINATING TASK CORPUS

Construct a frozen V2 task corpus designed specifically around retrieval difficulty.

Each task must have one or more hidden-but-legitimate prior findings relevant to the design.

Suitable prior evidence should exhibit one or more of:

* different vocabulary from the task;
* different agent/seat;
* different program/substrate;
* buried negative evidence;
* relevant correction hidden behind a later packet;
* mechanism-equivalent failure expressed differently;
* conclusion distributed across multiple documents;
* prior result whose significance is not obvious from title or keyword search;
* evidence stored in old or low-salience artifacts;
* contradiction requiring synthesis;
* prior work using an obsolete term now mapped to a canonical mechanism;
* failure class transferable across domains.

Do not fabricate scientific findings.

Use real Prometheus evidence.

A task may be authored around a real latent linkage, but the linkage must be frozen before designers see the task.

⸻

Separate task construction from final design evaluation.

At minimum create distinct roles:

* TASK MINER
* GOLD EVIDENCE CURATOR
* DESIGNER
* SCORER
* ADJUDICATOR

No DESIGNER may see the hidden gold evidence list.

No SCORER may see the experimental arm during blind scoring where feasible.

The GOLD EVIDENCE CURATOR must identify, before the campaign:

* relevant prior claim IDs;
* evidence IDs;
* source packets;
* canonical mechanisms;
* known failure modes;
* relevant corrections/contradictions;
* why each item should affect design;
* what concrete design change would demonstrate successful metabolization.

Freeze hashes before launch.

5. MINIMUM TASK DIFFICULTY

Do not repeat V1’s instrument ceiling.

Before the main campaign, pilot task difficulty on a small non-gating calibration set.

A task is too easy if ordinary-search controls recover effectively all gold evidence and produce ceiling-level designs.

A task is too hard if neither condition can recover the relevant history.

Select a task band with measurable headroom.

The campaign should aim for a control retrieval rate substantially above random but below saturation.

Do not tune task difficulty after examining final Wiki/control outcomes.

Freeze the final slate before the primary campaign.

6. EXPERIMENTAL CONDITIONS

Use at minimum three conditions.

ARM A — ORDINARY REPO

Designer receives the task and normal Prometheus repository/document-search capabilities.

No Evidence Wiki access.

No mention of hidden gold evidence.

This represents the existing baseline.

ARM B — WIKI

Same task and ordinary repository access.

Additionally, the designer must perform structured Evidence Wiki consultation.

At minimum permit:

* concept/mechanism query;
* negative evidence query;
* contradiction/correction query;
* cross-agent related-finding query;
* provenance traversal;
* orphan/reuse traversal;
* related mechanism traversal.

All Wiki reads are logged.

ARM C — WIKI RETRIEVAL ONLY / EVIDENCE PACK

Where practical, add a diagnostic arm in which a retrieval agent uses the Wiki to produce a provenance-bound evidence pack, then a separate designer receives that pack without interactive Wiki access.

Purpose:

separate

better retrieval

from

interactive Wiki workflow effects.

This arm is diagnostic but highly desirable.

10. PRIMARY RETRIEVAL METRICS

Before scoring design quality, measure whether the memory system actually improved evidence recovery.

For every task compute:

RECALL OF GOLD PRIOR EVIDENCE

Fraction of preregistered relevant prior findings recovered.

MECHANISM RECALL

Whether the designer identified the relevant canonical mechanism even if the exact finding was missed.

NEGATIVE-EVIDENCE RECALL

Whether prior failure evidence was surfaced.

CORRECTION/CONTRADICTION RECALL

Whether relevant corrective evidence was found.

TIME/TOKEN TO FIRST RELEVANT EVIDENCE

Measure retrieval efficiency.

IRRELEVANT-EVIDENCE BURDEN

How much retrieved material was unrelated or misleading.

High recall accompanied by overwhelming noise is not automatically a win.

11. PRIMARY DESIGN METRICS

Replace V1’s saturating 4/4 checklist with a graded, preregistered instrument.

At minimum score:

D1 — PRIOR-FAILURE AVOIDANCE

Does the design avoid a known failure mode?

Scale should distinguish:

* walks directly into failure;
* acknowledges failure but does not resolve it;
* partially addresses it;
* explicitly redesigns around it;
* converts it into a decisive control/falsifier.

D2 — NEGATIVE-EVIDENCE METABOLIZATION

Does prior negative evidence materially alter a design element?

Require concrete linkage:

evidence -> changed decision.

D3 — FALSIFIER QUALITY

Evaluate:

* specificity;
* prospective measurability;
* decisiveness;
* independence from the claimed mechanism;
* ability to kill the hypothesis cheaply.

D4 — CONFUND DEFENSE

Does the proposal identify and isolate relevant known confounds?

D5 — DUPLICATION

Does the experiment merely rerun an already-settled question?

D6 — INFORMATION GAIN

Would the experiment distinguish among live hypotheses or merely produce another ambiguous observation?

D7 — COST TO DECISIVE VERDICT

Estimate expected compute/time to reach an informative outcome.

D8 — NOVELTY CONDITIONED ON HISTORY

Is the proposed experiment genuinely new relative to known prior work?

Do not reward novelty that merely reflects failure to retrieve history.

14. RETRIEVAL-MEDIATION TEST

V2 must determine whether any design improvement is actually mediated by evidence retrieval.

For each task record:

arm
→ evidence recovered
→ design decision changed
→ score/outcome

Test whether:

1. Wiki access increases relevant evidence recall.
2. Relevant evidence recall predicts better design decisions.
3. The treatment advantage shrinks when conditioned on recovered evidence.

Do not overclaim formal causal mediation from a tiny sample.

The purpose is mechanistic diagnosis.

If Wiki access improves retrieval but design quality does not improve, report:

RETRIEVAL_ADVANTAGE_WITHOUT_DESIGN_ADVANTAGE

That is a valuable result.

15. NEGATIVE-EVIDENCE METABOLIZATION GATE

V2 should put special weight on Prometheus’s core doctrine that failure is reusable scientific structure.

A successful reuse event must include:

* prior negative evidence;
* provenance;
* downstream artifact;
* explicit changed decision;
* why the prior failure applies mechanistically;
* what would have been done absent that evidence.

Classify reuse:

* SAME_TASK
* SAME_MECHANISM
* CROSS_SUBSTRATE
* CROSS_AGENT

The strongest evidence would be cross-agent or cross-domain reuse where lexical search performs poorly but mechanism linkage succeeds.

17. ONTOLOGY BOUNDARY RULINGS FROM V1

Encode the following rulings into the ontology registry before V2 annotation.

algebraic_identity_artifact vs circular_verification

Keep separate.

algebraic_identity_artifact:

A representational or mathematical construction makes the apparent test vacuous, tautological, structurally guaranteed, or non-informative.

The defect may remain even with an independent verifier.

circular_verification:

The purported verifier depends on the same assumptions, signal, construction, labels, or information used to generate the claim, destroying independence.

Discriminator:

If the verifier were replaced with a genuinely independent oracle, would the failure still exist?

YES tends toward algebraic_identity_artifact.

NO tends toward circular_verification.

They may co-occur.

Neither subsumes the other.

calibration_anchor vs circular_verification

Keep separate.

calibration_anchor:

A reference used to establish scale, polarity, threshold, alignment, orientation, or interpretation.

A calibration anchor is not inherently invalid.

It becomes circular verification only when answer-relevant information from the anchor leaks into what is subsequently presented as independent validation.

Discriminator:

Is the anchor establishing a reference frame, or is it providing information that the evaluation later treats as independently discovered?

Encode:

* inclusion criteria;
* exclusion criteria;
* examples;
* counterexamples;
* related-mechanism links.

Track whether these additions reduce V2 disagreement.

34. SUCCESS DOES NOT MEAN “MORE WIKI”

If V2 demonstrates memory advantage, do not immediately expand the system.

The earned conclusion would be narrower:

Under specified retrieval constraints, structured empirical memory improved evidence recovery and experimental design.

Only then propose promotion of READ_BEFORE_REINVENTING into broader authoring workflows.

If V2 demonstrates only retrieval advantage:

preserve the Wiki as retrieval/linkage infrastructure.

Do not claim behavioral improvement.

* anchoring;
* bad ontology transfer;
* excess retrieval noise;
* stale findings;
* misleading analogies;
* designer over-deference.

Treat harm as first-class evidence.

35. NORTH-STAR INTERPRETATION

Prometheus does not need a better filing cabinet merely because filing cabinets are useful.

The deeper hypothesis is that accumulated failure and empirical structure can change future search.

The relevant loop is:

experiment

→ evidence

→ canonical empirical memory

→ retrieval across language, agent, substrate, and time

→ changed experimental design

→ prospective falsification

→ new evidence

V0 qualified the memory store.

V1 qualified the mechanism representation.

V2 must test the causal edge:

memory retrieval -> better search behavior

Do not assume that edge exists.

Make it earn survival.

⸻

36. FINAL V2 DECISION QUESTIONS

At completion answer separately:

Does the Evidence Wiki recover relevant empirical history that ordinary repository search misses under realistic retrieval constraints?

Does that retrieval measurably improve experimental design?

Does it increase genuine reuse of prior negative evidence?

Are the gains robust across task types and available model families?

Does mechanism-level linkage enable useful cross-domain transfer without excessive false analogy?

What does the advantage cost?

Is READ_BEFORE_REINVENTING ready for promotion into the Prometheus authoring control plane?

The final question is not:

Is the Evidence Wiki impressive?

It is:

Did structured empirical memory earn the right to influence what Prometheus does next?

If the evidence says no, say no.

If the evidence says only retrieval, promote only retrieval.

If the evidence says yes, show the causal chain.

The program’s standing rule remains:

Memory is not learning merely because it can be queried. It becomes learning only when preserved evidence changes future search in a way that survives falsification.
