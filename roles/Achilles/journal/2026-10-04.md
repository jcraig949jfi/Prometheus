- 15:24:31Z a USB keyboard was unplugged; 15:24:38Z `usb 4-1: USB disconnect` (the USB-C NVMe enclosure that

  crash-looped (24+ restarts): `git fetch` -> "cannot open .../FETCH_HEAD: Read-only file system".
- The disk re-enumerated as sdc, but root LV was bound to the vanished sda, so a reboot was needed.
  `sudo systemctl reboot` (from me) hung at "Failed to execute shutdown binary" (the binary lives on the gone
  disk), with journald looping on read-only writes. A hard power cycle (10 s hold) by the operator fixed it.
  The boot showed only "orphan cleanup", with no fs errors. Root rw, worker active, wired .222 back (the operator
  plugged in Ethernet; wired is now the primary route, Wi-Fi .227 is the backup).
- Lesson: a USB-rooted node can't reboot itself after a drop. The remedy is a hard power cycle, not a remote
  reboot. Same exposure for ubu007 (M6500 plan). Place both where cables can't be bumped; strain-relieve them.
