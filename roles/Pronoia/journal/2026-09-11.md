No tracked Python writes those columns; no tracked SQL creates them. The
two populated rows are written by M4-local untracked code. The fleet's

Semantics: roles/Pronoia/science/productive_liveness.py. Pure, no DB, no
clock -- now is injected so it is testable at any instant. Seven states,
each reachable and each asserted by a test. The load-bearing design
choice is that health is DERIVED FROM TIMESTAMPS ONLY, so a process whose
work thread dies but whose heartbeat thread lives degrades from
productive to stalled on wall-clock alone, with no cooperation from the
dead thread. That is the exact defect this seat committed twice.

Work boundary chosen:

    last_work_attempt_at   stamped at cycle start, unconditionally,
                           in exactly one place
    last_work_success_at   set ONLY when cycle_ok AND an artifact was
                           written at or after the cycle's wall-clock
                           start, in exactly one place

cycle_ok is already the conjunction of three subprocess exit codes, so it
is not "the loop did not throw". But an exit code is the child's own
report, so _cycle_left_evidence() adds the observable consequence: a
dashboard artifact whose mtime advanced. Both conditions, or no success
is recorded and the health value decays by itself.
