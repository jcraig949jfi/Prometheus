QUESTION -- (a) How often, and how fast (in evaluations), does selection find an exploit in the evaluator under three isolation
designs: separable test episode with fixed inputs, separable episode with randomised inputs, and in-population lineage-relative
comparison? (b) For the improver-of-improvers engines (Aphrodite, Ares), is there any path from the graded party to the grader?

WHY IT MATTERS -- Exploit-shaped reversals recur in this program: the WSE W8 leak, Ares D1/D2, Nemesis L-01, Ensorain WTP-01/02
(below). A measured base rate would size every engine's cheat controls. A clear answer on grader ownership decides whether
Aphrodite's recursion (IMPROVER_1 -> IMPROVER_2, not yet authorised) can be evaluated at all.

Prior art that changes the reading:
- STERILIZE_BENEFICIAL is not by itself an in-population pressure. Avida has a separate test-CPU path (random inputs; the
  separable episode that organisms learned to detect) and an in-situ parent-relative TestSterilize path. Only the second matches
  Ofria's working fix. PA W2 verified this from the source; which flag enables GetTestSterilize() is UNVERIFIED.
- Co-evolving the selector is contradicted by 25+ years of coevolution work (Ficici & Pollack; Watson & Pollack): collusion,
  mediocre stable states, cycling (PA W8). The known guards are a frozen gold scorer that the optimiser never sees (Gao et al.,
  PA W7) and an uninfluenceable evaluator (Everitt et al., PA W5). H-D5-37 should be read as SUPERSEDED in its optimistic form.

UNCERTAINTY -- No base rate or time-to-exploit for any isolation design, in this program or in the ALife literature (PA U3).
Unknown whether randomising the test episode helps at all (Ofria's organisms answered it by acting probabilistically, PA W1).
The RA-3 census can only count recorded exploits.

CHEAPEST DISCRIMINATOR -- Two parts. The first is repo-only and runs now; the second is the actual base-rate measurement.
(A) RA-3 census, about 0.5 agent-day. Unit: an event where a scored quantity rose through a channel other than the intended
  capability and was caught later. Fields: engine; evaluator design (separable episode / held-out / in-population / shuffled
  control); exploit channel; caught_by (cheat control / positive control / human reading / second evaluator); latency. Seeds:
  the six events above. Share rows with FR-057 (same extraction pass, GOODHART = adversarial).
(B) PA T6 on stock Avida (external code, no Prometheus engine). Step 0, 1 h desk work: trace the flag that enables
  GetTestSterilize(). Arms: (1) test CPU with fixed inputs (UseRandomInputs patched out); (2) stock random-input test CPU;
  (3) in-situ TestSterilize. STERILIZE_BENEFICIAL = 1.0 in all arms, 20 seeds each, the same logic-task environment. Outcome:
  updates until the first lineage whose in-population replication rate beats its ancestor by > 10% (an escape), censored at a
  fixed budget; report the escape fraction and Kaplan-Meier time-to-escape.
Belief moves: fixed < random << in-situ (in-situ rarely or never escapes) -> isolation must be structural and lineage-relative.
  Recommend the in-situ pattern to NPE, BEE and Aether harnesses, and treat randomised test episodes as delay, not cure.
  Random is about equal to fixed -> input randomisation is worthless in this regime. In-situ also escapes quickly ->
  lineage-relative pressure is not a cure either, and EV-8's independent second evaluator becomes the next test.
(C) Grader ownership, 1 h per engine (PA T9): list every path from improver outputs to grader parameters (evaluation protocol,
  distractor policy, task generator, tribunal) in Aphrodite and Ares. Any path found is an ownership violation to fix before
  IMPROVER_2 is authorised.
Cost: (A) and (C) are desk work; (B) is a few CPU-hours plus an Avida build.
