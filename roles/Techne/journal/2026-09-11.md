             odd cycle C_n        theta = n cos(pi/n) / (1 + cos(pi/n))   n in 21, 61, 121

           CERTIFICATE computed by numpy from the matrices the solver returns, never from its

             lower bound  project the returned X to exact feasibility (zero the edge entries,
                          clip negative eigenvalues, rescale trace to 1) and evaluate sum(X').
                          X' is feasible by construction, so sum(X') <= theta.
             upper bound  any symmetric Y supported on the edge set gives theta <= lambda_max(J + Y)

                          duals, both signs tried, the smaller lambda_max kept. Valid for ANY Y, so
                          the bound is unconditional; only its tightness depends on the solver.

the whole fixture; the bar is a reporting threshold, not an accuracy requirement (TECHNE-46):

    closed-form cases   rel = |value - theta| / theta

### Amendment to the preregistered certificate rule -- made after a control fired, before the run

The preregistered rule (above) held a certificate row to a 1e-6 "inside the bracket"
tolerance while holding a closed-form row to the 1e-2 bar -- two standards, in the same
preregistration that says one bar governs every arm. The control that exposed it, during
test writing: SCS on a 14-vertex random graph reported 6.0000632 against a bracket
[5.99989, 6.00000001]; the preregistered rule said SILENTLY_WRONG (1.05e-5 above ub), the
closed-form rule would say CORRECT for the identical error.

Amended rule: judge the WORST-CASE error of the value over every theta in the bracket,
err_bound = max(|v-lb|, |v-ub|)/ub, at the one bar; SILENTLY_WRONG when the value leaves
the bracket by more than the bar; INDETERMINATE otherwise. Both classes are recorded on
every row (certificate_class, certificate_class_prereg); the preregistered function is kept
verbatim in the code. On the real run the two rules disagree on exactly ONE row,
B_closed_paley_61 / SCS (1.09e-06 above ub), which the closed form independently scores
CORRECT at 5.96 digits -- so the amendment did not change any verdict a ground truth could
check, and the one row it touched is the one the ground truth settles.

I am recording this as a gate moved after data was seen, because it was, even though the
data was a unit-test control and not the fixture. The defence is that the change restores
the preregistration's own stated principle rather than rescuing a result; the evidence that
it is not a rescue is that the amended rule fails the cheat controls exactly as the old one
did (tests parametrised over both rules) and changes no ground-truth-checkable class.
