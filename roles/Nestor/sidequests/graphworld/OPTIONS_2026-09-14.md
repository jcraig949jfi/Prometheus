## Options under discussion

O1 Measure before building: Encounter ticks/s in-process vs Redis+Lua vs
   FalkorDB on one fixed world spec. Stand (falsifiable): in-process Python
   wins the tick; Redis wins only event/ledger throughput.
O2 Hot event tier: Redis Streams (AOF) as write buffer in front of the
   SQLite ledger. Targets the measured bottleneck. SFE is Daedalus's lane:
   prototype + kill-9 durability test here, proposal to Daedalus only.
O3 Metered channel + compression pressure: organism<->world and
   organism<->organism messages over Streams, atomic per-byte charge in a
   Lua script (maps onto Encounter's economy-settlement phase). Builds the
   pressure that does not exist yet.
O4 Relational world in FalkorDB: world state is a graph; organisms act by
   emitting graph patterns/queries; fitness charges description length and
   engine cost. Cheat control: re-wire the graph between episodes so a
   memorised answer fails.
O5 Evolve the engine as a world: organisms are plan/optimizer-pass
   orderings or PreJIT kernel sets; oracle = result equality with the stock
   engine; fitness = callgrind instruction count. Needs the build.
O6 Fork/rewrite FalkorDB or Redis by hand: park (SSPL, 127k lines Rust,
   already columnar with 15 optimizer passes; not our bottleneck).
