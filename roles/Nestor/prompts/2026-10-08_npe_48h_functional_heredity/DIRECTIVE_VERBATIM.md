2. First scientific branch: explain competence loss

Before inventing a better task gate, localize the existing failure.

Open an EXPLORE child of X-TASK-GATE-V2 whose question is approximately:

What causal event destroys the transmitted task function while leaving copying intact?

Use the existing Stage-0 trajectories and the smallest additional replays needed.

Track the FIRST loss of competence along transmitted P-11 descent.

Where possible distinguish:

* copy error;
* nominal mutation;
* partner overwrite;
* task-byte mutation specifically;
* loss of cue use while copying remains intact;
* genome replacement;
* state/context effect;
* measurement/ruler transition;
* lineage extinction versus within-lineage functional decay.

Estimate quantities such as:

* P(competent child | competent causal donor);
* competence-loss hazard per causal generation;
* competence-loss hazard per interaction;
* whether loss concentrates in specific task bytes/instructions;
* whether competence-bearing descendants have different copy success or overwrite exposure;
* whether the task routine is structurally independent of the conserved copier core.

Use byte/material provenance where appropriate.

Do not assume “mutation erosion” merely because it sounds plausible.

Turn the observed decay into an actual failure funnel.

3. Cheap causal discriminator: is the existing gate harmful?

The XTG-v2 symmetric gate changes interaction frequency:

p_interact = 0.15 + 0.85 * competence

A competent organism therefore interacts more often, but interactions are also occasions for copying/mutation/overwrite.

Test whether the current gate is:

* beneficial;
* neutral;
* or actively accelerating loss of competence.

Use a paired experiment with the SAME CT_UA plant and backgrounds.

At minimum compare:

A. current symmetric task-gated interaction;

B. no task gate / competence-blind interaction;

C. a matched interaction-rate control that reproduces the treatment’s overall interaction exposure without using competence, if necessary to separate rate from task coupling.

Primary question:

Does competence disappear faster because the “selection” treatment actually exposes competent genomes to more destructive interactions?

Use survival/trajectory information rather than only the final endpoint.

If this cleanly explains the transient result, record it and move immediately to a child that changes the direction of selection rather than merely interaction count.

4. Main frontier: selection on copying direction, not meeting frequency

The highest-priority design candidate is a task coupling that gives competence a heritable reproductive advantage while holding the amount of interaction approximately fixed.

Explore a minimal directional/asymmetric gate.

Examples of the scientific form, not mandatory implementation:

* competence biases which organism is donor;
* competence biases which half overwrites which;
* competence biases who executes/copies first;
* competence protects a competent donor from being replaced while still permitting it to copy;
* competence affects copy direction rather than pair encounter probability.

Prefer the smallest single-coordinate intervention.

Do NOT simply make competent organisms immortal or hard-code the answer.

The treatment must still permit:

* CT_UA as positive;
* CT_U as read-but-not-use negative;
* COPY_ONLY as copier-only negative.

The qualification stage should ask whether the new physics actually distinguishes useful function from mere copying and whether the functional property survives many causal generations.

A useful Stage-0 endpoint should include persistence, not only peak presence.

If qualification succeeds, move to random populations/fresh evolutionary starts under a frozen EXPLORE child.

If a mechanism looks real, create a fresh CONFIRM node.

5. Architectural integration is the deeper target

Do not reduce the 48-hour program to “find a gate that keeps CT_UA alive.”

The more important question is whether selection can cause the task function to become integrated with the hereditary core.

Where a lineage maintains competence, measure whether the architecture changes.

Look for:

* task instructions becoming physically coupled to SELF/copy machinery;
* shorter or compressed functional representations;
* overlapping bytes/instructions serving copying and task behavior;
* task code moving into the materially conserved core;
* increased mutational robustness of the task function;
* distributed representations replacing the planted 40-byte routine;
* changes in which bytes are under purifying selection;
* task performance surviving deletion/ablation of the original planted routine;
* competence being reconstructed endogenously after partial loss.

Use lineage/material provenance to distinguish:

the planted routine survived

from

the lineage evolved a new architecture that preserves the function.

The second is substantially more interesting.

Do not assume the architecture must resemble the planted solution.

6. Mutation/load branch

If loss localization shows task function is primarily destroyed by mutation before selection can act, run a bounded mutation/load experiment.

Do not merely turn mutation off.

Prefer a dose series or causal comparison that asks:

Is there a regime in which task information can become selectively maintained before mutation destroys it?

Possible coordinates include:

* mutation rate;
* mutation locality;
* copy error;
* task-routine size;
* copy frequency;
* interaction frequency.

Look for a transition surface, not just a favorable hand-picked point.

If a narrow window exists, test whether the mechanism persists when moved slightly away from that window.
