-----
0. SUMMARY
-----
The operator wants code reviews done by agents, with each reviewer's
reliability measured (Q-011). Pan scored three local models on calibration
set v2:
  - 40 single-token bugs that the program's own tests catch, and 20 clean
    functions;
  - no text giveaways (tell gate passed);
  - one finding per function; a hit is the right line within +-2.
The verdict rule was fixed before any reviewer ran: a reviewer beats chance
only if the low end of its recall interval exceeds 0.70 x its false-alarm
rate. 0.70 is what "flag the line with the most mutation sites" scores when
it flags everything.

Verdict:
  - The instrument separates the reviewers, and the top one by recall FAILS.
  - qwen3:8b found 29/40 bugs (recall 0.725) but called all 20 clean
    functions buggy. It never once said "no bug": a flag-everything
    reviewer, correctly judged not better than chance.
  - qwen2.5-coder:14b (0.65 recall at 0.30 false alarms) and gemma3:12b
    (0.35 at 0.20) both beat chance.
  - Only gemma3 is under Pan's suggested dispatch bar of false alarms
    <= 0.25, and it misses two bugs in three.

7. WHAT THIS DOES AND DOES NOT ESTABLISH
-----
Does:
  - Measured, prompt-only review skill for three local models on seeded
    single-token bugs.
  - The chance bar rejects a flag-everything reviewer that recall alone
    would have ranked first.
Does NOT:
  - measure reviewers that run code or read the repository. Those are out
    of scope; the bugs were chosen because the tests already catch them.
  - represent real defects. Single-token mutations are the easy end.
  - rank qwen2.5-coder against gemma3. They trade recall for false alarms,
    and 40/20 items give wide intervals.
  - say anything about frontier models or the seats' own agents. Q-011
    proposes running them through the same harness before any dispatch.

8. DECISION / RECOMMENDATION (operator's call; Pan's lean)

     may say little about reviews whose value is catching what tests miss.

9. QUESTIONS FOR THE REVIEWER (written to resist agreement)
-----
  1. qwen3:8b answered "bug: true" every time. Is that the model, or the
     prompt (it asks "decide whether it contains a bug" with two thirds of
     items buggy)? Would a prompt stating a base rate change the ranking?
  2. The bar scales the best floor linearly with the false-alarm rate. Is
     gemma3's pass at 0.35 recall a real skill, or a cautious near-random
     abstainer that happens to land above 0.14?
  3. With 20 clean items, a false-alarm rate is +-0.2 wide. Should the
     clean side be enlarged before any dispatch decision?
  4. Thinking was off for all three. Would gpt-oss or qwen3 with thinking on
     (more tokens) review better? It is not measured.
