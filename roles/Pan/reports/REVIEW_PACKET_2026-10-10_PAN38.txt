-----
0. SUMMARY
-----
The operator asked for tabs on the crowded Data Map dashboard, plus two new
views: every computer in the fleet ("e-waste network") with specs, OS, RAM,
disk and GPUs, and every seat with last active, last check-in, last work,
active/inactive status and last machine.

Delivered: six tabs (Overview, Machines, Pantheon, Storage, Search and
models, Code review); a module pan/fleet.py that joins existing sources and
measures what it can; a probe table pan.host_probe; live controls 7/7.

Verdict: the views are a faithful JOIN of sources that already existed, with
measured values laid over the hand-kept register where Pan could measure.
Coverage of the measurement is partial (4 of 14 machines measured today);
the rest is labelled as register-only or as an older probe, never presented
as measured. Three findings came out of the join (s4.3).

-----
2. THE CLAIM AND WHY IT MATTERS
-----
Claim: each row on the two tabs states where every value came from, and a
value shown as "measured" was measured on the date shown.
Why: the operator plans work placement (heavy CPU, GPU, light wide work)
from this view; a register value silently presented as measured, or a seat
shown "active" from a stale status flag, would mislead placement and
staffing decisions. The program's own doctrine: status columns are fossils;
presence is derived from activity.

-----
3. DESIGN AS EXECUTED
-----
3.1 Machines. Start from the register's two host tables (8 Windows, 6
Linux). For each machine take the newest ok probe: Pan's (ssh or local CIM)
if any, else agora's. Measured threads, cores, RAM, OS, CPU model, GPU,
disks and free space replace the register's values. Disagreement rules:
probe hostname != register host; threads differ; RAM measured < 0.85 x
register or > register + 1 GB (MemTotal reads below nominal). Last seen =
newest of seat session, Fabric worker heartbeat, agora probe, Pan probe.
Status buckets: active <= 24 h, week <= 7 d, month <= 30 d, else inactive;
none if nothing recorded.

3.2 Seats. Universe = comms registrations (69) union role directories,
minus role templates and Achilles' "historical role document" entries = 74.
Last active = newest of comms activity, commit on main, message sent. Last
check-in = newest comms sync. Last work = newest commit subject on main.
Last machine = machine of the newest session. Declared = the seat's own
WORK_STATE.json. Role line = Achilles' census (dated). The comms status
column is NOT used.

3.3 Probes are read-only: hostname, DMI vendor/product, os-release, kernel,
uptime, /proc/cpuinfo, nproc, lscpu cores, /proc/meminfo, lsblk, df /,
lspci display devices, loadavg. No package lists, no credential checks, no
git fetch (an existing node_inventory.sh does those; it was not reused for
that reason). ssh runs with BatchMode=yes and StrictHostKeyChecking=yes.

-----
5. INCIDENTS (and what they validated)
-----
5.1 OS misread. agora reported "Windows 10" for M1, whose register says
Windows 11 Home. Cause: Python < 3.12's platform.release() returns "10" on
Windows 11 (M1's probe ran Python 3.11.9). Fix: agora's OS is used only
when the register has none, and an ambiguous "10" is shown as "Windows 10
or 11 (probe cannot tell)". Caught before publishing.
5.2 Time zone slip. The freshness field last_probe_at was printed from a
local-time (-04:00) timestamp as if it were UTC (07:44 instead of 11:44).
Caught on inspection before publishing; now converted with the module's own
UTC formatter.
5.3 Vacuous control. The first CHEAT control checked seats whose comms
status says active but who were idle 30 days; there were 0 such rows, so it
tested nothing while passing. Strengthened to 24 h (42 rows) and made to
FAIL if no such rows exist.
5.4 Host keys. ssh to ubu004-006 was refused: M2's known_hosts has no entry
for them (Achilles provisioned them from ELSA). Not a changed key. Pan did
not add keys (a trust decision on the operator's admin machine) -> Q-012.

7. WHAT THIS DOES AND DOES NOT ESTABLISH
-----
Does: the tabs show the register faithfully, measured values where measured,
and activity-derived seat status; the merge flags lies it is fed (CHEAT).
Does NOT:
  - verify the 7 register-only machines (their specs are the operator's and
    Achilles' records, unverified by Pan);
  - verify M1/M3 since 2026-05-30;
  - say a seat is productive: "active" means it made a comms call, commit
    or message, not that it produced anything of value;
  - see work on branches: last work is the newest commit on main only;
  - stay current by itself: the datasets are snapshots, rebuilt by Pan on
    its loop until 2026-10-12, then marked stale (12 h threshold).
