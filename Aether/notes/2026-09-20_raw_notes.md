Three rulings:

GPU-native means the intended high-performance implementation is
massively parallel, but GPU execution must not define the scientific
semantics. Physics must first have an implementation-independent
specification and CPU oracle. Candidate GPU mapping is per-cell parallel
evaluation/proposal generation followed by deterministic parallel
arbitration/commit.

Executable matter is intentional. At Aether's base level,
instruction-bearing state is physical matter. Do not introduce a
privileged code/data distinction unless later experiments deliberately
add one.

First accessibility transplant: do not inspect any existing engine
implementation. The scientific finding available to Aether is: a system
can contain the required information and sufficient selection pressure
while useful conditional computation remains inaccessible because of
representation topology. In the observed case, an existing behavior
produced its answer before reading the information required for the
better behavior. The viable conditional form required several
coordinated changes separated from the incumbent by a zero-fitness
valley; no beneficial local one/two-edit route was found, while a seeded
viable witness was strongly selectable. Aether will eventually reproduce
the scientific property, not the previous implementation.

Next design task: define AETH-00. Still do not implement.

AETH-00 should be deliberately tiny: enough physics to establish
executable matter, synchronous snapshot semantics, local material
writing, deterministic collision handling, and exact replay. No energy,
mutation, heredity detector, emergence, task, fitness, GPU, or Runpod
yet.

Draft the following as a candidate AETH-00 contract.

Minimal physical state: each lattice location contains exactly four
8-bit physical fields: opcode uint8, arg0 uint8, arg1 uint8, payload
uint8. Every location is executable matter. NOP is simply inert matter;
there is no separate active/executable flag. This is only the AETH-00
state slice, not yet the permanent Aether v1 layout.

Minimal ISA: only two opcodes: 0x00 NOP, 0x01 WRITE. Unknown opcodes
should be specified explicitly. Candidate default: behave as NOP for
AETH-00, but flag this as a decision requiring justification before
freezing. WRITE operates from the tick-start snapshot. Candidate
semantics: arg0 mod 4 selects one von-Neumann neighbor: N/E/S/W; arg1
mod 4 selects one physical field of that neighbor: opcode/arg0/arg1/
payload; the value written is the source cell's payload; lattice
boundaries wrap toroidally. Thus executable matter can alter neighboring
executable matter without any reproduction primitive.

Tick semantics, candidate: S[t] -> every cell independently decodes
S[t] -> each WRITE emits at most one proposal -> proposals targeting the
same target-field compete -> exactly one deterministic winner is
selected -> all winners commit simultaneously -> S[t+1]. A write that
changes a neighbor's opcode cannot affect execution until the following
tick. No mutation, resource update, decay, or hidden side effects exist
in AETH-00.

Collision arbitration: we must not let Python iteration order or GPU
scheduling determine physics. Investigate and recommend a deterministic,
order-independent arbitration function keyed by at least: campaign/world
seed, tick, source coordinate, target coordinate, target field. Prefer a
simple integer/counter-based hash priority suitable for exact CPU/GPU
implementation. Avoid a fixed "lowest coordinate always wins" rule if
practical because it introduces permanent spatial bias. Do not choose the
algorithm casually. Compare a few options for exact cross-platform
semantics and likely GPU cost, then recommend one.

AETH-00 tests: design the tests before implementation. At minimum:
all-NOP world is invariant; one WRITE changes exactly one intended
field; toroidal wrapping is exact; all four physical target fields can
be changed; tick-start snapshot semantics hold; newly written
instructions execute only on the next tick; collision outcome is
deterministic; collision outcome is independent of proposal enumeration
order; repeated replay from identical initial state/seed produces
bit-identical states; only fields targeted by winning proposals may
change; world dimensions and physical dtypes remain invariant;
randomized/property-based tests exercise these invariants over many
small worlds. Include negative/adversarial cases, especially dense
collisions.

Explicit exclusions: AETH-00 contains no organism, genome, birth,
allocation, fitness, task, energy, resource ecology, mutation, heredity
detector, structural detector, GPU implementation, Runpod expenditure.
Its only scientific purpose is to establish trustworthy minimal
executable physics.

Qualification philosophy: do not fully specify the eventual
substrate-qualification gate yet, but add a section describing its
future categories: semantic correctness; deterministic replay; CPU/GPU
differential correctness; adversarial observatory correctness; seeded
