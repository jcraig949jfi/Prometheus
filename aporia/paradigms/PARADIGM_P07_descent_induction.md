# PARADIGM P07 — Descent and Induction (worked example + decision tree + code skeleton)

Aporia P83, 2026-08-21. Source: taxonomy P07; DR grounding report 00050
(infinite descent, per BACKCORPUS record — consulted via its filing summary).
Consumer: Learner corpus type C. Emitted to paradigm_trees.jsonl.

**The move**: reduce a hard case to strictly smaller cases until a base case
decides everything (verb: DESCEND; payoff verb:
DECIDE-INFINITELY-MANY-CASES-BY-ONE-BASE-CASE).

## 1. Worked example — EXECUTED (`paradigm_p07_worked_example.py`)

Markov triples (x²+y²+z²=3xyz) under the Vieta jump z → 3xy−z. The tree was
generated by ASCENT to max ≤ 1e12 (**152 triples**, largest maximum
982,145,940,029), then EVERY triple was descended with two invariants gated at
every single step: (a) the jump stays ON the Markov variety (a jump that
leaves it is an instrument bug, not a descent), (b) the maximum coordinate
never increases and strictly decreases into the base region. Result:
**152/152 reach (1,1,1)**, longest path 29 steps, 1,424 total steps, zero
invariant violations. Verdict: **DESCENT-COMPLETE**.

The open-boundary statement (the example's most important sentence): descent
proves every Markov triple CONNECTS DOWNWARD to (1,1,1); it says nothing about
the ASCENT-side unicity question — whether the largest member determines the
triple is the OPEN Markov unicity conjecture, untouched by this instrument.
Descent decides membership structure, not uniqueness structure.

## 2. Decision tree

- Q1: Can every instance be mapped to a STRICTLY SMALLER instance of the same
  problem (a descent map), or does the problem have a well-ordered parameter?
  — NO: no ladder to climb down; consider P01 (translate until one appears).
- Q1 YES — Q2: Is the descent map INVARIANT-PRESERVING (output provably
  satisfies the same defining property)? — NO: a jump off the variety proves
  nothing; fix the map. This is checkable computationally BEFORE any proof.
- Q2 YES — Q3: Is "smaller" WELL-FOUNDED (no infinite strictly-decreasing
  chains — integer-valued and bounded below)? — NO: descent can cycle or run
  forever; find the right measure.
- Q3 YES — EXECUTE: verify base case(s); then either (proof mode) conclude by
  contradiction/induction, or (computational mode) descend a generated
  population with BOTH invariants gated per step — the population run is the
  proof's dress rehearsal and finds map bugs proofs inherit.

## 3. Code skeleton

```python
def descent_attack(instances, descend, invariant, measure, base_cases, cap=10_000):
    """P07 template. Per-step gates: invariant preservation AND strict
    measure decrease. A descent that works 'in general' but is never run
    on a population hides its own map bugs."""
    for inst in instances:
        cur, steps = inst, 0
        while cur not in base_cases:
            nxt = descend(cur)
            assert invariant(nxt), f"descent left the variety at {cur} -> {nxt}"
            assert measure(nxt) < measure(cur), f"measure not decreasing at {cur}"
            cur, steps = nxt, steps + 1
            assert steps < cap, f"runaway descent from {inst}"
    return True   # every instance decided by the base cases
```

## Provenance and honesty

Markov descent is classical (Markov 1879); the executable content is the
per-step invariant gating over a 152-triple population spanning 12 orders of
magnitude, and the explicitly drawn open boundary (unicity untouched). The
population-descent pattern — run the descent computationally before trusting
it in a proof — is the transferable instrument.
