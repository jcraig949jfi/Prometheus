## GATE_ELI5 — what this park is waiting on

**What is stuck:** we found a way of comparing sequences that seems to more than double how often it
finds truly related ones — but the same change makes it much worse at recognising a sequence it has
already been handed, and our safety check refuses to trust *any* result from a system that fails that
recognition test, so the promising number never got tested properly.

**What would unstick it:** the safety check is aimed at the wrong thing. It exists so that a
*negative* result cannot be blamed on a broken search, but it was written to block *all* results.
X-5 should require it only for negatives, and protect positives with the shuffle test instead — the
one that already showed the improvement is real and not an artifact — then re-run on the untouched
reserve set of 800 pairs.

## X-5 PREREGISTRATION STUB — inherited cleanly, written without opening frozen-B

**Split:** frozen-B, 800 pairs, **640 four-real-operator**. Never read.

**Power, recomputed from the OBSERVED discordance of 0.2250 rather than an assumed one** (P117's
0.1125 assumption was falsified in P118): **MDE = 2·√(0.2250/640) = 0.0375.** Stated before any
threshold is chosen, per doctrine.

**Direction-conditional gates.** The X-4 defect was a single gate applied to both directions.
- **G-pos** (protects positives): the permutation null must sit at chance — permuted hit rate ≤ 3×
  answer-set-adjusted chance in **both** arms. This is the control that actually validates a positive,
  and it already fired clean in X-4 development (1/320 in both arms).
- **G-null** (protects nulls): Wilson 95% CI lower bound on frozen-B L1 top-1 > 0.90. Required only
  when the CI on D contains zero, because a null is what an unreliable index confounds.

**Branches on the paired McNemar 95% CI [lo, hi] of D, verified to PARTITION:**

    N5 REDESIGN   hi < 0
    N1 ADVANCE    hi >= 0, lo >  0.0375
    N2 REDESIGN   hi >= 0, 0 < lo <= 0.0375
    N3 KILL       lo <= 0 <= hi, G-null met,     hi <  0.0375
    N6 PARK       lo <= 0 <= hi, G-null met,     hi >= 0.0375   (underpowered)
    N4 PARK       lo <= 0 <= hi, G-null NOT met                 (null uninterpretable)
    -- and G-pos violated at any point -> PARK (artifact suspected)

*Proof:* `hi < 0` → N5. Otherwise `hi ≥ 0`: `lo > 0.0375` → N1; `0 < lo ≤ 0.0375` → N2; `lo ≤ 0` puts
zero inside the interval, and then G-null unmet → N4, else `hi < 0.0375` → N3 and `hi ≥ 0.0375` → N6.
Exhaustive, mutually exclusive.

**B-DIAG, the named binomial diagnostic, to run BEFORE the frozen-B read.** `binomial` L1 is 8/160 in
the learned space against 100/100 for V2 in X-3 — extreme enough that a bug cannot be excluded.
Test on development only: compare the projected-feature norms and NaN/clipping incidence of binomial
*images* against the other four operators, since the binomial operator caps at 24 terms and therefore
produces shorter, faster-growing images that may fall outside the fitted feature distribution. If the
norms are anomalous, it is a preprocessing bug and must be fixed before X-5 measures anything; if
they are ordinary, the collapse is a property of the learned metric and X-5 reports it as such.
