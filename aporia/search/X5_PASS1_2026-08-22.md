## 1. B-DIAG verdict: **BUG**, and it was one operator's padding

Binomial L1 in the learned space was 3/80 on development and 8/160 on frozen-A against 100/100 for
V2 in X-3. Measured per operator on development images:

    op          n   img_len   padded   raw|img|   raw|tgt|   ratio   proj norm
    diff       80     26-44        0     32.445     32.445   1.000       78.4
    partsum    80     25-45        0     38.881     38.878   1.000       70.3
    binomial   80     23-24       80     69.946     75.026   0.932      439.0
    moebius    80     25-40        0     24.111     24.038   1.003      189.3
    shift      80     25-44        0     19.343     19.348   1.000       82.1

**`binomial` is the only operator whose images are shorter than the 25-term raw block** — the
operator caps at 24 terms, so 80 of 80 queries were zero-padded in exactly the positions where pool
candidates hold real values, and because binomial images grow fastest those are the largest
components in the vector. Projected query norm 439.0 against 70–190 everywhere else: binomial
queries were landing far outside the fitted distribution. **The failure was in the comparison, not
in the learned metric.**

## 2. Fix and refit — the recovery is decisive

**Fix: the raw block is built from the first 20 terms instead of 25.** The minimum image length
across all five operators is 23, so no operator is padded and the comparison is length-symmetric for
every one. This changes the feature space for **both** arms, so the raw-term baseline was refit on
the same footing — X-3's 25-term figures are not comparable to what follows, and that is stated
rather than quietly carried.

    binomial L1 any-valid    3/80  ->  63/80
    overall  L1 any-valid  272/400 = 0.6800  ->  338/400 = 0.8450   Wilson 95% CI (0.8063, 0.8772)
    overall  L1 strict     246/400 = 0.6150  ->  309/400 = 0.7725
    by operator (any-valid): diff 72/80 · partsum 77/80 · binomial 63/80 · moebius 61/80 · shift 65/80

    L2 development, four real operators (n = 320):
      learned  116/320 = 0.3625      raw  55/320 = 0.1719
      D = +0.1906   paired 95% CI [0.1442, 0.2370]   (b = 65, c = 4)

**L1 is still below 0.90 after the fix.** The residual deficit is the genuine property X-4 described
— the metric trades identity resolution for relational proximity — with the bug now removed from it.
D fell slightly, from +0.2281 under the buggy 25-term block to +0.1906; both are development figures
and both are the training objective, so neither is evidence on its own.

## 3. MDE recomputed, not inherited

The X-4 stub fixed **MDE = 0.0375** from a discordance rate of 0.2250 measured under the *unfixed*
metric. Inheriting it would be the wrong-population error firing a sixth time. Re-measured under the
fixed metric: **discordance 0.2156 → MDE at frozen-B's n = 640 is 0.0367.** The two nearly agree,
which means the stub would not have misled — but that could only be known by measuring, and the
figure now carried forward is the one measured under the metric that will actually be used.

## 4. G-pos re-verified over 20 derangements, not one

P118 used a single permutation and flagged the unestimated sampling error. Twenty derangements:

    learned   permuted mean 0.00203   (min 0.00000, max 0.00937)   true 0.3625
    raw       permuted mean 0.00094   (min 0.00000, max 0.00313)   true 0.1719

    development mean |V| = 1.9438 (median 1, max 75), pool 25,305
    answer-set-adjusted chance = 10 x 1.9438 / 25,305 = 0.000768
    G-pos threshold (3x adjusted chance) = 0.002304

**G-pos passes in both arms — but the learned arm clears by only 12%** (0.00203 against 0.002304),
and **individual derangements reach 0.00937, which exceeds the threshold.** That is exactly the
instability P118 warned about, and it is why G-pos is defined on the mean over 20 draws rather than
on a single one. Reported as a narrow pass, not a clean one.

## 5. X-5 PREREGISTRATION, FINAL — branches verified by enumeration

Read against **frozen-B** (800 pairs, **640 four-real-operator**) once, in pass 3. `D` = L2(learned)
− L2(raw) at top-10, any-valid, `shift` reported separately and never folded into D. `mean |V|`,
the adjusted chance, and the permuted rate are all **recomputed on frozen-B**, never inherited.

    G-pos (protects positives)  mean permuted rate over 20 derangements <= 3 x adjusted chance,
                                in BOTH arms. Violated -> PARK (artifact suspected).
    G-null (protects nulls)     Wilson 95% CI lower bound on frozen-B L1 any-valid > 0.90.
                                Evaluated ONLY when the CI on D contains zero.

    N5 REDESIGN   hi < 0
    N1 ADVANCE    hi >= 0, lo >  0.0367
    N2 REDESIGN   hi >= 0, 0 < lo <= 0.0367
    N3 KILL       lo <= 0 <= hi, G-null met,     hi <  0.0367
    N6 PARK       lo <= 0 <= hi, G-null met,     hi >= 0.0367
    N4 PARK       lo <= 0 <= hi, G-null NOT met

**Partition verified by enumeration, not by eye:** 20,604 (lo, hi, G-null, G-pos) grid points with
lo ≤ hi, **zero unmapped**, every branch reachable (N1 4,032 · N2 938 · N3 248 · N4 2,201 · N5 930 ·
N6 1,953 · artifact-PARK 10,302). Boundary probes behave: `lo = hi = 0` routes N3 with G-null met and
N4 without; `hi = 0.0366` routes N3 while `hi = 0.0368` routes N6.

**Stated in advance:** development L1 is 0.8450 with an upper bound of 0.8772, so **G-null will
probably fail on frozen-B too**. Under the direction-conditional design that only matters if the CI
on D contains zero — and it means a null would land in **N4 PARK as uninterpretable** rather than
being read as a kill. The positive path is the live one, and G-pos governs it.
