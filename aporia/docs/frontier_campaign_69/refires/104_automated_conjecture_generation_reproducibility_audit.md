PART 2. THE ARTEFACT TRAIL
For Simon Colton's HR system, the original source code is lost. HR1 and HR2 were originally written in Prolog and Java in the late 1990s and early 2000s, but no public archive, repository, or university FTP remnant holds the original uncompiled code today cite: 2, cite: 18. The most complete surviving artefact is HRLPlus, a later multi-agent extension of HR built for Alison Pease's 2007 PhD thesis. The source code for HRLPlus was also lost, but decompiled Java class files were recovered and are now hosted at https://github.com/dshea89/HRLPlus. The repository maintainers explicitly note that original local variable names and comments have been lost to the sands of time cite: 1.

For Siemion Fajtlowicz's Graffiti, originally written in Pascal between "1984 to 1985" and later ported to C and Unix, the source code was never publicly distributed cite: 6, cite: 9. It is considered privately held or lost. A successor educational version, Graffiti.pc, was developed by Ermelinda DeLaViña in 2001 using C++ and Visual Basic, but its source code was similarly not distributed cite: 6. Modern open-source conjecturing systems exist, such as TxGraffiti at https://github.com/RandyRDavila/Automated-conjecturing-in-mathematics-with-TxGraffiti and the Sage package Conjecturing at https://github.com/nvcleemp/conjecturing, but these are independent reimplementations inspired by the original heuristic rather than faithful ports of the lost code cite: 11, cite: 62.

PART 3. THE PUBLISHED RESULT TO CHECK AGAINST
For HR, a specific quantitative claim exists in Colton's 2002 paper The HR System for Theorem Generation and the book Automated Theory Formation in Pure Mathematics DOI 10.1007/978-1-4471-0147-5. Colton reports a mode m1 session in group theory consisting of 5000 theory formation steps lasting 7163 seconds, during which HR produced 9 objects of interest, 306 concepts, and 3017 conjectures, of which 2941 were supplied with Otter proofs cite: 42, cite: 65. A faithful reproduction would need to match these exact counts of concepts and conjectures.

For Graffiti, no equivalent quantitative benchmark exists that a reproduction could be checked against. Conjectures were published sequentially in a manually curated list called Written on the Wall, beginning with 18 conjectures presented in 1986. Fajtlowicz reported that these early conjectures were based on a database of some 600 graphs cite: 6. However, the exact composition of this 600-graph database, the starting parameters, and the total number of rejected versus accepted conjectures for a specific run were never published. Because there is no exact figure or seed state to check against, Graffiti is irreproducible whatever survives of the code.

PART 4. WHAT WOULD BREAK A REPRODUCTION
A reproduction of HR is broken by lost source code, decompilation artifacts, and dependencies on vanished third-party software environments. The decompiled Java bytecode in HRLPlus lacks the original hand-tuned parameters and developer comments necessary to faithfully reconstruct Colton's exact control flow cite: 18. Furthermore, HR relied on the Otter automated theorem prover and the Mace model generator to evaluate conjectures cite: 65. Because HR used strict time limits to decide whether a conjecture was provable or interesting, running the system on modern hardware would cause Otter to search much faster, altering the time-bound proof outcomes and completely diverging from the 3017 conjectures generated in the original 7163-second run.

A reproduction of Graffiti is broken by undisclosed datasets and hardware-dependent evaluation rules. The original database of some 600 graphs was never formally released cite: 6. Additionally, Graffiti's informativeness filters and expression generation loops relied on hard time limits, such as timing out after 5 seconds cite: 30. As noted by later researchers, exact reproducibility depends on machine speed; a faster machine generates and tests more expressions than Fajtlowicz's original VAX or Unix systems did, leading to an entirely different cascade of accepted conjectures cite: 30.

PART 5. THE STANDING CRITIQUE OF THE ORIGINAL RESULT
The primary critique of Graffiti and similar automated conjecturing systems of that era is known as the Sorcerer's Apprentice Problem: the tendency of the program to overwhelm the user with an enormous volume of true but mathematically trivial or uninformative statements cite: 9, cite: 66. Fajtlowicz attempted to resolve this decisively in the early 1990s by introducing the Dalmatian heuristic, which required new conjectures to provide genuinely new information or sharper bounds relative to previously accepted conjectures cite: 11. However, a subsequent critique of this resolution is that the Dalmatian heuristic makes the system's output highly sensitive to the order in which graphs and invariants are processed, as well as to the specific hardware speed executing the time-limited search cite: 30.

Furthermore, the lack of source code transparency meant that the published results depended heavily on the authors' own interpretation and manual curation of the output. The conjectures distributed in Written on the Wall were curated by Fajtlowicz, and later by DeLaViña, meaning the raw output of the system was filtered through human judgement before publication cite: 45. Independent re-examination by researchers Craig Larson and Nico Van Cleemput in Automated Conjecturing I: Fajtlowicz's Dalmatian Heuristic Revisited DOI 10.1016/j.artint.2015.10.002 explicitly notes that exact reproducibility is impossible on different hardware speeds because the generation timeout dictates which statements are ever evaluated for significance cite: 30.

PART 6. IF IT CANNOT BE REPRODUCED, WHAT IS THE NEAREST HONEST THING
For HR, the nearest live substitute is the decompiled HRLPlus repository at https://github.com/dshea89/HRLPlus. What it does NOT capture about the original is the exact heuristic tuning of the 2002 version of HR, and it replaces the original Otter and Mace dependencies with modern alternatives like Isabelle cite: 1. Because of the missing variable names and different prover backends, it cannot reproduce the 3017 group theory conjectures reported by Colton.

For Graffiti, the nearest live substitutes are TxGraffiti by Randy Davila at https://github.com/RandyRDavila/Automated-conjecturing-in-mathematics-with-TxGraffiti and the Sage package Conjecturing by Craig Larson and Nico Van Cleemput at https://github.com/nvcleemp/conjecturing. What they do NOT capture about the original Graffiti is the exact algorithmic implementation and the original 600-graph database. TxGraffiti uses modern linear programming via SciPy to fit coefficients for inequalities rather than Graffiti's original algebraic enumeration, and relies on modern, systematically generated graph databases cite: 11. Conjecturing implements the Dalmatian heuristic but explicitly acknowledges that its output will vary based on the user's hardware speed cite: 30. Neither serves as a historical reproduction of Fajtlowicz's system.
