## Section 3: Transfer Candidate 1 - Query-Only Memory Injection (MINJA)

### 3.1 The Source-Domain Claim and Technique
**Source:** "Memory Injection Attacks on LLM Agents via Query-Only Interaction" (MINJA)
**Authors:** Shen Dong, Shaochen Xu, Pengfei He, et al.
**Citation Details:** arXiv:2503.03704, DOI: 10.48550/arXiv.2503.03704 [cite: 2, 3].

In early 2025, researchers discovered a catastrophic vulnerability in large language model (LLM) agents equipped with persistent long-term memory. Traditionally, attacking an agent's memory required direct access to the database (e.g., injecting poisoned documents into a RAG knowledge base). However, the MINJA framework demonstrated that an attacker can successfully poison a memory bank without any direct memory manipulation or elevated privileges, using only benign-looking user queries [cite: 2]. 

The MINJA attack operates by embedding malicious instructions within normal queries through a methodology utilizing "bridging steps, indication prompts, and progressive shortening" [cite: 2, 4]. The attacker provides a query that logically induces the agent to autonomously generate and store a poisoned memory entry. The paper states: "MINJA aims to elicit a sequence of malicious reasoning steps corresponding to the same query but with the victim term replaced by a target term... leading to a harmful agent decision that could be fatal" [cite: 2]. 

The progressive shortening strategy gradually removes the explicit indication prompt over multiple interactions so that the malicious record is easily retrieved when processing future victim queries [cite: 5]. MINJA achieves an astonishingly high efficacy, with an average Injection Success Rate (ISR) of 98.2% and an Attack Success Rate (ASR) of 76.8% across highly distinct tasks [cite: 2]. Because the "indication prompts are designed with plausible reasoning steps, ensuring they appear contextually harmless," traditional input and output moderation mechanisms fail entirely [cite: 6].

## Section 5: Transfer Candidate 3 - Proactive Spurious Defenses (ProAct)

### 5.1 The Source-Domain Claim and Technique
**Source:** "Proactive defense against LLM Jailbreak" (ProAct)
**Authors:** Weiliang Zhao, Jinjun Peng, Daniel Ben-Levi, Zhou Yu, Junfeng Yang.
**Citation Details:** arXiv:2510.05052, DOI: 10.48550/arXiv.2510.05052 [cite: 10, 11].

By late 2025, attackers had developed highly sophisticated "multi-turn jailbreaks that iteratively search for successful queries" [cite: 10]. These adversarial frameworks operate by continuously evaluating a model's responses and adapting their prompts until safety guardrails are bypassed. Traditional static defenses failed because they simply blocked the prompt, giving the attacker's optimization loop the exact feedback it needed to try a different vector.

In response, researchers introduced **ProAct**, a proactive defense framework designed to disrupt the attacker's autonomous optimization process [cite: 10]. ProAct operates on a brilliant premise: instead of blocking the attacker, it "intentionally mislead[s] these jailbreak methods into thinking that the model has been jailbroken with 'spurious responses'" [cite: 11]. These spurious responses appear to be successful rule-breaking outputs but actually contain no harmful content. 

By providing false signals of success to the attacker's internal optimization loop, ProAct causes "the adversarial search to terminate prematurely and effectively jailbreaking the jailbreak," reducing attack success rates by up to 94% [cite: 11]. This concept proves that the most effective way to halt an iterative optimization process is to feed it the exact psychological satisfaction of closure it is seeking, without actually granting the payload.
