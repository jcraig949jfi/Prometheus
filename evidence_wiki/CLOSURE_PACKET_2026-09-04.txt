1. FINAL PEW VERDICT
----------------------------------------------------------------------
PEW answers, durably and independently of authentication:
  WHICH host/service produced a record ...... YES (server attestation)
  WHAT evidence can we trust ................ YES, with a named ceiling:
     the causal ANCHOR is client-asserted, recorded honestly, NOT yet
     engine-verified (see 6). Everything else in the chain is typed +
     machine-checkable.
  WHAT can we replay ........................ IDENTITY + CAUSAL locus,
     NOT the exact action/input/output (see 5,6). REPLAY_COMPLETE=NO.
  WHICH prior lessons constrain the future .. YES (constraint store, 9).
  HOW wrong lessons are corrected ........... YES (errata/supersession,
     append-only, never mutated; 8,10).
Net: the interpretation layer is closed enough to be trusted as memory
and to remember its own corrections; two closures (exact replay, and
engine-verified anchors) are gated on SFE/Proteus and are named in 12.

3. CREDENTIAL RULING
----------------------------------------------------------------------
A. Should PEW machine creds be machine-specific?  YES -- eventually. But
   machine identity for PROVENANCE must not rely on the token at all
   (see 3G); per-machine tokens are a SECURITY hardening, not the
   provenance fix. The provenance fix (server attestation) is done and
   does not wait on rotation.
B. Should machine_tokens stay git-tracked?  NO. They are a shared secret
   in a repo cloned to every host.
C. Should db_password / auth_token stay in committed config?  NO.
D. Replacement mechanism (IMPLEMENTED, backward-compatible):
   load_config() precedence is now  env var > config.local.json
   (untracked, gitignored) > committed config.json. Absent overrides ->
   identical to today, so M1 and M2 keep running. Operators move real
   secrets to env/config.local.json with no code change.
E. Migration/back-compat impact: none forced. The committed cleartext
   remains a working default until an operator removes it; removal must
   be simultaneous on M1 and M2 (both read the same file) or the machine
   without the new secret source breaks.
F. What is compromised: SECURITY -- yes (any LAN peer holding the repo
   authenticates on any host; and 192.168.1.202:5432 accepts config.json
   creds directly, bypassing ew.write_log attribution entirely).
   PROVENANCE -- NO LONGER, given 3G: host identity is now independently
   attested, so a shared token no longer implies a shared host.
G. Must tokens be rotated because they lived in git history?  YES, they
   should be treated as compromised and rotated. This is OPERATOR ACTION
   (below); nothing in PEW can rotate a secret that other hosts and the
   raw 5432 port also trust.
RISK CLASS: SECURITY DEFECT (urgent-ish, trusted LAN) that does NOT
   invalidate any existing fossil.
REMEDIATION (done, mine): override mechanism + .gitignore.
ROTATION / OPERATOR ACTIONS (not mine, stated explicitly):
   (i)  choose new db_password + auth_token + per-machine tokens;
   (ii) place them in each host's config.local.json/env;
   (iii) delete the cleartext from config.json and purge history;
   (iv) scope inbound 5432 to the specific peer IPs that need it, or
        close it and give M2's service another route (closing it as-is
        breaks the M2 deploy -- coordinate first).

6. REPLAY VERDICT
----------------------------------------------------------------------
Test: could a future agent reconstruct the EXACT intended encounter from
durable evidence after today's working tree is gone? -- NO.
  recover fossil ................. YES (GET /fossil/encounters/{id}: all
                                   runs + anchors + attestation)
  identify producing PEW host .... YES [NEW] (attestation.db_system_id)
  reconstruct inputs ............. NO  (exact_input STILL_MISSING)
  instantiate equivalent world ... PARTIAL (world_id+manifest_hash+
                                   seed_root; full config missing)
  rerun same action .............. NO  (exact_action STILL_MISSING)
For REPLAY_COMPLETE, the durable minimum is:
  immutable refs: (encounter_id, run_id); (sfe_event_id, sfe_entry_hash,
    sfe_engine_identity); world manifest_hash + full config digest;
    player genome_hash + runtime_hash; exact_action; exact_input digest.
  retrieval: PEW read API (5,8) for the fossil + attestation; SFE ledger
    for the event by (engine, event_id, entry_hash); Proteus store for
    the serialized player by runtime_hash.
  digest validation: recompute manifest/genome/input/output digests and
    compare; any mismatch => REFUSE (HARD constraint).
  version interpretation: read attestation.schema_version/fossil_contract
    + SFE engine schema; interpret fields under those, never latest.
  failure behavior: if any immutable ref or digest source is unavailable,
    fail LOUD (no partial "best-effort" replay).
Gap owners: exact_action/exact_input/output_digest (producer contract,
12); sfe_engine_identity (SFE attest, 12).

7. CAUSAL-ANCHOR REGRESSION RESULT
----------------------------------------------------------------------
Regression: integration/closure_battery.py, gates C3+C4 (live PASS).
  C3  valid exact anchor (sha256:64hex + evt_ id) -> ACCEPTED;
      wrong CLASS (blob_hash / world head_hash, no evt_ id) -> 422;
      malformed shape -> 422.   [enforced, no fuzzy matching]
  C4  KNOWN GAP, PINNED: a well-formed but WRONG (real) event/hash pair
      is still ACCEPTED (200), because _check_sfe_anchor validates
      CLASS+SHAPE only and PEW holds no SFE client by design. The fossil
      records attestation.sfe_anchor_verified=false, so provenance stays
      honest: "THIS encounter -> a well-formed anchor the CLIENT chose",
      not "-> THIS verified ledger entry".
Machine-checkable linkage that IS enforced: evidence -> encounter is an
exact composite FK (unknown encounter -> refused); duplicate/conflict is
exact-value (409, never absorbed). The encounter -> ledger hop is the one
that is not verifiable inside PEW.
To make "wrong real event -> REJECTED" true requires SFE attestation
(12). This is a cross-component contract, not a PEW-only fix, and I did
not fake it with fuzzy matching.

CRITICAL SPLIT enforced by kind:

              incompatibility, wrong deployed service version).

              prohibit exploration.
Anti-Goodhart guard (tested, closure C6): scope is MANDATORY, so
"R~=0 in world family W" cannot be recorded as "never test primitive P".
Scope is part of the evidence.

10. ERRATA / SUPERSESSION V0   (with the real corrections as examples)
----------------------------------------------------------------------
A lesson transitions PROPOSED -> SUPPORTED -> NARROWED -> SUPERSEDED, or
PROPOSED -> REFUTED, by APPENDING a constraint_events row (from_status,
to_status, adjudicating_evidence_id, successor_constraint_id, rationale,
reproducer). The original row is NEVER mutated; current status = latest
event; a REFUTED/SUPERSEDED lesson is excluded from an "active" listing
but stays fully recoverable. Seeded live (namespace prod):

  K-60724e7c13ff  I-WORLD-ENUM-UNSCOPED  PROPOSED -> NARROWED

Both readable at GET /constraints/{id} with the full trail; REFUTED is
absent from status=PROPOSED listings. This is the behavior the whole lane
exists for: Prometheus cannot accumulate knowledge without also
accumulating corrections to it.

11. COMPOSITION PROVENANCE CONTRACT  (exact request to Proteus)
----------------------------------------------------------------------
PEW stores exactly the typed provenance Proteus supplies; it invents no
Proteus semantics. Today fossil_players carries lineage_id, generation,
runtime_hash, producer; fossil_encounters carries players[] + producer.
Before COMPOSITION_COMPLETE can be claimed for a composite A+B, PEW
REQUIRES Proteus to supply (as typed provenance, not free-form producer):
  - exact A identity, exact B identity (content-addressed);
  - exact composition identity (composition_id) + topology/order;
  - player serialization digest (the bytes that ran);
  - lineage + mutation state (mutation_ref / genome delta);
  - world/run identity (already carried);
  - intervention/ablation identity (which ablation this row is);
  - outcome measurements (typed, joinable -- blocked upstream, see 12);
  - preserved negatives (the ablations that did NOT survive).
Proposed shape: a composition provenance block Proteus posts alongside
the encounter; PEW adds typed columns/edges for composition_id, topology,
serialization_digest, ablation_id when Proteus fixes their names. PEW
will not guess them.

15. HANDOFF TO HARMONIA
----------------------------------------------------------------------
WHAT PEW NOW PROVES:
  - which PEW/store you reached (GET /identity, db_system_id) -- from the
    service, never from your token;
  - which host/service produced any new fossil (row .attestation);
  - the typed chain evidence->encounter->run/world->SFE event->ledger pos
    ->Proteus organisms, in one /provenance call, all exact joins.
WHAT PEW CAN NOW REPLAY:
  - the IDENTITY and CAUSAL LOCUS of an encounter (who/where/which event);
  - NOT the exact action/input/output yet (REPLAY_COMPLETE=NO; R-PRO-2).
WHAT PEW CAN NOW REMEMBER AS A CONSTRAINT:
  - HARD invariants vs ADVISORY scoped lessons, with mandatory scope,
    provenance, and a full errata trail; refuted lessons go inactive but
    stay recoverable (/constraints).
WHAT HARMONIA MUST STILL NOT INFER:
  - do NOT treat a stored anchor as engine-verified: sfe_anchor_verified
    is false until R-SFE-1 lands; verify (event_id, entry_hash) against
    SFE yourself before trusting causal correctness;
  - do NOT read "ADVISORY R~=0 in family W" as "primitive is dead" --
    scope is the evidence;
  - do NOT infer machine identity from the bearer token;
  - do NOT assume M1 has this closure -- it is M2-live only until M1
    applies 008 and redeploys.

DEFINITION OF DONE: the six questions Harmonia should no longer need to
ask (which PEW / token=machine? / enough to replay? / wrong event? / what
on refutation? / hard vs narrow?) are now answered explicitly and
durably, EXCEPT "could this fossil cite the wrong real event?" whose
honest answer is "yes, and the fossil says so" until SFE attestation
(R-SFE-1) closes it.
