## 4. The finding that changes how a result must be read

A non-LLM control, no API calls: **"count how many of the five integers are coprime to 30"** —
no primality reasoning whatever — scores **0.5225 on 400 fresh tasks** from the same generator at
a different seed. **This manifest levels at 0.4900.**

The solver is *below* a one-line arithmetic heuristic. So:

- The band `[0.35, 0.60]` guarantees headroom against a floor of **chance, 0.25**. The
  attainable-**without-reasoning** floor is **~0.52**. The band's headroom argument does not
  describe this family.
- Residue that does nothing but remind the solver to filter small factors could deliver **≈+4pp
  — half the +8pp the probe is powered for — with zero metabolization.** The D0 residue is a
  `METHOD_VOCAB` census that *contains* `parity-or-last-digit` and `digit-sum-rule`, i.e. it
  names that filter by construction.
- The arm that would bound this is `F-generic`, and a decidable check shows it is separable from
  `F-null`/`F-prom` **by shape alone**. The controlling comparison is itself confounded.

**Cleared in the same run**, so it is not conflated: the method census does **not** predict the
answer — 0.2900 cross-validated against a permutation null whose 95th percentile is 0.2950. The
naive same-rows number was 0.4000, and without the null I would have reported a leak that is not
there.
