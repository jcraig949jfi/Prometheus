## Verdict: REVISE

The instrument half (sections 7-9: minimal substrate, neutrality audit,
dangerous abstractions, missing capabilities) is sound and worth keeping.
The architecture half has a structural problem: as written, the outcome of
most screens can be predicted before they run (F-01, F-02). This is not
resource authorization and not scientific qualification.

## Findings

Format per the requested response contract: affected identifiers, smallest
counterexample, severity, repair, consequence.

### F-01. Signatures test where function resides, not whether it was acquired

- Affected: all packets; weakest in A01, A02, A06, A07, A08, A10, A12.
- Severity: CRITICAL.
- Finding: each organism is a designer-written fixed meta-algorithm (a
  proposer plus a retention criterion) with data-dependent state. Lesion,
  transplant and rescue establish that the state is causally used. That is
  true of any correct implementation, including the hand-built positive,
  which passes the same signature by design.
- Smallest counterexample: A02 with a kernel that grows the two-stage relay
  regardless of traffic. Topology transfer carries the transformation,
  matched scrambling removes it, motif reconstruction rescues it. The named
  impostor "seeded construction recipe" passes every arm. "Cross identical
  kernels with two mature topologies" does not say the two topologies came
  from different experience.
- Repair: add a history-contingency arm to every packet. Same founder, two
  experience regimes, a yoked control receiving matched event statistics
  with scrambled contingency; the function must follow the regime. A05
  (matched/unmatched histories) and A09 (two developmental histories)
  already have this shape; the other ten do not.
- Consequence: REVISE.

### F-02. The 20% cost margin has no headroom at the stated minimal scale

- Affected: A07, A10, A01; common contract "Decision".
- Severity: CRITICAL.
- Finding: at the stated sizes exact or near-optimal baselines saturate, so
  the cost half of the signature fails for reasons unrelated to the
  mechanism. A negative would then be a degenerate-domain result recorded
  as a parked mechanism.
- Smallest counterexamples:
  - A10: at most 8 hypotheses with binary probe outcomes gives a floor of
    3 probes for full identification, which a generic information-gain
    policy reaches whenever splitting probes exist. "At least 20% fewer
    paid probes" is not available. For a held-out pair the floor is 1.
  - A07: a "disclosed fixed content-addressed algorithm" that respects the
    organism's access boundary (no global key service) must itself be
    built in the contact graph. That is the hand-built distributed index,
    i.e. the positive control. The candidate must beat its own positive
    control by 20%.
  - A01: 8 primitive edits and strings of length <= 8 are fully enumerable;
    the document already concedes the dictionary can win.
- Repair: before any build, show on paper that the designed positive clears
  the registered margin against the best named comparator in the tiny
  world. If it cannot, enlarge or redesign the world first. State the reuse
  horizon as a registered number; it currently is a free parameter that
  decides the sign of every amortized comparison.
- Consequence: REVISE.

### F-03. "Native event" is undefined, so the uniform cap is not uniform

- Affected: common contract "Proposed bounded screen"; A11, A12, A02;
  VALIDATION.md arithmetic.
- Severity: MAJOR.
- Finding: 4,096 native events per arm is applied to rewrite steps, message
  arrivals, reactions and lattice updates. The 1,179,648 total is a sum
  over incommensurable units; the validation checks the multiplication,
  not the meaning.
- Smallest counterexample: A11, 16 x 16 lattice. If an event is one cell
  update, 4,096 events is 16 sweeps: no time to form a guide, propagate a
  defect and test a held-out sequence. If an event is one sweep, A11 gets
  256 times the per-component budget of every other packet. A12 must fit
  operator search, a sandboxed old-versus-new procedure comparison and
  concealed-task testing in the same 4,096.
- Repair: define the event per runtime and set budgets per packet from the
  designed positive's measured need. Drop the common total.
- Consequence: REVISE. A11 has no transition law, defect invariant or work
  functional yet; DEFER it until those exist. It is a placeholder, not a
  packet.

### F-04. The portfolio collapses to about six mechanisms

- Affected: A01, A06, A10, A12; A04, A09; selection table in section 4.
- Severity: MAJOR. Answers questions 1 and 8.
- Translation 1: A01, A06, A10 and minimal A12 are one mechanism. Retain a
  bounded executable procedure when amortized saving exceeds description
  plus test plus maintenance cost; test by crossing {procedure} with
  {contents}, scrambling, a fixed library and a planted positive. A06's
  return program is an A01 rule over action traces. A10's experiment
  operator is an A01 rule over probe constructions. A12 with "one editable
  proposal/test rule and one modification round" is a single proposer
  edit, i.e. a choice among fixed enumerators. Costs and interventions map
  one to one.
- Translation 2: A04 and A09. Fuse material <-> permit; committed edge <->
  protected resource or channel; costly unbinding <-> revocation; selector
  rule edit <-> ratification rule edit; selector/content swap <->
  rule/stock swap.
- Smallest counterexample for A09: at 4 processes, 3 reserves and 2
  editable clauses the constitution is a few bits of persistent state. An
  ordinary adaptive allocator with the same state bits, transplanted, also
  makes "allocation priorities follow the transplanted rules rather than
  donor reserve levels". Candidate and comparator are extensionally the
  same machine.
- Repair: MERGE A06 and A10 into A01 as domains of one packet; keep A12
  only as a later multi-round extension. MERGE A09 into A04 as its
  multi-process scale-up and retire A09's frontier framing at minimal
  scale. Use freed slots for carriers the twelve do not cover: S14 (timing
  as carrier, pressures C5 and C11) and S17 or S21 (memory carried by the
  environment, pressures the untested "environmental construction" row of
  section 9).
- Consequence: MERGE.

### F-05. A07 is K, and the candidate is a fixed index-construction algorithm

- Affected: S07 / A07; H count; recommended first build.
- Severity: MAJOR. Answers questions 2, 3 and 5 for A07.
- Smallest counterexample: every record draws a random local tag at
  creation (lawful local randomness), then flooding builds per-record
  routing tables. This standard construction survives host renaming and
  relocation that preserves the contact relation, breaks under semantic
  misalignment, and transfers with contents permuted. It passes the whole
  assay. More generally, "the address organization is learned" means the
  index is data-dependent, as for any trie insert.
- Second issue: "Park if host renaming changes results." Random contact
  proposals consume a random stream in an order set by host iteration
  order. Renaming shifts the stream and changes results with no organism
  access to host IDs. In an addressless system per-record randomness must
  be keyed by something; keying by host ID is a stable hidden identity.
- Repair: reclassify S07 as K. Keep A07 as a conformance fixture for "the
  runtime offers no free memory API", which is the value section 11 already
  assigns to it. Define renaming invariance distributionally and specify
  how per-record randomness is keyed.
- Consequence: REVISE (reframe).

### F-06. The decision gate has a dead zone and mixes qualification into the screen

- Affected: common contract "Decision"; sections 7.3 item 8 and 11.
- Severity: MAJOR. Answers question 12.
- Finding: no verdict is defined for a primary signature in 5 to 19 of 24
  blocks. The designed positive and principal negative appear as arms of
  the candidate screen, while 7.3 item 8 requires admitting the positive
  and refusing the impostor "without looking at candidate outcomes" and
  section 11 orders qualification before the candidate.
- Smallest counterexample: 12 of 24. Neither pass nor park; the reading is
  chosen after the fact.
- Repair: run positive and negative first under their own cap; only a
  qualified assay proceeds. Predeclare the 5-19 outcome (suggest
  INCONCLUSIVE with exactly one prespecified diagnostic). Signatures are
  conjunctions of several conditions; define the per-block predicate
  exactly, and name the experimental unit as the world generator when the
  claim concerns held-out latent structure.
- Consequence: REVISE.

### F-07. The capability matrices barely discriminate

- Affected: section 6; the claim in section 11 that the four first builds
  "test different laboratory assumptions".
- Severity: MINOR.
- Finding: C1, C2, C3, C6, C8, C9 and C10 are R for all twelve packets; C7
  and C12 are R for eleven. 58 of 60 G cells are D. Only C4, C5 and C11
  vary. The rows for A04 and A10 differ in one cell (C11: U versus N).
- Repair: state the universal columns as the common core and G1-G5 as a
  rule. Keep a matrix only for C4, C5, C11 and justify build order from
  section 11's prose, which is where the argument actually is.
- Consequence: REVISE.

### F-08. No prior-work check was made

- Affected: section 1 source boundary; question 11; A04, A03, A01, A12.
- Severity: MAJOR.
- Finding: the Evidence Wiki client failed on import and the failure was
  recorded rather than fixed. An instrument error is not evidence of
  absence. The repository holds adjacent prior campaigns that the design
  never consulted, for example `archaeon/wse/ledgers/ssf-c1` to `ssf-c3`
  (selective state, adjacent to A04) and `archaeon/wse/ledgers/wse-survey-v01`.
  This reviewer has not read those ledgers either and makes no claim about
  what they imply.
- Repair: fix the client, query for each retained packet, and add a
  "prior program result" line per packet before any build is proposed.
- Consequence: REVISE.

### F-09. A04's shuffled-commitment control is a straw arm

- Affected: A04.
- Severity: MINOR. Answers part of question 4.
- Smallest counterexample: moving a commitment in time fuses whatever
  occupies that location at the new time, so the shuffled arm differs in
  committed content, not only timing, and loses trivially. With 2 regime
  changes per lifetime there is nothing for the selector to learn within
  a lifetime; learning across lifetimes needs a selection rule that is not
  specified and risks gift G5. A fixed threshold tuned under the comparator
  tuning allowance will probably match.
- Repair: content-preserving timing control (commit the same content
  earlier or later); state the learning signal and timescale; more regime
  changes per lifetime.
- Consequence: REVISE.

## Recommendation

1. Build the positive/impostor fixture pairs as the Observatory conformance
   suite. Section 7.3's final paragraph already points there, and these
   fixtures test the instrument whatever the candidates do.
2. Hold candidate search until a packet carries a history-contingent claim
   (F-01) with demonstrated headroom (F-02) and a defined event unit (F-03).
3. Reduce the twelve to about six distinct mechanisms (F-04, F-05) and
   spend the freed slots on timing and environment-carried memory.
4. Fix and query the Evidence Wiki before proposing builds (F-08).

Astra is asked to incorporate or reject each finding with reasons, as the
packet commits to.
