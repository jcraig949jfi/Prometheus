#### Receipt provenance that is meaningful, but not magical

1. Restrict the canonical schema to ASCII string keys, strings, integers, booleans, null, arrays, and objects; use integer resource quantities and rational numerator/denominator pairs instead of floats. Reject NaN/infinity, duplicate keys, unknown fields at a fixed schema version, excessive nesting, bool masquerading as int, and malformed digests. Canonical bytes use sorted keys, fixed separators, ASCII escaping, and no optional whitespace. Define receipt ID as SHA-256 over a domain separator plus canonical payload excluding its own ID. Arrays have documented order; set-like fields must be sorted and duplicate-free. Different key insertion order must not change the ID; a material value change must.
2. Bind schema version; immutable policy and registration digests; all eight cell components; claim/ruler identity and qualification version; source/code artifact digest; runtime/version and observation adapter identities; native resource units and host-cost quantities; exposure/custody digest; sample unit, generator family and founder ancestry; search regime, operator, tuning and budget; actual resource ledger; exact input/output/checkpoint/transcript artifact references; and parent receipt IDs. Each ArtifactRef includes role, SHA-256, and byte length. Content digest authenticates bytes, not truth of declared execution or authorship.
3. Registration commits the expected answer table, positive/impostor IDs, claim policy, hypothesis, effect threshold, baselines, stopping rule, sample unit, power requirement, and confirmation panel/generator-family commitment BEFORE access to outcomes. Run receipt references that registration. Evaluation receipt references run receipts plus exact evaluator/policy identity. Corrections append a new receipt with explicit supersession; old IDs remain resolvable.
4. Read artifacts as bounded bytes once and compute both hash and length from those exact bytes. Do not hash one read and parse a different read. Treat paths as local bundle members, reject absolute paths, parent traversal, symlinks/reparse escapes, and resolved paths outside the root; do not fetch URLs or run artifact code. Cap bytes, nodes, edges, nesting, and traversal work. Missing referenced file is BLOCKED; present wrong bytes are FAIL. A resource-limit rejection must return a typed reason, never crash into a green result.
5. Use a content-addressed bundle plus expected registration root and sealed run-bundle root supplied independently of the bundle. Parent-hash chaining is useful for order and substitution detection only when a trusted external root or checkpoint exists. Require sequence completeness relative to the externally sealed inventory/terminal sequence, or tail truncation and selective run omission can be invisible. A local timestamp or self-contained hash chain cannot establish preregistration time or detect wholesale rewritten history.
6. The offline checker can compare bytes to caller-supplied trusted roots. It cannot establish why the caller should trust those roots. A separate custodian or CI job with independent write permissions should retain the preregistration commitment before outcomes and the complete run inventory afterward. Externally attested ordering is stronger than filesystem time or a git hash alone. Without the required anchor, provenance qualification is BLOCKED even if internal consistency PASSes.
7. Do not put signing keys in fixtures or imply a self-signed JSON file is independent attestation. A shared-secret HMAC only separates trust if the producer cannot access its key; a secret held by the same harness proves no such separation. Minimal stdlib scope can consume out-of-band pinned digests without implementing cryptographic identity or a PKI. Independently authenticated attestations are a later integration, not an invented property of SHA-256.
8. The checker must independently recompute derived verdicts and promotions. A producer's PASS field, reset_complete flag, physics_family label, independence flag, or auditor accusation is data, never authority. Deterministic fixture digests may be pinned in reviewed tests, but do not generate expected outputs with the exact implementation under test.

These are recommended protections for H0 and H8; even perfect integrity only establishes which bytes were supplied under which commitments, not that the runtime performed the described physics. #### Evidence graph semantics and scoped promotion logic

- Node kinds are registration, raw artifact/observation, qualification result, adjudicated evidence, claim, and correction/invalidation event. SUPPORTS and REQUIRES edges point from a derived node to its premises; validate their dependency graph as a DAG. Dangling required refs BLOCK; contradictory scope/roles, duplicate conflicting identities, and dependency cycles FAIL graph integrity. A claim cannot cite its own conclusion or an ancestor dependent on it as independent support.
- Qualifications are keyed by ruler, physics, world family, observation adapter, runtime version, scope, and policy version. A PASS for another adapter/runtime is not transferable by relabeling its receipt. Registration owns required facets for each supported claim kind and requested level; the producer cannot lower requirements by supplying required_facets=[]. Unknown claim kinds/levels or absent policy mapping BLOCK rather than default-promote. Policy bytes must match the independently pinned policy digest.
- Represent each facet as (status, scope, evidence IDs, reason, adjudication source), not a truthy boolean. Missing is not PASS; not-applicable is allowed only by pinned policy, with rationale. Keep origin (designed/seeded/transplanted/endogenous) distinct from capability and from search reach. Capacity, demand, reach, detection, developability, and neutrality qualification feed the relevant claim facets rather than being lost in display-level labels.
- For the first reference fixture, define a narrow, explicit policy only: bounded-retention EFFECT at L1 requires qualified detection/known answers, demand and constant baseline, valid declared origin, resources, custody/exposure, and restart/observer prerequisites; a cold-reach claim additionally needs cold-founder evidence; a shared claim needs neutrality across the registered unlike panel; a MECHANISM claim additionally needs qualified causal controls; L3 additionally needs independent replication. Other mappings are BLOCKED until separately registered. This is a proposal, not a universal scientific level assignment.
- Compute eligibility from all required scoped facets; never accept a producer's requested display level as the answer. Store requested and achieved/eligible levels separately. If L1 loses detection, it may become BLOCKED rather than automatically L0: retain L0 only if its own registered descriptive requirements still hold. A structure claim without the exact restricted-class bound cannot exceed the design's L1 ceiling even if other facets are present.
- A source failure or externally adjudicated invalidation must re-evaluate the transitive dependency closure. A bad custody node invalidates dependent detection/transfer/replication eligibility, not an unrelated claim. Removing a facet or adding a valid invalidation must never increase eligibility. Input ordering must not affect the result. Identical blobs with renamed IDs or new seeds do not create independent evidence; provenance ties records to their actual code/world/founder/custodian families.
- Invalidation and supersession are separate event relations, not ordinary scientific support edges. Preserve history, explicit authority, and effective graph revision. Untrusted prose alleging fraud cannot revoke evidence automatically. Conflicting qualified adjudications block promotion pending resolution; do not choose whichever yields the stronger claim. A repair creates a new evaluation under a new graph root; it does not silently erase the earlier failure.
- Report scope, required facets, evidence closure, unsupported facets, max eligible level, and all demotion reasons. A contract-valid synthetic graph remains a test fixture, not scientific evidence. A structurally sound bundle without independently qualified underlying evidence receives contract PASS and scientific BLOCKED/UNQUALIFIED as appropriate.

These semantics implement the requested automatic demotion and separate claim kind from strength, while preserving the stated L1 ceiling for unbounded structure claims.
